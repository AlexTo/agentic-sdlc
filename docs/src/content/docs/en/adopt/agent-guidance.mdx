**You'll end with:** an `AGENTS.md` every agent reads first, and the issue templates under
`.github/ISSUE_TEMPLATE/`, the source of the standing instructions in every implementation issue.

<Steps>

1. **Copy `AGENTS.md`** from this repository, and rewrite each section for your project. It is
   short on purpose: what an agent needs on every run, and nothing else.

   | Section | Write |
   | --- | --- |
   | What this is | One paragraph: the product, the stack, the monorepo tool |
   | Commands | Install; build, lint, test everything; one project's tests, once (not watch mode); one test file; `nx affected`; e2e; local dev |
   | Architecture | One bullet per package: what it is, what it may import, where new code of each kind goes |
   | Conventions | Conventional Commits, the formatter by name, where helpers go, and every rule a reviewer has had to repeat twice |

   <Aside type="tip">
   The commands section matters most. An agent that can't find "run one test file, once" will run
   the whole suite in watch mode and hang. Run each command you list once, to be sure it works.
   </Aside>

   When the architecture section outgrows a line per package, move each package's detail into a
   nested `AGENTS.md` in its folder, and leave the root a line pointing there. An agent loads a
   nested file only when it works in that folder, so a run reads only the detail it needs. This
   repository's `packages/tooling/agent/AGENTS.md` is one; copy it along with the glue in
   [step 5](../glue-scripts/).

   If your agent reads a differently named file, such as `CLAUDE.md`, make that file point to
   `AGENTS.md`. This repository's `CLAUDE.md` starts with `@AGENTS.md`, which Claude Code reads
   as "include that file here".

2. **Copy `.github/ISSUE_TEMPLATE/`** from this repository: `implement-phase.md` for the
   Developer, and `test-deployed-pr.md` for the Tester, if you add it in [step 9](../deploy/).

   The Agent Issues script writes the issue's spec and scope sections itself, and reads everything
   under `## Instructions for the agent` in `implement-phase.md` at run time. Keep that heading
   exactly, because the script looks for it and fails without it. Keep `#<parent>` literally, too:
   the script replaces it with the spec's parent issue, and drops the bullet when the spec has
   none.

3. **Edit the instructions to match your stack**: the commands, the screenshot helper path, and
   what "cloud credentials" means for you.

</Steps>

## Check it worked

```bash
grep -c '^## Instructions for the agent$' .github/ISSUE_TEMPLATE/implement-phase.md
```

```text
1
```
