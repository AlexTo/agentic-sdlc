**You'll end with:** a ratified constitution of your own, and Speckit templates that produce files
the Agent Issues workflow can read.

The `.specify/` you copied in [step 2](../speckit/) already holds a working constitution and
templates, written for the notes app. This step makes them yours.

<Steps>

1. **Rewrite the constitution for your project.** In your coding agent:

   ```text
   /speckit-constitution
   ```

   Give it your project's own principles: architecture, data model, security defaults, code
   conventions. [Discava's](../../discava/constitution-and-guidance/) is a full example. Keep
   these parts of the copied one, adapting the commands and package names to your stack, because
   the rest of the workflow depends on them:

   | Keep | From the copied constitution | Why |
   | --- | --- | --- |
   | Unit tests, invariants and e2e tests are required, and tests are a specification | III. Layered Tests | The agent may not weaken a test to turn CI green |
   | Everything runs under `pnpm dev`, with no cloud account | II. Everything Runs Locally | PR CI can then run the e2e suite and give the agent real feedback |
   | Agents implement on their own branch and PR, never run the local stack, and mark tasks needing it **(human)** | Development Workflow | The agent has no Docker. CI runs what it can't |
   | PR CI is the gate. An agent never merges, pushes to `main`, edits CI workflows or weakens a test | Development Workflow | What keeps an agent inside its lane |

2. **Change the package paths in `tasks-template.md`.** Its test tasks name this repository's
   packages: `packages/notes-table/src/helpers/invariants/` and `@agentic-sdlc/e2e`. Point them at
   yours. Keep the rest of the template as it is: the format rules under **Read by automation**,
   the **(human)** marker, the mandatory tests, and the note against editing existing tests are
   what the Agent Issues workflow and the `Tasks format` check rely on.

3. **Keep the parent issue line** in `spec-template.md`:

   ```markdown
   **Parent issue**: [#<number>, or "none" if there is no tracking issue]
   ```

   Agent Issues writes `Refs #<parent>` into each issue from it.

</Steps>

## Check it worked

Generate a throwaway spec and tasks for a tiny feature. Then, once the glue is in place
([step 5](../glue-scripts/)):

```bash
pnpm nx run @your-scope/tooling-agent:validate-tasks
```

```text
1 tasks.md file(s) are in the expected format.
```

Delete the throwaway spec folder afterwards.

<Aside type="caution">
`/speckit-tasks` sometimes writes `### Phase 2` or indents a task. That is exactly what the
validator catches, so don't relax the validator. Fix the template wording until the generated files
pass.
</Aside>
