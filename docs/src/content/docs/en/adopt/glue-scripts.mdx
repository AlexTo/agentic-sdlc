import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**You'll end with:** a `tooling-agent` project with ten Nx targets and 223 passing unit tests.
The workflows in steps 6, 7 and 9 only call these targets.

<Steps>

1. **Copy `packages/tooling/agent/`** from this repository, whole. Its `project.json` already
   declares every target the workflows call, and its `AGENTS.md` tells an agent what each folder
   holds:

   <FileTree>
   - packages/tooling/agent/src/
     - agent-issues/ spec → issue, the `tasks.md` validator, and archiving finished specs
     - agent-ci/ red CI → agent
     - agent-review/ "changes requested" → agent
     - helpers/ locking the issues an agent reads, and telling trusted authors from strangers
     - ui-screenshots/ the screenshots rule, and the `E2E screenshots` comment
     - invariant-coverage/ which code writes which entity, and the rule that new writers need invariants
     - post-merge-test/ deployed PR → test issue for the Tester
   </FileTree>

   They depend only on Node built-ins, TypeScript (for the invariant scan) and the `gh` CLI.
   `tsx` runs them. Add the folder to your workspace's `pnpm-workspace.yaml` and root
   `tsconfig.json` references if your globs don't already cover `packages/tooling/*`.

2. **Rename the scope.** Replace `@agentic-sdlc/` with your workspace's scope in the project's
   `package.json`, `project.json` and `vitest.config.mts`, and in the comments of its `main.ts`
   files. Every workflow you copy later names `@agentic-sdlc/tooling-agent`, too.

3. **Change the constants for your setup.** The ones in bold point at this repository's notes
   app, so you will almost certainly change them. The rest only change if you changed a decision
   in [the overview](../overview/):

   | Constant | File | Default |
   | --- | --- | --- |
   | **`UI_SOURCE`** | `ui-screenshots/check.ts` | `.tsx`/`.css` under `packages/notes-website/src/` and `packages/common/shadcn/src/` |
   | **`WRITER_PACKAGES`**, **`ENTITIES_PACKAGE`** | `invariant-coverage/scan.ts` | The packages whose code writes the table, and the one holding its entities (`notes-table`) |
   | **`WRITER_MAP_PATH`**, **`INVARIANTS_PATH`**, **`HELPERS`** | `invariant-coverage/check.ts` | `packages/notes-table/entity-writers.json`, `packages/notes-table/src/helpers/invariants`, `notes-table` |
   | **`UI_PATHS`**, **`NOT_DEPLOYED`** | `post-merge-test/plan.ts` | What counts as a UI change worth clicking through, and paths that never reach a deployed stack |
   | `SPEC_READY_LABEL`, `AGENT_BRANCH_PREFIX` | `agent-issues/gate.ts` | `spec-ready`, `openhands/` |
   | `AGENT_LABEL` | `agent-issues/issue.ts` | `openhands` |
   | `AGENT_BRANCH`, `REVIEW_STATUS_CONTEXT`, `MAX_CI_FIX_ATTEMPTS` | `agent-ci/plan.ts` | `^openhands\/issue-\d+$`, `software-factory/review`, `5` |
   | `MAX_REVIEW_FIX_ATTEMPTS`, `CHANGES_REQUESTED` | `agent-review/plan.ts` | `5`, `🔄 CHANGES REQUESTED` |
   | `WAIVER_LABEL` | `ui-screenshots/check.ts`, `invariant-coverage/check.ts` | `no-ui-screenshots`, `no-new-invariant` |

   If you won't check invariants yet, leave the `invariant-coverage` folder in place and don't
   copy its PR Checks job in step 6. Some unit tests read the real invariants files, so update
   those tests (in `invariant-coverage/check.test.ts`) or the paths above.

   <Aside type="caution">
   Don't change `REVIEW_STATUS_CONTEXT`. `software-factory/review` is the status the OpenHands
   issue-to-PR worker looks for. Any other name and the agent is never sent back.
   </Aside>

4. **Run the tests.**

   ```bash
   pnpm nx run @your-scope/tooling-agent:test
   ```

</Steps>

## Try a dry run

Each of the agent scripts reads the GitHub event from `GITHUB_EVENT_PATH`, and with
`DRY_RUN=true` prints its decision instead of acting on it. To replay a real case, save a payload
from a past workflow run and point the script at it:

```bash
DRY_RUN=true GITHUB_REPOSITORY=owner/repo GITHUB_EVENT_PATH=./event.json \
  pnpm nx run @your-scope/tooling-agent:agent-ci-status
```

```json
{
  "pullRequest": 470,
  "plan": {
    "action": "send-back",
    "attempt": 1,
    "label": "ci-fix-1",
    "description": "CI failed (fix attempt 1 of 5): E2E tests (4/4)"
  }
}
```
