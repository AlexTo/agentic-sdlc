import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**You'll end with:** a `common-scripts` project with six Nx targets and 143 passing unit tests.
The workflows in steps 6 and 7 only call these targets.

<Steps>

1. **Create the project.** Copy `packages/common/scripts/` from this repository (its
   `package.json`, `project.json`, `tsconfig*.json` and `vitest.config.mts`), and delete
   `src/dynamodb/`, which belongs to the example app. Rename it to `@your-scope/common-scripts` in
   `package.json` and `project.json`, and in the `name` in `vitest.config.mts`. A TypeScript
   project generated by the Nx Plugin for AWS has the same shape, if you'd rather generate one.

2. **Copy the four glue folders** from this repository's `packages/common/scripts/src/`:

   <FileTree>
   - packages/common/scripts/src/
     - agent-issues/ spec → issue: gate, discover, tasks, validate, issue, plan-issue, create-next-issue, main, validate-main, and archive, archive-specs, archive-main for archiving
     - agent-ci/ CI → agent: plan, run, main
     - agent-review/ review → agent: plan, run, main
     - ui-screenshots/ the screenshots rule: check, main
   </FileTree>

   They depend only on Node built-ins and the `gh` CLI. `tsx` runs them.

3. **Add the targets** to the project's `project.json`, under `targets`:

   ```json
   "agent-issue":         { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-issues/main.ts",    "cwd": "{projectRoot}" } },
   "archive-specs":       { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-issues/archive-main.ts", "cwd": "{projectRoot}" } },
   "agent-ci-status":     { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-ci/main.ts",        "cwd": "{projectRoot}" } },
   "agent-review-status": { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-review/main.ts",    "cwd": "{projectRoot}" } },
   "ui-screenshots":      { "executor": "nx:run-commands", "options": { "command": "tsx src/ui-screenshots/main.ts",  "cwd": "{projectRoot}" } },
   "validate-tasks":      { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-issues/validate-main.ts", "cwd": "{projectRoot}" } }
   ```

4. **Change the constants for your setup**, if you changed any decision in
   [the overview](../overview/):

   | Constant | File | Default |
   | --- | --- | --- |
   | `SPEC_READY_LABEL`, `AGENT_BRANCH_PREFIX` | `agent-issues/gate.ts` | `spec-ready`, `openhands/` |
   | `AGENT_LABEL` | `agent-issues/issue.ts` | `openhands` |
   | `AGENT_BRANCH`, `REVIEW_STATUS_CONTEXT`, `MAX_CI_FIX_ATTEMPTS` | `agent-ci/plan.ts` | `^openhands\/issue-\d+$`, `software-factory/review`, `5` |
   | `MAX_REVIEW_FIX_ATTEMPTS`, `CHANGES_REQUESTED` | `agent-review/plan.ts` | `5`, `🔄 CHANGES REQUESTED` |
   | `UI_SOURCE`, `SCENARIO`, `WAIVER_LABEL` | `ui-screenshots/check.ts` | portal and shared UI `.tsx`/`.css`, `packages/e2e/src/scenarios/*.e2e.ts`, `no-ui-screenshots` |

   `UI_SOURCE` is the one you will almost certainly change. Point it at your frontends' source.

   <Aside type="caution">
   Don't change `REVIEW_STATUS_CONTEXT`. `software-factory/review` is the status the OpenHands
   issue-to-PR worker looks for. Any other name and the agent is never sent back.
   </Aside>

5. **Run the tests.**

   ```bash
   pnpm nx run @your-scope/common-scripts:test
   ```

</Steps>

## Try a dry run

Each of the three agent scripts reads the GitHub event from `GITHUB_EVENT_PATH`, and with
`DRY_RUN=true` prints its decision instead of acting on it. To replay a real case, save a payload
from a past workflow run and point the script at it:

```bash
DRY_RUN=true GITHUB_REPOSITORY=owner/repo GITHUB_EVENT_PATH=./event.json \
  pnpm nx run @your-scope/common-scripts:agent-ci-status
```

```json
{
  "pullRequest": 470,
  "plan": {
    "action": "send-back",
    "attempt": 1,
    "label": "ci-fix-1",
    "description": "CI failed (fix attempt 1 of 5): E2E tests (4/4)"
  }
}
```
