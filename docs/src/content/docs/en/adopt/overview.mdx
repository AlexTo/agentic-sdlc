The quickest way to get the workflow is to [fork this repository](../../setup/fork/). This section
is for when you can't: you have an existing product repository and want the same setup in it.

Each step adds one piece, copied from this repository, and says how to check it. When you've
finished, your repository has what a fork has, and you continue from
[2. Configure the repository](../../setup/github-repository/).

<Aside type="tip">
Fork this repository anyway and run [your first feature](../../setup/first-feature/) on the notes
app first. Seeing the whole loop work once makes each step here much easier to follow.
</Aside>

## Decide these first

| Decision | Default | Change it if |
| --- | --- | --- |
| Trigger label for implementation | `openhands` | You already use that label |
| Branch prefix | `openhands/issue` | Rarely. The glue matches `openhands/issue-<n>` exactly. If you change it, change `AGENT_BRANCH` and the workflow conditions too |
| Review label | `openhands-review` | Same as above |
| Poll interval | every 5 minutes | You want lower cost and can wait longer (the catalog default is 15) |
| Max fix-up attempts | 5 per loop | Rarely. It is `MAX_*_FIX_ATTEMPTS` in two `plan.ts` files |
| Spec folder numbering | timestamp | Never, with more than one spec author |

In every command and copied file, replace `@your-scope` or `@agentic-sdlc` with your workspace's
npm scope.
