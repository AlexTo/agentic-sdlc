**You'll end with:** `.specify/` in the repository, the `speckit-*` commands available to your
coding agent, and spec folders named by timestamp.

<Steps>

1. **Install the CLI**, pinned to the version Discava uses:

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. **Copy `.specify/`** from this repository. It is already set up the way the workflow needs:

   | Setting | Where | Value |
   | --- | --- | --- |
   | Spec folders named by timestamp | `extensions/git/git-config.yml` | `branch_numbering: timestamp`, so two people writing specs at once never collide: `specs/20261116-013307-course-reviews/`, not `specs/001-course-reviews/` |
   | Conventional commits for each step | `extensions/git/git-config.yml` | `commit_style: conventional` |
   | The git extension's hooks run without asking | `extensions.yml` | `auto_execute_hooks: true`: a branch before `/speckit-specify`, a commit after every step |
   | The templates and the constitution | `templates/`, `memory/` | Already carry the changes in [step 3](../constitution-and-templates/) |

3. **Add the commands for your coding agent.** If it reads Claude Code skills, copy
   `.claude/skills/speckit-*` from this repository. Otherwise, let Speckit write them for your
   agent in a scratch folder, and copy only the command files:

   ```bash
   mkdir /tmp/speckit && cd /tmp/speckit
   specify init --here --integration <your-agent> --script sh --extension git
   ```

   Run `specify init --help` for the list of integrations. Copy the folder it creates for your
   agent's commands, not its `.specify/`, which would undo step 2.

4. **Commit `.specify/`** and the command or skill files.

</Steps>

## Check it worked

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, commands, scripts
  - extensions.yml
  - init-options.json
  - memory/constitution.md the notes app's, rewritten for yours in the next step
  - scripts/bash/
  - templates/ spec, plan, tasks, checklist and constitution templates
</FileTree>

In your coding agent, the `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`,
`speckit-analyze` and `speckit-constitution` commands are listed.

<Aside type="tip">
Spec PRs go on their own branch (`spec/<name>`), not `openhands/...`. The git extension's feature
branch is fine for that. Only the agent's branches use the `openhands/` prefix.
</Aside>
