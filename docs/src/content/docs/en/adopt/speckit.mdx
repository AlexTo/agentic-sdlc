import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**You'll end with:** `.specify/` in the repository, the `speckit-*` commands available to your
coding agent, and spec folders named by timestamp.

<Steps>

1. **Install the CLI**, pinned to the version Discava uses:

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. **Initialise it in the repository** for your coding agent, with the bundled git extension.
   Discava used the `claude` integration, which installs the commands as skills:

   ```bash
   specify init --here --integration claude --script sh --extension git
   ```

   Run `specify init --help` to see the other integrations. Pick the one your team's agent reads.

3. **Switch to timestamp numbering.** In `.specify/extensions/git/git-config.yml`:

   ```yaml
   branch_numbering: timestamp
   commit_style: conventional
   ```

   Folders become `specs/20261116-013307-course-reviews/` instead of `specs/001-course-reviews/`,
   so two people writing specs at once never collide on a number.

4. **Check the git extension's hooks** in `.specify/extensions.yml`. Discava keeps the defaults:
   `speckit.git.feature` before `/speckit-specify` (create a branch), and `speckit.git.commit` after
   every step (one commit per step). It sets `auto_execute_hooks: true` so they run without asking.

5. **Commit `.specify/`** and the integration's command or skill files.

</Steps>

## Check it worked

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, commands, scripts
  - extensions.yml
  - init-options.json
  - memory/constitution.md still the template, filled in the next step
  - scripts/bash/
  - templates/ spec, plan, tasks, checklist and constitution templates
</FileTree>

In your coding agent, the `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`,
`speckit-analyze` and `speckit-constitution` commands are listed.

<Aside type="tip">
Spec PRs go on their own branch (`spec/<name>`), not `openhands/...`. The git extension's feature
branch is fine for that. Only the agent's branches use the `openhands/` prefix.
</Aside>
