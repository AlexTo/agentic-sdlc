[Discava](https://github.com/AlexTo/discava) is a serverless learning management system on AWS:
three React portals, three tRPC APIs on Lambda, a single DynamoDB table, a media pipeline and
search, deployed with CDK from an Nx monorepo. It is large enough that no one keeps it all in
their head, which is exactly when the workflow pays off.

This section describes what Discava actually runs, as of November 2026. Each page links to the
files, so you can read the source next to the explanation.

## The tools and versions

| Tool | Version | Role |
| --- | --- | --- |
| Speckit (`specify-cli`) | 1.3.2 | Spec, plan and task generation, with its `git` extension |
| OpenHands Agent Canvas | 1.41.0 | Agent runtime and the two automations, as a user service on one Linux machine |
| `github-issue-to-pr` automation | 1.2.4 | Implements labelled issues, revises failing PRs |
| `github-pr-reviewer` automation | 1.11.2 | Reviews PRs once checks finish |
| Agent for implementing | Claude Code over ACP, Sonnet | `default` agent profile |
| Agent for reviewing | Claude Code over ACP, Opus | `reviewer` agent profile |
| Nx + pnpm | Nx 23 | Monorepo, `nx affected` in CI |
| Playwright | | E2E tests against the local stack, four shards in CI |
| Trivy, git-secrets, commitlint | | Security scan, pre-commit secret check, commit message format |

## Gap to file

| Gap | Discava's answer | Files |
| --- | --- | --- |
| Spec to issue | Agent Issues workflow and its scripts | `.github/workflows/agent-issues.yml`, `packages/common/scripts/src/agent-issues/` |
| CI failure to agent | Agent CI Status | `.github/workflows/agent-ci.yml`, `src/agent-ci/` |
| Review to agent | Agent Review Status | `.github/workflows/agent-review.yml`, `src/agent-review/` |
| Endless loops | Five-attempt caps with labels | `MAX_CI_FIX_ATTEMPTS` and `MAX_REVIEW_FIX_ATTEMPTS` in `plan.ts` |
| Malformed `tasks.md` | Tasks format job | `pr-checks.yml` `tasks-format`, `src/agent-issues/validate.ts` |
| Unseen UI changes | UI Screenshots job, E2E screenshots comment | `pr-checks.yml`, `src/ui-screenshots/`, `packages/e2e/src/helpers/screenshots.ts` |
| Merge doesn't continue | Agent Issues on merged `openhands/` branches | `src/agent-issues/gate.ts` |
| No cloud for the agent | Local stand-ins for every AWS service | `pnpm dev`, `packages/common/scripts/src/{dynamodb,s3mock,elasticmq,opensearch,local-oidc}` |
| Merge doesn't ship | CI on `main`, then Deploy | `.github/workflows/ci.yml`, `deploy.yml`, `scripts/setup-stage.sh` |
| Secrets and vulnerable dependencies | Trivy in CI and before deploy, git-secrets on commit | `ci.yml` `trivy`, `deploy.yml`, `.husky/pre-commit`, `.trivyignore` |

And the prose every agent reads:

| Guidance | File |
| --- | --- |
| Project rules, checked by every plan | `.specify/memory/constitution.md` (version 1.2.1) |
| Commands, architecture, conventions | `AGENTS.md` |
| PR process, local stack, testing | `CONTRIBUTING.md` |
| Instructions on every implementation issue | `.github/ISSUE_TEMPLATE/implement-phase.md` |
| Speckit templates, customised for the automation | `.specify/templates/tasks-template.md`, `spec-template.md` |

## By the numbers

From 29 October to 18 November 2026:

- 12 feature specs written with Speckit, under `specs/`.
- 2,576 automation sweeps: 1,670 issue-to-PR polls and 906 review polls.
- 67 agent PRs merged. 42 needed no automatic fix, 17 needed one round, one exhausted a loop.
