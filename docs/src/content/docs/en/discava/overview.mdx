[Discava](https://github.com/AlexTo/discava) is a serverless learning management system on AWS:
three React portals, three tRPC APIs on Lambda, a single DynamoDB table, a media pipeline and
search, deployed with CDK from an Nx monorepo. It is large enough that no one keeps it all in
their head, which is exactly when the workflow pays off.

This section describes what Discava runs, as of November 2026, with the files behind each piece.

## The tools and versions

| Tool | Version | Role |
| --- | --- | --- |
| Speckit (`specify-cli`) | 1.3.2 | Spec, plan and task generation, with its `git` extension |
| OpenHands Agent Canvas | 1.45.0 | Agent runtime and the three automations, as a user service on one Linux machine |
| GitHub App `alex-coding-agent` | | What the agents act as on GitHub, with tokens that last an hour |
| `github-issue-to-pr` automation | 1.2.4 | Developer: implements labelled issues, revises failing PRs |
| `github-pr-reviewer` automation | 1.11.2, patched | Reviewer: reviews PRs once checks finish |
| `github-issue-tester` automation | written by hand | Tester: tests merged PRs on the deployed development stage |
| Developer agent | Claude Code over ACP, Sonnet | `developer` agent profile |
| Reviewer agent | Claude Code over ACP, Opus | `reviewer` agent profile |
| Tester agent | Claude Code over ACP, Opus | `tester` agent profile |
| Nx + pnpm | Nx 23 | Monorepo, `nx affected` in CI |
| Playwright | | E2E tests against the local stack, twelve shards in CI. The Tester agent also drives the deployed portals with it |
| Trivy, git-secrets, commitlint | | Security scan, pre-commit secret check, commit message format |

## Gap to file

| Gap | Discava's answer | Files |
| --- | --- | --- |
| Spec to issue | Agent Issues workflow and its scripts | `.github/workflows/agent-issues.yml`, `packages/tooling/agent/src/agent-issues/` |
| CI failure to agent | Agent CI Status | `.github/workflows/agent-ci.yml`, `src/agent-ci/` |
| Review to agent | Agent Review Status | `.github/workflows/agent-review.yml`, `src/agent-review/` |
| Endless loops | Five-attempt caps with labels | `MAX_CI_FIX_ATTEMPTS` and `MAX_REVIEW_FIX_ATTEMPTS` in `plan.ts` |
| Malformed `tasks.md` | Tasks format job | `pr-checks.yml` `tasks-format`, `src/agent-issues/validate.ts` |
| Unseen UI changes | UI Screenshots job, E2E screenshots comment | `pr-checks.yml`, `src/ui-screenshots/`, `packages/e2e/src/helpers/screenshots.ts` |
| Merge doesn't continue | Agent Issues on merged `openhands/` branches | `src/agent-issues/gate.ts` |
| No cloud for the agent | Local stand-ins for every AWS service | `pnpm dev`, `packages/tooling/local-dev/src/{dynamodb,s3mock,elasticmq,opensearch,local-oidc}` |
| Merge doesn't ship | CI on `main`, then Deploy | `.github/workflows/ci.yml`, `deploy.yml`, `scripts/setup-stage.sh` |
| Secrets and vulnerable dependencies | Trivy in CI and before deploy, git-secrets on commit | `ci.yml` `trivy`, `deploy.yml`, `.husky/pre-commit`, `.trivyignore` |
| Merged change never tested where it runs | Post-merge Verify opens a test issue per deployed PR, the Tester agent tests it, and only collaborators can comment on what the agents read | `.github/workflows/post-merge-verify.yml`, `src/post-merge-test/`, `src/helpers/conversation-lock.ts`, the repository's interaction limit |

The glue lives in `packages/tooling/agent/` (`@discava/tooling-agent`). The `src/…` paths in this
section are relative to it.

And the prose every agent reads:

| Guidance | File |
| --- | --- |
| Project rules, checked by every plan | `.specify/memory/constitution.md` (version 1.2.1) |
| Commands, architecture, conventions | `AGENTS.md` |
| PR process, local stack, testing | `DEVELOPMENT.md` |
| No outside issues or pull requests; ideas and bug reports go to Discussions | `CONTRIBUTING.md` |
| Instructions on every implementation issue | `.github/ISSUE_TEMPLATE/implement-phase.md` |
| The by-hand form of a test issue | `.github/ISSUE_TEMPLATE/test-deployed-pr.md` |
| Each agent role's standing prompt | In OpenHands, outside the repository. See [The agents' prompts](../agent-prompts/) |
| Speckit templates, customised for the automation | `.specify/templates/tasks-template.md`, `spec-template.md` |

## By the numbers

From 14 November, when the workflow went live, to 24 November 2026:

- 29 feature specs written with Speckit, under `specs/`.
- 9,869 automation sweeps, every five minutes at first and every two since 22 November: 3,932
  issue-to-PR polls, 3,670 review polls and 2,267 test polls. 603 of them found work and started
  an agent.
- 263 agent PRs merged. 95 needed no automatic fix, 81 needed one round, two exhausted a loop.
