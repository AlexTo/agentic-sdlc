---
title: Issue to PR
description: How merged specs become agent-authored pull requests.
---

1. A merged spec PR labelled `spec-ready` triggers the **Agent Issues** workflow, which opens
   the first implementation issue from `tasks.md`.
2. An implementing agent polls for issues carrying its label and opens a pull request from a
   dedicated branch prefix.
3. The agent's PR ticks the completed tasks in `tasks.md`.
4. When that PR merges, the workflow opens the **next** issue, repeating until the task list is done.

Only the agent's own branches advance the chain; other merged PRs are ignored so the process
cannot loop on its own edits.
