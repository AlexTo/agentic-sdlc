---
title: Specs
description: How work is defined before an agent touches code.
---

Each feature starts as a folder under `specs/`, created with [Spec Kit](https://github.com/github/spec-kit)
skills (`specify`, `clarify`, `plan`, `tasks`, `analyze`). A spec folder contains:

| File | Purpose |
| --- | --- |
| `spec.md` | What and why: user stories, requirements, acceptance criteria |
| `plan.md` | How: technical approach and design decisions |
| `research.md`, `data-model.md`, `contracts/` | Supporting design detail |
| `tasks.md` | Ordered, checkable implementation tasks |
| `checklists/` | Requirement-quality checklists |

Folders are timestamp-numbered (e.g. `20261115-204447-certificates`).

The spec lands via a normal pull request. A human reviews it, and labelling it `spec-ready`
before merge is the signal to start implementation.
