| Label | On | Set by | Read by | Means |
| --- | --- | --- | --- | --- |
| `spec-ready` | Spec PR | A person | Agent Issues | Merging this PR starts implementation. Adding it to an already merged PR does too |
| `openhands` | Issue | Agent Issues, or a person | Issue-to-PR automation | Implement this issue. Remove and re-apply it for a fresh attempt on a new branch |
| `openhands-review` | PR | The implementing agent, after opening or revising | Code review automation | Review this PR's current head |
| `ci-fix-1` … `ci-fix-3` | Agent PR | Agent CI Status | Agent CI Status | That many automatic fix-ups for red CI have been used |
| `ci-fix-exhausted` | Agent PR | Agent CI Status | Agent CI Status, people | CI fix-ups are used up. A person takes over |
| `review-fix-1` … `review-fix-3` | Agent PR | Agent Review Status | Agent Review Status | That many fix-ups for "changes requested" have been used |
| `review-fix-exhausted` | Agent PR | Agent Review Status | Agent Review Status, people | Review fix-ups are used up. A person takes over |
| `no-ui-screenshots` | PR | A maintainer | UI Screenshots | Waive the screenshots rule: the UI change has nothing to look at. Re-run the check after adding it |
| `priority:high` | Issue | A person | Issue-to-PR automation | Start this issue before others in the same poll |

## Resetting a loop

To let the agent try again after you've added guidance, remove both the counter labels and the
`*-exhausted` label, then:

- **CI loop:** re-run the failed PR Checks run.
- **Review loop:** re-request a review, or re-apply `openhands-review`.

The count is the highest `*-fix-<n>` label on the PR, so removing only the `exhausted` label is not
enough.
