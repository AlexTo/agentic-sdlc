`scripts/setup-repository.sh` creates all of them. See
[2. Configure the repository](../../setup/github-repository/).

| Label | On | Set by | Read by | Means |
| --- | --- | --- | --- | --- |
| `spec-ready` | Spec PR | A person | Agent Issues | Merging this PR starts implementation. Adding it to an already merged PR does too |
| `openhands` | Issue | Agent Issues, or a person | Issue-to-PR automation (Developer) | Implement this issue. Remove and re-apply it for a fresh attempt on a new branch |
| `openhands-review` | PR | The Developer agent, after opening or revising | Code review automation (Reviewer) | Review this PR's current head |
| `openhands-test` | Issue | Post-merge Verify, or a person | Issue tester automation (Tester) | Test the merged pull request this issue names on the deployed development stage. Remove and re-apply it to test again |
| `skip-deploy-test` | PR | A person | Post-merge Verify | Open no test issue for this pull request when it is deployed |
| `ci-fix-1` … `ci-fix-5` | Agent PR | Agent CI Status | Agent CI Status | That many automatic fix-ups for red CI have been used |
| `ci-fix-exhausted` | Agent PR | Agent CI Status | Agent CI Status, people | CI fix-ups are used up. A person takes over |
| `review-fix-1` … `review-fix-5` | Agent PR | Agent Review Status | Agent Review Status | That many fix-ups for "changes requested" have been used |
| `review-fix-exhausted` | Agent PR | Agent Review Status | Agent Review Status, people | Review fix-ups are used up. A person takes over |
| `no-ui-screenshots` | PR | A maintainer | UI Screenshots | Waive the screenshots rule: the UI change has nothing to look at. Re-run the check after adding it |
| `no-new-invariant` | PR | A maintainer | PR Checks (`Invariant coverage`) | Waive the invariant coverage rule: no rule spans the new writer. Re-run the check after adding it |
| `priority:high` | Issue | A person | Issue-to-PR automation | Start this issue before others in the same poll |

## Resetting a loop

To let the agent try again after you've added guidance, remove both the counter labels and the
`*-exhausted` label, then:

- **CI loop:** re-run the failed PR Checks run.
- **Review loop:** re-request a review, or re-apply `openhands-review`.

The count is the highest `*-fix-<n>` label on the PR, so removing only the `exhausted` label is not
enough.
