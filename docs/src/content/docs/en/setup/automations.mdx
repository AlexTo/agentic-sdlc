**You'll end with:** OpenHands polling your fork every five minutes. It implements issues
labelled `openhands`, revises PRs marked as failing, and reviews PRs labelled `openhands-review`.
These are the Developer and Reviewer agents.

Both automations come from the Agent Canvas **automation catalog**. You fill in a form, and the
catalog packages a tested worker with your settings. You don't write or upload any code.

<Steps>

1. **Add "GitHub issue to PR"** from the catalog, with these settings:

   | Field | Value |
   | --- | --- |
   | Repositories | `<you>/agentic-sdlc` |
   | Trigger label | `openhands` |
   | Branch prefix | `openhands/issue` |
   | Pull request mode | Ready for review |
   | GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
   | Agent profile | `developer` |
   | Check frequency | `*/5 * * * *` |
   | Timezone | yours |

   Discava runs template version 1.2.4. The worker prompt tells the agent to add the
   `openhands-review` label after it opens a PR, so every new PR reaches the Reviewer.

2. **Add "GitHub code review"** from the catalog:

   | Field | Value |
   | --- | --- |
   | Repositories | `<you>/agentic-sdlc` |
   | Trigger label | `openhands-review` |
   | Requested reviewer | `all-hands-bot` (unused: the label does the work) |
   | New reviews per scan | `2` |
   | Review tone | Concise |
   | Maintainers | empty, or two or more logins (see below) |
   | GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
   | Agent profile | `reviewer` |
   | Check frequency | `*/5 * * * *` |

   Discava runs template version 1.11.2, with the patch below. **New reviews per scan** caps how
   many review conversations one poll starts, so a backlog doesn't start ten agents at once.

   **Maintainers** is optional. When set, an approved PR is handed to one of them as a requested
   reviewer, chosen by who has changed those files before. This happens only when the PR's issue
   carries `priority:medium` or `priority:high`. Discava leaves it empty.

   <Aside type="caution" title="The code review template refuses an app's token">
   Up to at least version 1.11.3, the worker asks `GET /user` which account it acts as, and
   GitHub answers an installation token with `403 Resource not accessible by integration`. Every
   scan then fails before it reviews. Discava patched its copy to ask GraphQL `viewer { login }`
   instead: see [Troubleshooting](../../reference/troubleshooting/#reviews).
   </Aside>

3. **Run each automation once by hand** from its page in Agent Canvas, and read the run log.

</Steps>

## Check it worked

A first run with nothing to do logs a sweep of the repository and ends `COMPLETED`. Then:

1. Create a test issue: "Add a line to README.md saying hello", and add the `openhands` label.
2. Within one poll, a conversation for the issue appears in Agent Canvas.
3. When the agent finishes, a PR appears on `openhands/issue-<n>`, titled `[#<n>] <issue
   title>`, with `openhands-review` added.
4. Once its checks finish, the Reviewer agent posts a review that starts
   "_This review was posted by an AI agent (OpenHands)._" and ends `✅ APPROVED` or
   `🔄 CHANGES REQUESTED`.

Close the PR and delete the branch afterwards.

What each automation does on a poll is on [The agent runtime](../../concepts/the-agent-runtime/).

<Aside type="tip" title="The third role: Tester">
Discava runs a third automation, the Tester, which tests each merged change on its deployed
development stage. It needs a deploy to test, so it isn't part of this setup. When your repository
deploys by itself, see [Post-merge verify](../../discava/post-merge-verify/) and
[The agents' prompts](../../discava/agent-prompts/).
</Aside>

<Aside type="note">
To give the agent a second try at an issue from scratch, remove and re-apply the `openhands` label.
To send it back to an open PR with your own comment, post the status the glue workflows post:
`gh api repos/<you>/agentic-sdlc/statuses/<sha> -f state=failure -f context=software-factory/review -f description="See my comment"`.
</Aside>
