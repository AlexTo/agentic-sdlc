A [fork of this repository](../../guides/fork-this-repo/) has everything Discava's setup keeps in
the repository. These steps add the part that lives outside it: your GitHub settings, and an
OpenHands installation pointed at your fork. Then you write a spec for the notes app and watch it
go from spec PR to merged agent PRs.

**Time:** about an hour, most of it waiting for the first agent run.

## What you need

| Need | Why |
| --- | --- |
| A GitHub account | To fork, and to own the token the agents use |
| Node.js 24 and pnpm | To run the repository and Agent Canvas |
| `uv` | Agent Canvas starts its backend with `uvx` |
| Docker | Only to run the notes app and its e2e tests locally. CI runs them for the agent |
| GitHub CLI (`gh`), signed in | Most steps use it |
| A coding agent, installed and signed in | Writes specs with Speckit, and runs inside OpenHands. Discava uses Claude Code |

<Aside type="note">
Agent Canvas runs on your own machine and polls GitHub, so it needs no public address and no
webhook. The agents only work while it is running.
</Aside>

## The steps

| # | Step | You'll end with |
| --- | --- | --- |
| 1 | [Fork the repository](../fork/) | Your own copy, with Actions and Issues on |
| 2 | [Configure the repository](../github-repository/) | Labels, and a protected `main` |
| 3 | [Install OpenHands](../openhands/) | Agent Canvas running, a GitHub token, two agent profiles |
| 4 | [Create the two automations](../automations/) | The Developer and Reviewer agents implementing and reviewing in your fork |
| 5 | [Run your first feature](../first-feature/) | A spec for the notes app, carried to merged code by agents |
