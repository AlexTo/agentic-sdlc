**You'll end with:** OpenHands Agent Canvas running on your machine as your GitHub App, and two
agent profiles: `developer` for the Developer agent and `reviewer` for the Reviewer agent.

<Steps>

1. **Install Agent Canvas.** Discava runs version 1.45.0:

   ```bash
   npm install -g @openhands/agent-canvas
   ```

2. **Start it as your app**, from your clone:

   ```bash
   pnpm agent-canvas
   ```

   The first time, it asks for the **App ID** and the path to the **`.pem` file** from
   [step 2](../github-repository/), and keeps both in `~/.config/agent-app/`, readable only by
   you. Then, every time, it:

   - starts Agent Canvas with the app as the author of the agents' commits, so GitHub shows them
     under the app;
   - makes one of the app's tokens, which last an hour, and stores it in Agent Canvas as the
     secret `GITHUB_PERSONAL_ACCESS_TOKEN`, the one the automations read. Despite the name, any
     GitHub token works there;
   - replaces the token every 45 minutes for as long as it runs.

   Wait for the line `Token stored in the GITHUB_PERSONAL_ACCESS_TOKEN secret`, then open
   [http://127.0.0.1:8000](http://127.0.0.1:8000). If Agent Canvas asks which agent to use,
   choose Claude Code: it finds the login you already have, so leave any API key fields blank.

   Keep the terminal open, and always start Agent Canvas this way: the automations only poll
   while it is up, and the token only stays fresh while this command runs.

3. **Create two agent profiles**, one per agent role. In Agent Canvas, open **Settings → Agent**
   and click **Add agent profile**, twice:

   | Name | Agent type | Agent | Model |
   | --- | --- | --- | --- |
   | `developer` | ACP (external subprocess) | `claude-code` | `sonnet` |
   | `reviewer` | ACP (external subprocess) | `claude-code` | `opus` |

   ACP is the Agent Client Protocol: the coding agent you already use does the work, signed in
   as you on this machine. Any agent and model works. Keep the Reviewer at least as strong as the
   Developer: it is the last check before you.

   Leave everything else as it is. Agent Canvas already runs unattended (no confirmation
   prompts), with room for a whole phase in one conversation (500 iterations).

</Steps>

## Check it worked

In Agent Canvas, **Settings → Secrets** lists `GITHUB_PERSONAL_ACCESS_TOKEN`. Start a conversation
with the `developer` profile and ask it:

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

It reports `<app-name>[bot]`, and an empty issue list.

<Aside type="caution" title="Keep your own GitHub login away from the agents">
Don't add a GitHub token under Agent Canvas's **Integrations**, and delete any GitHub server
listed under **MCP Servers**: either one holds a fixed token, usually yours, and an agent using it
acts as you instead of the app.
</Aside>

<Aside type="caution">
The agent runs commands on this machine as your user. Don't keep cloud credentials in its
environment, and use a separate machine or VM once you go beyond trying it out.
</Aside>

<Aside type="tip" title="Running Agent Canvas as a service">
Once Agent Canvas runs as a service instead of in a terminal, have a timer run
`pnpm agent-canvas --once` every 45 minutes: it makes one token, stores it and exits. Discava
does this on Linux with systemd: see
[Discava's OpenHands setup](../../discava/openhands-setup/#the-github-app).
</Aside>

Discava has a third profile, `tester`, for the Tester agent. It tests merged changes on a deployed
stage, which the notes app doesn't have, so you don't need it here.
