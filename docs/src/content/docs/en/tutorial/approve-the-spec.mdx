**You are here:** human gate #1. **Output:** a merged spec PR and the first implementation issue.

<Steps>

1. Open the spec PR.

   ```bash
   git add specs/ && git commit -m "docs(specs): add note tags spec"
   git push -u origin spec/note-tags
   gh pr create --fill
   ```

2. Review it as you would code. Read `spec.md` first, then `plan.md`, then skim `tasks.md`.
   Ask yourself:

   - Does the spec say what you actually want?
   - Is each phase small enough to review in one sitting?
   - Is anything in the plan something you would reject in a code review?

   Comment on the PR to change anything. The agent reads comments too, so you can ask it to revise.

   Bring in your business analyst or product owner here. `spec.md` is plain language, so they can
   review and approve it on the PR while you check the plan. This review is now the slowest human
   step, and sharing it is how you speed it up. See
   [Human gates](../../concepts/human-gates/#this-is-now-the-main-bottleneck).

3. Label the PR `spec-ready`, then merge.

   ```bash
   gh pr edit --add-label spec-ready
   gh pr merge --squash
   ```

   You opened this PR, so GitHub won't let you approve it. With branch protection on, merge it as
   the repository admin with `gh pr merge --squash --admin`.

</Steps>

## What happens next, with no one touching anything

The **Agent Issues** workflow sees a merged PR carrying `spec-ready`. It reads `tasks.md`, takes
the first unfinished phase and opens an issue from the
[implementation template](https://github.com/AlexTo/agentic-sdlc/blob/main/.github/ISSUE_TEMPLATE/implement-phase.md):
spec folder, task range `T001` to `T003`, and the rules the agent must follow. It adds the
`openhands` label, which is the go signal.

<Aside type="note">
Forgot the label? Add `spec-ready` to the already merged PR, or run the workflow by hand with the
spec folder name. Nothing else is needed.
</Aside>

Your attention is now free until there is something to review. Next: [Agent implements](../agent-implements/).
