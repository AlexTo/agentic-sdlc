**You are here:** 🧑 you + 🤖 agent. **Output:** `plan.md`, `data-model.md`, `contracts/` and `tasks.md`.

<Steps>

1. Generate the plan.

   ```text
   /speckit-plan
   ```

   The plan reads the spec and the project constitution (`.specify/memory/constitution.md`) and
   decides *how*: add `tags` to the ElectroDB entity, extend the tRPC input schemas, add a
   `tag` filter to `notes.list`.

2. Generate the tasks.

   ```text
   /speckit-tasks
   ```

   `tasks.md` is ordered, checkable and grouped by phase. A script reads it later, so its
   [format](../../reference/tasks-format/) is fixed, and a PR check validates it in the next step.

   ```markdown
   ## Phase 1: User Story 1 - Tags in the data and API (Priority: P1) 🎯 MVP
   - [ ] T001 Add `tags` to the note entity in packages/notes-table/src/entities/note.ts
   - [ ] T002 [P] Unit tests for tag rules (max five, unique, case-insensitive)
   - [ ] T003 Extend create and update procedures in packages/notes-api/src/procedures/notes.ts

   ## Phase 2: User Story 2 - Tags on the website (Priority: P2)
   - [ ] T004 Tag input on the note form
   - [ ] T005 Tag filter on the list page
   - [ ] T006 e2e scenario with screenshots, invariant and concurrency tests

   ## Phase 3: Docs
   - [ ] T007 Describe tags on the notes app page in docs/
   - [ ] T008 **(human)** Confirm the screenshots match the docs wording
   ```

3. Cross-check everything before any code exists.

   ```text
   /speckit-analyze
   ```

   It reports requirements with no task, tasks with no requirement, and contradictions between
   the three files. Fix them now; it costs a sentence. After implementation it costs a PR.

</Steps>

Tasks marked **(human)** are skipped by the agent and listed in its PR description for you.
