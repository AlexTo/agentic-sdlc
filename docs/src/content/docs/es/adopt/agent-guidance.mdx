import { Steps, Aside } from '@astrojs/starlight/components';

**Al terminar tendrás:** un `AGENTS.md` que todo agente lee primero, y las plantillas de issue bajo
`.github/ISSUE_TEMPLATE/`, el origen de las instrucciones fijas de cada issue de implementación.

<Steps>

1. **Copia `AGENTS.md`** de este repositorio y reescribe cada sección para tu proyecto. Es
   breve a propósito: lo que un agente necesita en cada ejecución, y nada más.

   | Sección | Escribe |
   | --- | --- |
   | What this is | Un párrafo: el producto, el stack, la herramienta de monorepo |
   | Commands | Instalar; build, lint y tests de todo; los tests de un proyecto, una vez (no en modo watch); un archivo de test; `nx affected`; e2e; desarrollo local |
   | Architecture | Una viñeta por paquete: qué es, qué puede importar, dónde va el código nuevo de cada tipo |
   | Conventions | Conventional Commits, el formateador por su nombre, dónde van los helpers, y cada regla que un revisor ha tenido que repetir dos veces |

   <Aside type="tip">
   La sección de comandos es la que más importa. Un agente que no encuentra "ejecutar un archivo de test, una vez" ejecutará
   toda la suite en modo watch y se quedará colgado. Ejecuta una vez cada comando que listes, para asegurarte de que funciona.
   </Aside>

   Cuando la sección de arquitectura ya no cabe en una línea por paquete, mueve el detalle de cada paquete a un
   `AGENTS.md` anidado en su carpeta, y deja en la raíz una línea que apunte allí. Un agente solo carga un
   archivo anidado cuando trabaja en esa carpeta, así que cada ejecución lee solo el detalle que necesita. El
   `packages/tooling/agent/AGENTS.md` de este repositorio es uno; cópialo junto con el pegamento en el
   [paso 5](../glue-scripts/).

   Si tu agente lee un archivo con otro nombre, como `CLAUDE.md`, haz que ese archivo apunte a
   `AGENTS.md`. El `CLAUDE.md` de este repositorio empieza con `@AGENTS.md`, que Claude Code lee
   como "incluye aquí ese archivo".

2. **Copia `.github/ISSUE_TEMPLATE/`** de este repositorio: `implement-phase.md` para el
   Desarrollador, y `test-deployed-pr.md` para el Tester, si lo añades en el [paso 9](../deploy/).

   El script de Agent Issues escribe él mismo las secciones de spec y alcance de la issue, y lee todo
   lo que hay bajo `## Instructions for the agent` en `implement-phase.md` en tiempo de ejecución. Mantén
   exactamente ese encabezado, porque el script lo busca y falla sin él. Deja también `#<parent>` tal cual:
   el script lo sustituye por la issue padre de la spec, y elimina la viñeta cuando la spec no tiene
   ninguna.

3. **Edita las instrucciones para que encajen con tu stack**: los comandos, la ruta del helper de capturas y
   lo que significa "cloud credentials" para ti.

</Steps>

## Comprueba que funciona

```bash
grep -c '^## Instructions for the agent$' .github/ISSUE_TEMPLATE/implement-phase.md
```
