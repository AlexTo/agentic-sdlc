**Al terminar tendrás:** un workflow **PR Checks** cuyo fallo alimenta el bucle de CI, un check **UI Screenshots**
y **CI** en `main`.

<Steps>

1. **Copia `.github/workflows/pr-checks.yml`** de este repositorio. Mantén su `name: PR Checks`
   exactamente: Agent CI Status escucha un workflow con ese nombre. Sus jobs:

   | Job | ¿Se deja tal cual? |
   | --- | --- |
   | `checks`, una matriz de `lint`, `test`, `build` con `fail-fast: false` | Sí |
   | `tasks-format` | Sí |
   | `e2e`, en shards, más `e2e-result`, que reúne los shards en un único check `E2E tests` | Ajusta el número de shards a tu suite |
   | `e2e-screenshots` | Sí, una vez hecho el [paso 8](../local-stack-and-e2e/) |

2. **Copia `.github/workflows/ui-screenshots.yml`.** En este repositorio la regla de capturas es su
   propio workflow, disparado en `opened, synchronize, reopened, labeled, unlabeled`. Así, añadir o
   quitar la label `no-ui-screenshots` vuelve a ejecutar solo este check, no toda la suite e2e.
   Discava ejecuta la misma regla como un job de PR Checks. Las dos opciones funcionan.

3. **Copia `.github/workflows/ci.yml`** para los push a `main`. Mantén el paso `Check for mutations`
   (`git diff --ignore-space-at-eol --exit-code` después del build). Detecta archivos generados que el
   agente olvidó incluir en el commit. Mantén el job `playwright-cache` si usas Playwright: las ejecuciones de PR solo pueden
   restaurar cachés guardadas en `main`.

   El job `build` pasa `nx-cache-scope: main` a `init-monorepo`, que guarda la caché de tareas de Nx.
   La primera ejecución de un PR parte de ella, así que las tareas cuyas entradas ya construyó `main` se reproducen, no
   se vuelven a ejecutar, y el agente espera menos en cada ronda de corrección. Cada rama de `checks` en PR Checks guarda
   su propia caché de la misma forma, excepto `lint`, que solo restaura, porque hacer lint es más rápido que
   guardar una caché. `init-monorepo` limita la caché a 1 GB.

4. **Copia `.github/workflows/cache-cleanup.yml`.** Borra las cachés de un PR cuando el PR se cierra.
   Nada más puede leerlas, y sin él cuentan para los 10 GB de caché de Actions del repositorio
   hasta que GitHub las expulsa, empezando por las de PR que siguen abiertos. Consulta
   [Mantenerlo rápido](../../discava/pr-checks/#mantenerlo-rápido) para ver lo que esto le ahorró a Discava.

5. **Fija cada action a un SHA de commit**, como hacen los archivos copiados, y añade
   `.github/dependabot.yml` para que las versiones fijadas se mantengan al día:

   ```yaml
   version: 2
   updates:
     - package-ecosystem: 'npm'
       directory: '/'
       schedule: { interval: 'weekly' }
       groups: { all: { patterns: ['*'] } }
     - package-ecosystem: 'github-actions'
       directories: ['/', '/.github/actions/*']
       schedule: { interval: 'weekly' }
       groups: { github-actions: { applies-to: version-updates, patterns: ['*'] } }
   ```

</Steps>

## Comprueba que funciona

Abre un PR desechable que rompa una línea de `tasks.md`, por ejemplo indentando una tarea. El
check **Tasks format** falla con una anotación en esa línea:

```text
A task must be written "- [ ] T<3 digits> <description>", starting in the first column
```

Abre otro que cambie un archivo de UI sin tocar ningún escenario. **UI Screenshots** falla:

```text
This pull request changes UI source (…) but no e2e scenario gained a `screenshot(page, 'name')` call.
```

<Aside type="note">
`codecov/codecov-action` en los archivos copiados necesita un secret `CODECOV_TOKEN`. Quita el paso si
no usas Codecov.
</Aside>
