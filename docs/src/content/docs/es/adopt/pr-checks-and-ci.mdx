**Al terminar tendrás:** un workflow **PR Checks** cuyo fallo alimenta el bucle de CI, un check **UI Screenshots**
y **CI** en `main`.

<Steps>

1. **Copia cuatro workflows** de `.github/workflows/` de este repositorio:

   | Archivo | Qué hace |
   | --- | --- |
   | `pr-checks.yml` | Lint, test y build de lo que afecta el PR; `Tasks format`; `Invariant coverage`; e2e en shards reunidos en un único check `E2E tests`; el comentario `E2E screenshots` |
   | `ui-screenshots.yml` | La regla de capturas, como su propio workflow, para que añadir o quitar la label `no-ui-screenshots` vuelva a ejecutar solo este check. Discava la ejecuta como un job de PR Checks. Las dos opciones funcionan |
   | `ci.yml` | Los mismos checks en cada push a `main`, Trivy, la caché de Playwright y el despliegue de este sitio de documentación |
   | `cache-cleanup.yml` | Borra las cachés de un PR cuando se cierra |

   Mantén exactamente el `name: PR Checks` de `pr-checks.yml`: Agent CI Status escucha un workflow con
   ese nombre.

2. **Apúntalos a tus proyectos.** Busca `@agentic-sdlc/` en los archivos copiados y cambia el
   scope. Después, en `pr-checks.yml`:

   | Job | Cambio |
   | --- | --- |
   | `invariant-coverage` | Los `paths` del código que podría escribir en tu tabla, los mismos que `WRITER_PACKAGES` en el paso 5. O borra el job si todavía no compruebas invariantes |
   | `e2e` | El número de shards en `matrix.shard`, según tu suite. Un shard cuesta unos dos minutos antes de su primer test, así que deja de añadirlos cuando los tests de cada uno tarden más o menos eso |
   | `e2e-screenshots` | Nada, una vez hecho el [paso 8](../local-stack-and-e2e/) |

   En `ci.yml`, borra el job `deploy_docs` y su permiso `pages: write` salvo que publiques
   un sitio de documentación desde `docs/`.

3. **Conserva lo que mantiene rápido al agente.** El paso `Check for mutations` de `ci.yml` (`git diff
   --exit-code` después del build) detecta archivos generados que el agente olvidó incluir en el commit. El
   job `playwright-cache` guarda Chromium desde `main`, ya que las ejecuciones de PR solo pueden restaurar
   cachés guardadas allí. El job `build` guarda la caché de tareas de Nx desde `main`, así que la primera
   ejecución de un PR reproduce lo que `main` ya construyó, y el agente espera menos en cada ronda de
   corrección. Cada rama de `checks` en PR Checks guarda su propia caché de la misma forma, excepto `lint`,
   que solo restaura. `init-monorepo` limita la caché a 1 GB, y Cache Cleanup libera la parte de un PR
   cerrado de los 10 GB del repositorio. Consulta
   [Mantenerlo rápido](../../discava/pr-checks/#mantenerlo-rápido) para ver lo que esto le ahorró a Discava.

</Steps>

Cada action está fijada a un SHA de commit, y el `dependabot.yml` que copiaste en el paso 1 mantiene al
día las versiones fijadas.

## Comprueba que funciona

Abre un PR desechable que rompa una línea de `tasks.md`, por ejemplo indentando una tarea. El
check **Tasks format** falla con una anotación en esa línea:

```text
A task must be written "- [ ] T<3 digits> <description>", starting in the first column
```

Abre otro que cambie un archivo de UI sin tocar ningún escenario. **UI Screenshots** falla:

```text
This pull request changes UI source (…) but no e2e scenario gained a `screenshot(page, 'name')` call.
```

<Aside type="note">
`codecov/codecov-action` en los archivos copiados necesita un secret `CODECOV_TOKEN`. Quita el paso si
no usas Codecov.
</Aside>
