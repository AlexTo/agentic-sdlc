import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**Al terminar tendrás:** `.specify/` en el repositorio, los comandos `speckit-*` disponibles para tu
agente de programación y carpetas de spec nombradas por timestamp.

<Steps>

1. **Instala la CLI**, fijada a la versión que usa Discava:

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. **Inicialízala en el repositorio** para tu agente de programación, con la extensión git incluida.
   Discava usó la integración `claude`, que instala los comandos como skills:

   ```bash
   specify init --here --integration claude --script sh --extension git
   ```

   Ejecuta `specify init --help` para ver las otras integraciones. Elige la que lee el agente de tu equipo.

3. **Cambia a numeración por timestamp.** En `.specify/extensions/git/git-config.yml`:

   ```yaml
   branch_numbering: timestamp
   commit_style: conventional
   ```

   Las carpetas pasan a ser `specs/20261116-013307-course-reviews/` en lugar de `specs/001-course-reviews/`,
   así que dos personas que escriben specs a la vez nunca chocan.

4. **Revisa los hooks de la extensión git** en `.specify/extensions.yml`. Discava mantiene los valores predeterminados:
   `speckit.git.feature` antes de `/speckit-specify` (crea una rama), y `speckit.git.commit` después de
   cada paso (un commit por paso). Pone `auto_execute_hooks: true` para que se ejecuten sin preguntar.

5. **Haz commit de `.specify/`** y de los archivos de comandos o skills de la integración.

</Steps>

## Comprueba que funciona

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, comandos, scripts
  - extensions.yml
  - init-options.json
  - memory/constitution.md todavía la plantilla, se rellena en el siguiente paso
  - scripts/bash/
  - templates/ plantillas de spec, plan, tasks, checklist y constitución
</FileTree>

En tu agente de programación aparecen los comandos `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`,
`speckit-analyze` y `speckit-constitution`.

<Aside type="tip">
Los PR de spec van en su propia rama (`spec/<name>`), no en `openhands/...`. La rama de feature de la extensión git
sirve para eso. Solo las ramas del agente usan el prefijo `openhands/`.
</Aside>
