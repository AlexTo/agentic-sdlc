**Al terminar tendrás:** un workspace de pnpm con Nx, Biome, Conventional Commits aplicados en cada
commit y una comprobación de secretos antes de cada commit.

El pegamento no necesita Nx. Pero `nx affected` es lo que mantiene los PR checks lo bastante rápidos para que un agente
itere sobre ellos, y cada script de pegamento se ejecuta como un target de Nx. Si usas otra herramienta de monorepo, conserva la
idea: ejecuta solo lo que afecta el PR y expón cada script como una tarea con nombre.

<Steps>

1. **Crea el workspace**, si no tienes uno. Tanto Discava como este repositorio se crearon
   con el Nx Plugin for AWS:

   ```bash
   pnpm create @aws/nx-workspace your-project --iac=cdk --no-interactive
   ```

   Un workspace de Nx existente también sirve. Fija pnpm en el `package.json` raíz con `packageManager`,
   para que CI y el agente usen la misma versión.

2. **Copia estos archivos** de este repositorio a las mismas rutas en el tuyo:

   <FileTree>
   - commitlint.config.js Conventional Commits
   - lint-staged.config.js Biome sobre los archivos en staging
   - .husky/
     - commit-msg ejecuta commitlint
     - pre-commit git-secrets, después lint-staged, y falla si Biome cambió algo, para que el agente vuelva a añadirlo a staging y haga commit de nuevo
     - prepare-commit-msg Commitizen, para las personas que hacen commit de forma interactiva. Se omite con `git commit -m`, que es como hacen commit los agentes
   - .git-secrets/ el script de git-secrets que ejecuta el hook pre-commit
   - .gitallowed patrones que git-secrets deja pasar
   - .github/
     - actions/init-monorepo/ configuración de CI compartida
     - actions/changed-paths/ "¿este PR cambió alguna de estas rutas?", para omitir jobs
     - actions/playwright-setup/ Chromium para Playwright, en caché por versión
     - dependabot.yml mantiene al día las actions fijadas y las dependencias
   </FileTree>

   Deja `.husky/pre-push` para el [paso 8](../local-stack-and-e2e/): comprueba el mapa de invariantes.
   `init-monorepo` instala pnpm (con tres intentos, porque un timeout del registro le costaría al
   agente un intento de corrección), Node 24 y opcionalmente uv, restaura las cachés de pnpm y Nx,
   instala las dependencias y define `NX_BASE`/`NX_HEAD` para `nx affected`.

3. **Copia los scripts raíz y las dependencias de desarrollo** del `package.json` de este repositorio: el
   bloque `scripts` (al que llaman `AGENTS.md`, CI y el agente), y de `devDependencies`,
   `@commitlint/config-conventional`, `commitlint`, `commitizen`, `husky` y `lint-staged`. Después:

   ```bash
   pnpm install
   ```

   Su script `prepare` instala los hooks.

4. **Cambia el scope del paquete** en `.github/actions/playwright-setup/action.yml`
   (`@agentic-sdlc/e2e`) por el nombre de tu proyecto de e2e.

</Steps>

## Comprueba que funciona

```bash
git commit --allow-empty -m "not conventional"
```

```text
⧗   input: not conventional
✖   subject may not be empty [subject-empty]
✖   type may not be empty [type-empty]
```

Después, `git commit --allow-empty -m "chore: check hooks"` funciona.

<Aside type="note">
Los títulos de issue que escribe el pegamento son cabeceras de Conventional Commit, y el agente los
reutiliza para sus commits y pull requests. Por eso commitlint va primero.
</Aside>
