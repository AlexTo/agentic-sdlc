**Al terminar tendrás:** un workspace de pnpm con Nx, Biome, Conventional Commits aplicados en cada
commit y una comprobación de secretos antes de cada commit.

El pegamento no necesita Nx. Pero `nx affected` es lo que mantiene los PR checks lo bastante rápidos para que un agente
itere sobre ellos, y cada script de pegamento se ejecuta como un target de Nx. Si usas otra herramienta de monorepo, conserva la
idea: ejecuta solo lo que afecta el PR y expón cada script como una tarea con nombre.

<Steps>

1. **Crea el workspace**, si no tienes uno. Tanto Discava como este repositorio se crearon
   con el Nx Plugin for AWS:

   ```bash
   pnpm create @aws/nx-workspace your-project --iac=cdk --no-interactive
   ```

   Esto también instala el hook pre-commit de git-secrets que se usa en el paso 4. Un workspace de Nx existente
   también sirve. Fija pnpm en el `package.json` raíz, para que CI y el agente usen la misma versión:

   ```json
   { "packageManager": "pnpm@<version>" }
   ```

2. **Añade los scripts raíz** que llamarán `AGENTS.md`, CI y el agente:

   ```json
   "scripts": {
     "dev": "nx run-many --target dev",
     "build": "nx run-many --target build",
     "lint": "nx run-many --target lint --configuration=fix",
     "test": "nx run-many --target test --all",
     "trivy": "nx run-many --target trivy --all",
     "prepare": "husky"
   }
   ```

3. **Añade Conventional Commits con commitlint.** Los títulos de issue que escribe el pegamento son cabeceras de Conventional
   Commit, y el agente los reutiliza.

   ```bash
   pnpm add -Dw @commitlint/config-conventional commitlint husky lint-staged
   echo "export default { extends: ['@commitlint/config-conventional'] };" > commitlint.config.js
   ```

   `.husky/commit-msg`:

   ```bash
   FORCE_COLOR=1 pnpm commitlint --edit "$1"
   ```

4. **Añade el hook pre-commit.** Registra una vez los patrones de secretos de AWS, rechaza un commit que contenga un
   secreto, ejecuta Biome sobre los archivos en staging y falla si eso cambió algo, para que el agente
   vuelva a añadirlos a staging y haga commit de nuevo. `.husky/pre-commit`:

   ```bash
   if ! git config --get-all secrets.patterns >/dev/null 2>&1; then
     bash .git-secrets/git-secrets --register-aws
   fi
   bash .git-secrets/git-secrets --pre_commit_hook

   PRE_SHA="$(git diff HEAD --ignore-space-at-eol | shasum -a 256 --tag)"
   FORCE_COLOR=1 pnpm lint-staged
   POST_SHA="$(git diff HEAD --ignore-space-at-eol | shasum -a 256 --tag)"

   if [ "$PRE_SHA" != "$POST_SHA" ]; then
     echo "Pre-commit modified your working directory"
     echo "Please verify and stage changed, then retry git commit"
     exit 1
   fi
   ```

   Un workspace del Nx Plugin for AWS ya tiene `.git-secrets/git-secrets`, `.gitallowed`
   y la mayor parte de este hook. Si no, cópialos de este repositorio. `lint-staged.config.js`:

   ```js
   export default {
     'packages/**/*.{ts,tsx,js,jsx,json,css,scss}': ['biome check --write --no-errors-on-unmatched'],
     '*.{js,json}': ['biome check --write --no-errors-on-unmatched'],
   };
   ```

5. **Copia la action compartida de configuración de CI** de este repositorio: `.github/actions/init-monorepo/`.
   Instala pnpm (con tres intentos, porque un timeout del registro le costaría al agente un
   intento de corrección), Node 24 y opcionalmente uv, restaura la caché de pnpm, instala las dependencias y
   define `NX_BASE`/`NX_HEAD` para `nx affected`.

</Steps>

## Comprueba que funciona

```bash
git commit --allow-empty -m "not conventional"
```

```text
⧗   input: not conventional
✖   subject may not be empty [subject-empty]
✖   type may not be empty [type-empty]
```

Después, `git commit --allow-empty -m "chore: check hooks"` funciona.

<Aside type="note">
Discava también ejecuta Commitizen desde `prepare-commit-msg` para las personas que hacen commit de forma interactiva.
Se omite cuando se da un mensaje con `-m`, que es como hacen commit los agentes, así que es opcional.
</Aside>
