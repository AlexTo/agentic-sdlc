**Al terminar tendrás:** tu propio fork, con Issues y Actions activados, clonado en local y con sus
checks pasando.

<Steps>

1. **Haz fork y clona.**

   ```bash
   gh repo fork AlexTo/agentic-sdlc --clone
   cd agentic-sdlc
   ```

2. **Haz que tu fork sea el predeterminado para `gh`.** Si no, los comandos de `gh` apuntan al repositorio
   original, no al tuyo.

   ```bash
   gh repo set-default <you>/agentic-sdlc
   ```

3. **Activa Issues.** GitHub las desactiva en los forks, y todo el workflow funciona sobre issues. En
   tu fork, abre **Settings → General → Features** y marca **Issues**.

4. **Activa Actions.** Abre la pestaña **Actions** de tu fork y haz clic en **I understand my workflows, go
   ahead and enable them**. GitHub no ejecuta workflows en un fork hasta que lo haces.

5. **Instala y ejecuta los checks en local**, los mismos que ejecuta CI:

   ```bash
   pnpm install
   pnpm nx run-many --target lint --all
   pnpm nx run-many --target test --all
   pnpm nx run-many --target build --all
   ```

   Para ejecutar la app de notas (necesita Docker): `pnpm dev`, y abre la URL que imprime el sitio web.

</Steps>

## Comprueba que funciona

Tu fork muestra una pestaña **Issues**, y su pestaña **Actions** lista los workflows. En local, los tres
comandos `nx run-many` pasan.

<Aside type="note">
Hay dos cosas que funcionan distinto en un fork, y ninguna bloquea el workflow. Sin el secret `CODECOV_TOKEN`,
el paso de subida de cobertura registra un error y continúa. El job **Deploy Docs** de CI falla
hasta que activas GitHub Pages (**Settings → Pages → Source: GitHub Actions**), o puedes
ignorarlo.
</Aside>
