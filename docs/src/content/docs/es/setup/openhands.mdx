import { Steps, Aside } from '@astrojs/starlight/components';

**Al terminar tendrás:** OpenHands Agent Canvas ejecutándose en tu máquina como tu GitHub App, y dos
perfiles de agente: `developer` para el agente Desarrollador y `reviewer` para el agente Revisor.

<Steps>

1. **Instala Agent Canvas.** Discava usa la versión 1.45.0:

   ```bash
   npm install -g @openhands/agent-canvas
   ```

2. **Inícialo como tu app**, desde tu clon:

   ```bash
   pnpm agent-canvas
   ```

   La primera vez, pide el **App ID** y la ruta del **archivo `.pem`** del
   [paso 2](../github-repository/), y guarda ambos en `~/.config/agent-app/`, legibles solo por ti.
   Después, cada vez:

   - inicia Agent Canvas con la app como autora de los commits de los agentes, así que GitHub los
     muestra con la app;
   - crea uno de los tokens de la app, que duran una hora, y lo guarda en Agent Canvas como el
     secret `GITHUB_PERSONAL_ACCESS_TOKEN`, el que leen las automatizaciones. Pese al nombre, ahí
     sirve cualquier token de GitHub;
   - reemplaza el token cada 45 minutos mientras esté en marcha.

   Espera a la línea `Token stored in the GITHUB_PERSONAL_ACCESS_TOKEN secret`, y abre
   [http://127.0.0.1:8000](http://127.0.0.1:8000). Si Agent Canvas pregunta qué agente usar,
   elige Claude Code: encuentra la sesión que ya tienes iniciada, así que deja en blanco los campos
   de API key.

   Deja la terminal abierta, e inicia siempre Agent Canvas de esta forma: las automatizaciones solo
   consultan mientras está activo, y el token solo se mantiene al día mientras este comando se ejecuta.

3. **Crea dos perfiles de agente**, uno por cada rol de agente. En Agent Canvas, abre **Settings → Agent**
   y haz clic en **Add agent profile**, dos veces:

   | Nombre | Tipo de agente | Agente | Modelo |
   | --- | --- | --- | --- |
   | `developer` | ACP (external subprocess) | `claude-code` | `sonnet` |
   | `reviewer` | ACP (external subprocess) | `claude-code` | `opus` |

   ACP es el Agent Client Protocol: el agente de programación que ya usas hace el trabajo, con tu
   sesión iniciada en esta máquina. Cualquier agente y modelo sirve. Mantén el Revisor al menos tan
   potente como el Desarrollador: es el último control antes de ti.

   Deja todo lo demás como está. Agent Canvas ya se ejecuta sin supervisión (sin peticiones de
   confirmación), con espacio para una fase entera en una conversación (500 iteraciones).

</Steps>

## Comprueba que funciona

En Agent Canvas, **Settings → Secrets** lista `GITHUB_PERSONAL_ACCESS_TOKEN`. Inicia una conversación
con el perfil `developer` y pídele:

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

Informa de `<app-name>[bot]` y de una lista de issues vacía.

<Aside type="caution" title="Mantén tu propio login de GitHub lejos de los agentes">
No añadas un token de GitHub en **Integrations** de Agent Canvas, y borra cualquier servidor de GitHub
que aparezca en **MCP Servers**: cualquiera de los dos guarda un token fijo, normalmente el tuyo, y un
agente que lo use actúa como tú en lugar de como la app.
</Aside>

<Aside type="caution">
El agente ejecuta comandos en esta máquina con tu usuario. No guardes credenciales de la nube en su
entorno, y usa una máquina o VM separada cuando vayas más allá de probarlo.
</Aside>

<Aside type="tip" title="Ejecutar Agent Canvas como servicio">
Cuando Agent Canvas se ejecute como servicio en lugar de en una terminal, haz que un timer ejecute
`pnpm agent-canvas --once` cada 45 minutos: crea un token, lo guarda y termina. Discava lo hace en
Linux con systemd: consulta
[La configuración de OpenHands de Discava](../../discava/openhands-setup/#la-github-app).
</Aside>

Discava tiene un tercer perfil, `tester`, para el agente Tester. Prueba los cambios fusionados en un
stage desplegado, que la app de notas no tiene, así que aquí no lo necesitas.
