**Estás aquí:** 🧑 control humano n.º 1. **Resultado:** un PR de spec fusionado y la primera issue de implementación.

<Steps>

1. Sube la rama que creó Speckit y abre un pull request para ella.

   ```bash
   git add specs/ && git commit -m "docs(specs): add note tags spec"
   git push -u origin HEAD
   gh pr create --fill
   ```

   En un fork, `gh` lo abre en tu fork una vez que has ejecutado `gh repo set-default`. La web de
   GitHub ofrece en su lugar el repositorio original como base.

2. Revísalo como revisarías código. Lee primero `spec.md`, después `plan.md`, y luego echa un vistazo a `tasks.md`.
   Pregúntate:

   - ¿La spec dice lo que realmente quieres?
   - ¿Cada fase es lo bastante pequeña para revisarla de una sentada?
   - ¿Hay algo en el plan que rechazarías en una code review?

   Comenta en el PR para cambiar lo que sea. El agente también lee los comentarios, así que puedes pedirle que lo revise.

   Involucra aquí a tu analista de negocio o product owner. `spec.md` está en lenguaje llano, así que pueden
   revisarlo en el PR mientras tú compruebas el plan. Consulta
   [Controles humanos](../../concepts/human-gates/#esto-es-ahora-el-principal-cuello-de-botella).

3. Añade la label `spec-ready` al PR y después fusiónalo.

   Tú abriste este PR, así que GitHub no te deja aprobarlo. Con la protección de rama activada, marca
   **Merge without waiting for requirements to be met** para fusionar como administrador del repositorio.

</Steps>

## Qué pasa después, sin que nadie toque nada

El workflow **Agent Issues** ve un PR fusionado que lleva `spec-ready`. Lee `tasks.md`, toma
la primera fase sin terminar y abre una issue a partir de la
[plantilla de implementación](https://github.com/AlexTo/agentic-sdlc/blob/main/.github/ISSUE_TEMPLATE/implement-phase.md):
carpeta de la spec, rango de tareas de `T001` a `T003` y las reglas que el agente debe seguir. Añade la
label `openhands`, que es la señal de salida.

<Aside type="note">
¿Olvidaste la label? Añade `spec-ready` al PR ya fusionado.
</Aside>

Tu atención queda libre hasta que haya algo que revisar. Siguiente: [El agente implementa](../agent-implements/).
