**Résultat :** un `AGENTS.md` que chaque agent lit en premier, et les templates d'issue sous
`.github/ISSUE_TEMPLATE/`, la source des instructions permanentes de chaque issue d'implémentation.

<Steps>

1. **Copiez `AGENTS.md`** depuis ce dépôt, et réécrivez chaque section pour votre projet. Il est
   court à dessein : ce dont un agent a besoin à chaque exécution, et rien d'autre.

   | Section | À écrire |
   | --- | --- |
   | What this is | Un paragraphe : le produit, la stack, l'outil de monorepo |
   | Commands | Installer ; build, lint, tests de tout ; les tests d'un projet, une fois (pas en mode watch) ; un fichier de test ; `nx affected` ; e2e ; dev local |
   | Architecture | Une puce par package : ce qu'il est, ce qu'il peut importer, où va le nouveau code de chaque type |
   | Conventions | Conventional Commits, le formateur par son nom, où vont les helpers, et chaque règle qu'un relecteur a dû répéter deux fois |

   <Aside type="tip">
   La section des commandes est la plus importante. Un agent qui ne trouve pas « lancer un fichier de test, une fois » lancera
   toute la suite en mode watch et restera bloqué. Lancez une fois chaque commande que vous listez, pour être sûr qu'elle fonctionne.
   </Aside>

   Quand la section d'architecture dépasse une ligne par package, déplacez le détail de chaque package dans un
   `AGENTS.md` imbriqué dans son dossier, et laissez à la racine une ligne qui y renvoie. Un agent ne charge un
   fichier imbriqué que lorsqu'il travaille dans ce dossier, donc une exécution ne lit que le détail dont elle a besoin. Le
   `packages/tooling/agent/AGENTS.md` de ce dépôt en est un ; copiez-le avec la glue à
   [l'étape 5](../glue-scripts/).

   Si votre agent lit un fichier au nom différent, comme `CLAUDE.md`, faites pointer ce fichier vers
   `AGENTS.md`. Le `CLAUDE.md` de ce dépôt commence par `@AGENTS.md`, que Claude Code lit
   comme « inclure ce fichier ici ».

2. **Copiez `.github/ISSUE_TEMPLATE/`** depuis ce dépôt : `implement-phase.md` pour le
   Développeur, et `test-deployed-pr.md` pour le Testeur, si vous l'ajoutez à [l'étape 9](../deploy/).

   Le script Agent Issues écrit lui-même les sections de spec et de périmètre de l'issue, et lit tout ce qui se trouve
   sous `## Instructions for the agent` dans `implement-phase.md` au moment de l'exécution. Gardez exactement ce titre,
   car le script le cherche et échoue sans lui. Gardez aussi `#<parent>` tel quel :
   le script le remplace par l'issue parente de la spec, et supprime la puce quand la spec n'en a
   pas.

3. **Adaptez les instructions à votre stack** : les commandes, le chemin du helper de captures d'écran, et
   ce que « cloud credentials » signifie pour vous.

</Steps>

## Vérifier que ça marche

```bash
grep -c '^## Instructions for the agent$' .github/ISSUE_TEMPLATE/implement-phase.md
```

```text
1
```
