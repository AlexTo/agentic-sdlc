**Résultat :** un workflow **PR Checks** dont l'échec alimente la boucle CI, un check **UI Screenshots**,
et la **CI** sur `main`.

<Steps>

1. **Copiez quatre workflows** depuis le dossier `.github/workflows/` de ce dépôt :

   | Fichier | Ce qu'il fait |
   | --- | --- |
   | `pr-checks.yml` | Lint, test et build de ce que la PR affecte ; `Tasks format` ; `Invariant coverage` ; e2e découpé en shards, regroupés en un seul check `E2E tests` ; le commentaire `E2E screenshots` |
   | `ui-screenshots.yml` | La règle des captures d'écran, dans son propre workflow, pour qu'ajouter ou retirer le label `no-ui-screenshots` ne relance que ce check. Discava l'exécute plutôt comme job de PR Checks. Les deux fonctionnent |
   | `ci.yml` | Les mêmes checks à chaque push sur `main`, Trivy, le cache Playwright, et le déploiement de ce site de documentation |
   | `cache-cleanup.yml` | Supprime les caches d'une PR quand elle est fermée |

   Gardez exactement le `name: PR Checks` de `pr-checks.yml` : Agent CI Status écoute un workflow portant
   ce nom.

2. **Faites-les pointer vers vos projets.** Cherchez `@agentic-sdlc/` dans les fichiers copiés et changez le
   scope. Puis, dans `pr-checks.yml` :

   | Job | À changer |
   | --- | --- |
   | `invariant-coverage` | Les `paths` du code qui pourrait écrire dans votre table, les mêmes que `WRITER_PACKAGES` à l'étape 5. Ou supprimez le job si vous ne vérifiez pas encore les invariants |
   | `e2e` | Le nombre de shards dans `matrix.shard`, selon votre suite. Un shard coûte environ deux minutes avant son premier test, donc arrêtez d'en ajouter une fois que les tests de chacun prennent à peu près ce temps |
   | `e2e-screenshots` | Rien, une fois l'[étape 8](../local-stack-and-e2e/) faite |

   Dans `ci.yml`, supprimez le job `deploy_docs` et sa permission `pages: write` sauf si vous publiez
   un site de documentation depuis `docs/`.

3. **Gardez ce qui garde l'agent rapide.** L'étape `Check for mutations` de `ci.yml` (`git diff
   --exit-code` après le build) repère les fichiers générés que l'agent a oublié de committer. Le
   job `playwright-cache` enregistre Chromium depuis `main`, puisque les exécutions de PR ne peuvent restaurer que des caches
   enregistrés là. Le job `build` enregistre le cache de tâches de Nx depuis `main`, pour que la première exécution d'une PR rejoue ce que
   `main` a déjà construit, et l'agent attend moins à chaque tour de correction. Chaque branche de `checks` dans PR
   Checks garde son propre cache de la même façon, sauf `lint`, qui ne fait que restaurer. `init-monorepo`
   plafonne le cache à 1 Go, et Cache Cleanup libère la part d'une PR fermée dans les 10 Go du dépôt.
   Voir [Garder les checks rapides](../../discava/pr-checks/#garder-les-checks-rapides) pour ce que cela a fait gagner à Discava.

</Steps>

Chaque action est épinglée sur un SHA de commit, et le `dependabot.yml` que vous avez copié à l'étape 1 garde les
épinglages à jour.

## Vérifier que ça marche

Ouvrez une PR jetable qui casse une ligne de `tasks.md`, par exemple en indentant une tâche. Le
check **Tasks format** échoue avec une annotation sur cette ligne :

```text
A task must be written "- [ ] T<3 digits> <description>", starting in the first column
```

Ouvrez-en une autre qui modifie un fichier d'UI sans toucher à un scénario. **UI Screenshots** échoue :

```text
This pull request changes UI source (…) but no e2e scenario gained a `screenshot(page, 'name')` call.
```

<Aside type="note">
`codecov/codecov-action` dans les fichiers copiés a besoin d'un secret `CODECOV_TOKEN`. Retirez l'étape si
vous n'utilisez pas Codecov.
</Aside>
