import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**Résultat :** `.specify/` dans le dépôt, les commandes `speckit-*` disponibles pour votre
agent de code, et des dossiers de spec nommés par horodatage.

<Steps>

1. **Installez le CLI**, épinglé sur la version qu'utilise Discava :

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. **Initialisez-le dans le dépôt** pour votre agent de code, avec l'extension git fournie.
   Discava a utilisé l'intégration `claude`, qui installe les commandes sous forme de skills :

   ```bash
   specify init --here --integration claude --script sh --extension git
   ```

   Lancez `specify init --help` pour voir les autres intégrations. Choisissez celle que lit l'agent de votre équipe.

3. **Passez à la numérotation par horodatage.** Dans `.specify/extensions/git/git-config.yml` :

   ```yaml
   branch_numbering: timestamp
   commit_style: conventional
   ```

   Les dossiers deviennent `specs/20261116-013307-course-reviews/` au lieu de `specs/001-course-reviews/`,
   donc deux personnes qui écrivent des specs en même temps n'entrent jamais en collision.

4. **Vérifiez les hooks de l'extension git** dans `.specify/extensions.yml`. Discava garde les valeurs par défaut :
   `speckit.git.feature` avant `/speckit-specify` (créer une branche), et `speckit.git.commit` après
   chaque étape (un commit par étape). Il règle `auto_execute_hooks: true` pour qu'ils s'exécutent sans demander.

5. **Committez `.specify/`** ainsi que les fichiers de commandes ou de skills de l'intégration.

</Steps>

## Vérifier que ça marche

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, commandes, scripts
  - extensions.yml
  - init-options.json
  - memory/constitution.md encore le template, rempli à l'étape suivante
  - scripts/bash/
  - templates/ templates de spec, de plan, de tâches, de checklist et de constitution
</FileTree>

Dans votre agent de code, les commandes `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`,
`speckit-analyze` et `speckit-constitution` sont listées.

<Aside type="tip">
Les PR de spec vont sur leur propre branche (`spec/<name>`), pas sur `openhands/...`. La branche de fonctionnalité
de l'extension git convient pour cela. Seules les branches de l'agent utilisent le préfixe `openhands/`.
</Aside>
