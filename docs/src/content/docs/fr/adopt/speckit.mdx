import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**Résultat :** `.specify/` dans le dépôt, les commandes `speckit-*` disponibles pour votre
agent de code, et des dossiers de spec nommés par horodatage.

<Steps>

1. **Installez le CLI**, épinglé sur la version qu'utilise Discava :

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. **Copiez `.specify/`** depuis ce dépôt. Il est déjà configuré comme le workflow en a besoin :

   | Paramètre | Où | Valeur |
   | --- | --- | --- |
   | Dossiers de spec nommés par horodatage | `extensions/git/git-config.yml` | `branch_numbering: timestamp`, pour que deux personnes qui écrivent des specs en même temps n'entrent jamais en collision : `specs/20261116-013307-course-reviews/`, et non `specs/001-course-reviews/` |
   | Conventional Commits pour chaque étape | `extensions/git/git-config.yml` | `commit_style: conventional` |
   | Les hooks de l'extension git s'exécutent sans demander | `extensions.yml` | `auto_execute_hooks: true` : une branche avant `/speckit-specify`, un commit après chaque étape |
   | Les templates et la constitution | `templates/`, `memory/` | Portent déjà les modifications de [l'étape 3](../constitution-and-templates/) |

3. **Ajoutez les commandes pour votre agent de code.** S'il lit les skills de Claude Code, copiez
   `.claude/skills/speckit-*` depuis ce dépôt. Sinon, laissez Speckit les écrire pour votre
   agent dans un dossier temporaire, et ne copiez que les fichiers de commandes :

   ```bash
   mkdir /tmp/speckit && cd /tmp/speckit
   specify init --here --integration <your-agent> --script sh --extension git
   ```

   Lancez `specify init --help` pour la liste des intégrations. Copiez le dossier qu'il crée pour les commandes de votre
   agent, pas son `.specify/`, qui annulerait l'étape 2.

4. **Committez `.specify/`** ainsi que les fichiers de commandes ou de skills.

</Steps>

## Vérifier que ça marche

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, commandes, scripts
  - extensions.yml
  - init-options.json
  - memory/constitution.md celle de l'application de notes, réécrite pour la vôtre à l'étape suivante
  - scripts/bash/
  - templates/ templates de spec, de plan, de tâches, de checklist et de constitution
</FileTree>

Dans votre agent de code, les commandes `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`,
`speckit-analyze` et `speckit-constitution` sont listées.

<Aside type="tip">
Les PR de spec vont sur leur propre branche (`spec/<name>`), pas sur `openhands/...`. La branche de fonctionnalité
de l'extension git convient pour cela. Seules les branches de l'agent utilisent le préfixe `openhands/`.
</Aside>
