**Résultat :** un workspace pnpm avec Nx, Biome, les Conventional Commits imposés sur chaque
commit, et une vérification des secrets avant chaque commit.

La glue n'a pas besoin de Nx. Mais c'est `nx affected` qui garde les checks de PR assez rapides pour qu'un agent puisse
itérer, et chaque script de glue s'exécute comme une cible Nx. Si vous utilisez un autre outil de monorepo, gardez
l'idée : n'exécuter que ce que la PR affecte, et exposer chaque script comme une tâche nommée.

<Steps>

1. **Créez le workspace**, si vous n'en avez pas. Discava et ce dépôt ont tous deux été créés
   avec le Nx Plugin for AWS :

   ```bash
   pnpm create @aws/nx-workspace your-project --iac=cdk --no-interactive
   ```

   Un workspace Nx existant convient aussi. Épinglez pnpm dans le `package.json` racine avec `packageManager`,
   pour que la CI et l'agent utilisent la même version.

2. **Copiez ces fichiers** depuis ce dépôt aux mêmes chemins dans le vôtre :

   <FileTree>
   - commitlint.config.js Conventional Commits
   - lint-staged.config.js Biome sur les fichiers indexés
   - .husky/
     - commit-msg lance commitlint
     - pre-commit git-secrets, puis lint-staged, et échoue si Biome a modifié quoi que ce soit, pour que l'agent réindexe et committe à nouveau
     - prepare-commit-msg Commitizen, pour les personnes qui committent de façon interactive. Il se désactive pour `git commit -m`, ce qui est la façon dont les agents committent
   - .git-secrets/ le script git-secrets que lance le hook pre-commit
   - .gitallowed motifs que git-secrets laisse passer
   - .github/
     - actions/init-monorepo/ configuration CI partagée
     - actions/changed-paths/ « cette PR a-t-elle modifié l'un de ces chemins ? », pour sauter des jobs
     - actions/playwright-setup/ Chromium pour Playwright, mis en cache par version
     - dependabot.yml garde à jour les actions épinglées et les dépendances
   </FileTree>

   Laissez `.husky/pre-push` de côté jusqu'à [l'étape 8](../local-stack-and-e2e/) : il vérifie la carte des invariants.
   `init-monorepo` installe pnpm (avec trois essais, car un timeout du registre coûterait sinon à l'agent une
   tentative de correction), Node 24 et éventuellement uv, restaure les caches pnpm et Nx,
   installe les dépendances, et définit `NX_BASE`/`NX_HEAD` pour `nx affected`.

3. **Copiez les scripts racine et les dépendances de développement** depuis le `package.json` de ce dépôt : le
   bloc `scripts` (qu'appellent `AGENTS.md`, la CI et l'agent), et dans `devDependencies`,
   `@commitlint/config-conventional`, `commitlint`, `commitizen`, `husky` et `lint-staged`. Ensuite :

   ```bash
   pnpm install
   ```

   Son script `prepare` installe les hooks.

4. **Changez le scope du package** dans `.github/actions/playwright-setup/action.yml`
   (`@agentic-sdlc/e2e`) pour le nom de votre projet e2e.

</Steps>

## Vérifier que ça marche

```bash
git commit --allow-empty -m "not conventional"
```

```text
⧗   input: not conventional
✖   subject may not be empty [subject-empty]
✖   type may not be empty [type-empty]
```

Ensuite, `git commit --allow-empty -m "chore: check hooks"` réussit.

<Aside type="note">
Les titres d'issue qu'écrit la glue sont des en-têtes de Conventional Commit, et l'agent les réutilise pour
ses commits et ses pull requests. C'est pourquoi commitlint vient en premier.
</Aside>
