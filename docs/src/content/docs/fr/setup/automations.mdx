**Résultat :** OpenHands interroge votre fork toutes les cinq minutes. Il implémente les issues
portant le label `openhands`, révise les PR marquées en échec et relit les PR portant le label `openhands-review`.
Ce sont les agents Développeur et Relecteur.

Les deux automatisations viennent du **catalogue d'automatisations** d'Agent Canvas, sous **Automations**. Vous
remplissez un formulaire, et le catalogue empaquette un worker testé avec vos réglages. Vous n'écrivez aucun
code.

<Steps>

1. **Ajoutez « GitHub issue to PR »** depuis le catalogue, avec ces réglages :

   | Champ | Valeur |
   | --- | --- |
   | Repositories | `<you>/agentic-sdlc` |
   | Trigger label | `openhands` |
   | Branch prefix | `openhands/issue` |
   | Pull request mode | Ready for review |
   | GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
   | Agent profile | `developer` |
   | Check frequency | `*/5 * * * *` |
   | Timezone | le vôtre |

   Discava utilise la version 1.2.4 du template. Le prompt du worker demande à l'agent d'ajouter le
   label `openhands-review` après avoir ouvert une PR, pour que chaque nouvelle PR parvienne au Relecteur.

2. **Ajoutez « GitHub code review »** depuis le catalogue :

   | Champ | Valeur |
   | --- | --- |
   | Repositories | `<you>/agentic-sdlc` |
   | Trigger label | `openhands-review` |
   | Requested reviewer | `all-hands-bot` (inutilisé : c'est le label qui fait le travail) |
   | New reviews per scan | `2` |
   | Review tone | Concise |
   | Maintainers | vide, ou deux logins ou plus (voir ci-dessous) |
   | GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
   | Agent profile | `reviewer` |
   | Check frequency | `*/5 * * * *` |

   Discava utilise la version 1.11.2 du template, avec le patch de l'étape suivante. **New reviews per scan**
   limite le nombre de conversations de review qu'un passage démarre, pour qu'un arriéré ne lance pas
   dix agents d'un coup.

   **Maintainers** est facultatif. S'il est renseigné, une PR approuvée est confiée à l'un d'eux comme
   reviewer demandé, choisi selon qui a déjà modifié ces fichiers. Cela ne se produit que si l'issue de la PR
   porte `priority:medium` ou `priority:high`. Discava le laisse vide.

3. **Patchez l'automatisation de code review pour votre app.** Telle qu'elle est livrée, jusqu'à au
   moins la version 1.11.3 du template, elle demande à GitHub par `GET /user` sous quel compte elle agit,
   et GitHub le refuse au token d'une app (`403 Resource not accessible by integration`). Chaque passage
   de review échoue alors. En attendant qu'OpenHands le corrige, laissez un agent faire la correction
   qu'a faite Discava. Démarrez une conversation dans Agent Canvas et collez :

   ```text
   The "GitHub code review" automation fails with HTTP 403: its GitHub token is a GitHub App
   installation token, and GitHub refuses those on GET /user. Fix the automation's worker bundle:
   wherever the code reads the token's login from GET /user (the login lookup in worker.py and
   the token check in main.py), fall back on a 403 to the GraphQL query { viewer { login } }.
   Upload the patched bundle through the automation API and point this automation at it, changing
   nothing else. Then run the automation once and show me that the run completed.
   ```

   Recommencez si vous mettez plus tard l'automatisation à jour depuis le catalogue.

4. **Lancez chaque automatisation une fois à la main**, avec **Run now** sur sa page dans Agent Canvas,
   et lisez le journal d'exécution.

</Steps>

## Vérifier que ça marche

Un premier passage sans rien à faire journalise un balayage du dépôt et se termine par `COMPLETED`. Essayez ensuite
un petit changement de bout en bout :

1. Dans votre fork, créez une issue intitulée « Add a line to README.md saying hello », et ajoutez le
   label `openhands`.
2. En un passage, une conversation pour l'issue apparaît dans Agent Canvas.
3. Quand l'agent a fini, une PR apparaît sur `openhands/issue-<n>`, intitulée `[#<n>] <issue
   title>`, avec `openhands-review` ajouté.
4. Une fois ses checks terminés, l'agent Relecteur publie une review qui commence par
   « _This review was posted by an AI agent (OpenHands)._ » et se termine par `✅ APPROVED` ou
   `🔄 CHANGES REQUESTED`.

Fermez ensuite la PR et l'issue, et supprimez la branche.

Ce que fait chaque automatisation à chaque passage est décrit dans [Le runtime de l'agent](../../concepts/the-agent-runtime/).

<Aside type="tip" title="Le troisième rôle : Testeur">
Discava fait tourner une troisième automatisation, le Testeur, qui teste chaque changement mergé sur son
stage de développement déployé. Il a besoin d'un déploiement à tester, donc il ne fait pas partie de cette mise en place. Quand votre dépôt
se déploie de lui-même, voir [Vérification après merge](../../discava/post-merge-verify/) et
[Les prompts des agents](../../discava/agent-prompts/).
</Aside>

<Aside type="note">
Pour donner à l'agent un nouvel essai sur une issue depuis zéro, retirez puis remettez le label `openhands`.
Pour le renvoyer sur une PR ouverte avec votre propre commentaire, publiez le statut que publient les workflows de glue :
`gh api repos/<you>/agentic-sdlc/statuses/<sha> -f state=failure -f context=software-factory/review -f description="See my comment"`.
</Aside>
