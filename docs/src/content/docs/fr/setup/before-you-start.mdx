Un [fork de ce dépôt](../../guides/fork-this-repo/) contient tout ce que la configuration de Discava garde dans
le dépôt. Ces étapes ajoutent la partie qui vit en dehors : vos réglages GitHub, une GitHub App
sous laquelle agissent les agents, et une installation d'OpenHands pointée vers votre fork. Ensuite, vous écrivez
une spec pour l'application de notes et la regardez passer de la PR de spec aux PR d'agents mergées.

**Durée :** environ une heure, passée surtout à attendre la première exécution de l'agent.

## Ce dont vous avez besoin

Sous macOS ou Linux (sous Windows, utilisez WSL) :

| Besoin | Pourquoi |
| --- | --- |
| Un compte GitHub | Pour forker, écrire les specs et relire |
| GitHub CLI (`gh`), connecté | Le script de configuration et les agents l'utilisent |
| Node.js 24 et pnpm | Pour faire tourner le dépôt et Agent Canvas |
| `uv` | Agent Canvas démarre son backend avec `uvx` |
| Un agent de code, installé et connecté | Il écrit les specs avec Speckit, et fait le travail des agents dans OpenHands. Discava utilise Claude Code |
| Docker (facultatif) | Seulement pour lancer l'application de notes et ses tests e2e sur votre machine. La CI les lance pour les agents |

<Aside type="note">
Agent Canvas tourne sur votre propre machine et interroge GitHub, il n'a donc besoin ni d'adresse publique ni de
webhook. Les agents ne travaillent que tant qu'il tourne.
</Aside>

## Les étapes

| # | Étape | Ce que vous faites | Résultat |
| --- | --- | --- | --- |
| 1 | [Forker le dépôt](../fork/) | Trois commandes | Votre propre copie, clonée |
| 2 | [Configurer le dépôt](../github-repository/) | Créer une GitHub App depuis un formulaire pré-rempli, lancer un seul script | La GitHub App des agents sur votre fork, les labels, une branche `main` protégée, les commentaires limités aux collaborateurs |
| 3 | [Installer OpenHands](../openhands/) | Deux commandes, deux profils dans l'interface web | Agent Canvas en marche sous votre app, avec un profil `developer` et un profil `reviewer` |
| 4 | [Créer les deux automatisations](../automations/) | Deux formulaires dans l'interface web, un prompt à coller | Les agents Développeur et Relecteur qui implémentent et relisent dans votre fork |
| 5 | [Lancer votre première fonctionnalité](../first-feature/) | Écrire une spec, relire des pull requests | Une spec pour l'application de notes, menée jusqu'au code mergé par les agents |

Vous préférez mettre la configuration en place dans un dépôt existant ? Voir
[L'adopter dans votre propre dépôt](../../adopt/overview/).
