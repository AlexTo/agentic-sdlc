Un [fork de ce dépôt](../../guides/fork-this-repo/) contient tout ce que la configuration de Discava garde dans
le dépôt. Ces étapes ajoutent la partie qui vit en dehors : vos réglages GitHub, et une
installation d'OpenHands pointée vers votre fork. Ensuite, vous écrivez une spec pour l'application de notes et la regardez
passer de la PR de spec aux PR d'agents mergées.

**Durée :** environ une heure, passée surtout à attendre la première exécution de l'agent.

## Ce dont vous avez besoin

| Besoin | Pourquoi |
| --- | --- |
| Un compte GitHub | Pour forker, écrire les specs et relire |
| Un second compte GitHub pour les agents | Il possède le token qu'utilisent les agents, donc leurs PR et leurs commentaires sont les leurs et vous pouvez les approuver. Celui de Discava est `discava-bot` |
| Node.js 24 et pnpm | Pour faire tourner le dépôt et Agent Canvas |
| `uv` | Agent Canvas démarre son backend avec `uvx` |
| Docker | Seulement pour lancer l'application de notes et ses tests e2e en local. La CI les lance pour l'agent |
| GitHub CLI (`gh`), connecté | La plupart des étapes l'utilisent |
| Un agent de code, installé et connecté | Écrit les specs avec Speckit, et tourne dans OpenHands. Discava utilise Claude Code |

<Aside type="note">
Agent Canvas tourne sur votre propre machine et interroge GitHub, il n'a donc besoin ni d'adresse publique ni de
webhook. Les agents ne travaillent que tant qu'il tourne.
</Aside>

## Les étapes

| # | Étape | Résultat |
| --- | --- | --- |
| 1 | [Forker le dépôt](../fork/) | Votre propre copie, avec Actions et Issues activés |
| 2 | [Configurer le dépôt](../github-repository/) | Un seul script : Issues et Actions activés, les labels, une branche `main` protégée, les commentaires limités aux collaborateurs, et le compte des agents comme collaborateur |
| 3 | [Installer OpenHands](../openhands/) | Agent Canvas en marche, un token GitHub, deux profils d'agent |
| 4 | [Créer les deux automatisations](../automations/) | Les agents Développeur et Relecteur qui implémentent et relisent dans votre fork |
| 5 | [Lancer votre première fonctionnalité](../first-feature/) | Une spec pour l'application de notes, menée jusqu'au code mergé par les agents |

Vous préférez mettre la configuration en place dans un dépôt existant ? Voir
[L'adopter dans votre propre dépôt](../../adopt/overview/).
