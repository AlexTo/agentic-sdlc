import { Steps, Aside } from '@astrojs/starlight/components';

**Résultat :** OpenHands Agent Canvas qui tourne sur votre machine sous votre GitHub App, le token de
l'app tenu à jour dans un secret, et deux profils d'agent : `developer` pour l'agent Développeur et
`reviewer` pour l'agent Relecteur.

<Steps>

1. **Trouvez l'identité de commit de l'app.** GitHub n'attribue un commit à l'app que si l'email de son
   auteur est l'adresse noreply de l'app, qui contient l'ID de son utilisateur bot :

   ```bash
   gh api '/users/<app-name>[bot]' --jq .id
   ```

   L'adresse est `<id>+<app-name>[bot]@users.noreply.github.com`.

2. **Installez et démarrez Agent Canvas** avec cette identité. Discava utilise la version 1.45.0 :

   ```bash
   npm install -g @openhands/agent-canvas
   export GIT_AUTHOR_NAME='<app-name>[bot]' GIT_COMMITTER_NAME='<app-name>[bot]'
   export GIT_AUTHOR_EMAIL='<id>+<app-name>[bot]@users.noreply.github.com'
   export GIT_COMMITTER_EMAIL="$GIT_AUTHOR_EMAIL"
   agent-canvas
   ```

   Ouvrez [http://127.0.0.1:8000](http://127.0.0.1:8000). Laissez-le tourner : les automatisations n'interrogent GitHub
   que tant qu'Agent Canvas est en marche.

   Les variables l'emportent sur le nom `OpenHands` que les templates d'automatisation écrivent dans
   chaque checkout. Le formulaire **Git Settings** d'Agent Canvas lui-même ne peut pas contenir l'adresse :
   il refuse un email qui contient des crochets.

3. **Gardez le token de l'app à jour.** Une app travaille avec des installation tokens, qui expirent au
   bout d'une heure. `scripts/agent-app-token.sh` en crée un à partir de la clé privée de l'app et le
   stocke dans Agent Canvas comme secret `GITHUB_PERSONAL_ACCESS_TOKEN`, que lisent les automatisations
   et leurs conversations. Malgré le nom, n'importe quel token y fonctionne. Donnez-lui les ID et la clé
   de l'[étape 2](../github-repository/) :

   ```bash
   mkdir -p ~/.config/agent-app
   cat > ~/.config/agent-app/env <<'EOF'
   AGENT_APP_ID=<app-id>
   AGENT_APP_INSTALLATION_ID=<installation-id>
   AGENT_APP_KEY=$HOME/.ssh/<app-name>.pem
   EOF
   ```

   Puis, dans un second terminal depuis votre clone, lancez-le toutes les 45 minutes tant qu'Agent Canvas
   tourne :

   ```bash
   while true; do ./scripts/agent-app-token.sh; sleep 2700; done
   ```

   Chaque exécution affiche quand le nouveau token expire et que le secret a été mis à jour. La clé reste
   hors d'Agent Canvas, donc un agent ne détient jamais qu'un token qui disparaît dans l'heure. Sous
   Linux, un timer utilisateur systemd peut le lancer à la place : voir
   [La configuration OpenHands de Discava](../../discava/openhands-setup/#la-github-app).

4. **Choisissez l'agent.** Discava fait tourner Claude Code via ACP (l'Agent Client Protocol), donc
   l'agent de code que vous utilisez déjà fait le travail. Dans les réglages de l'agent, définissez :

   | Réglage | Valeur |
   | --- | --- |
   | Agent | ACP, serveur `claude-code` |
   | Confirmation mode | désactivé (personne n'est là pour confirmer) |
   | Max iterations | 500 (de quoi faire une phase entière) |

   L'agent de code doit être installé et connecté sur cette machine, sous le même utilisateur.

5. **Créez deux profils d'agent**, un par rôle d'agent :

   | Profil | Rôle | Agent | Modèle |
   | --- | --- | --- | --- |
   | `developer` | Développeur | ACP, `claude-code` | `sonnet` |
   | `reviewer` | Relecteur | ACP, `claude-code` | `opus` |

   N'importe quel agent et modèle conviennent. Gardez le Relecteur au moins aussi fort que le Développeur : c'est le
   dernier contrôle avant vous.

   Discava a un troisième profil, `tester`, pour l'agent Testeur. Il teste les changements mergés sur un
   stage déployé, ce que l'application de notes n'a pas, donc vous n'en avez pas besoin ici.

</Steps>

## Vérifier que ça marche

Dans Agent Canvas, démarrez une conversation avec le profil `developer` et donnez-lui le secret
`GITHUB_PERSONAL_ACCESS_TOKEN`. Demandez-lui :

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

Il indique `<app-name>[bot]`, et une liste d'issues vide. (`gh auth status` et `GET /user` refusent le
token d'une app, ils ne servent donc pas de test.)

<Aside type="caution" title="Tenez votre propre login GitHub à l'écart des agents">
N'ajoutez pas de token sous **Integrations** dans Agent Canvas, et supprimez tout serveur GitHub sous
**MCP Servers** : l'un comme l'autre détient un token fixe, généralement le vôtre, et un agent qui
l'utilise agit en votre nom au lieu de celui de l'app. Discava en a trouvé un qui pointait vers
`api.githubcopilot.com` avec le token de son propriétaire.
</Aside>

<Aside type="caution">
L'agent exécute des commandes sur cette machine sous votre utilisateur. Ne gardez pas d'identifiants cloud dans son
environnement, et utilisez une machine ou une VM séparée dès que vous dépassez le stade de l'essai.
</Aside>
