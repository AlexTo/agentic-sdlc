**Résultat :** OpenHands Agent Canvas qui tourne sur votre machine sous votre GitHub App, et deux
profils d'agent : `developer` pour l'agent Développeur et `reviewer` pour l'agent Relecteur.

<Steps>

1. **Installez Agent Canvas.** Discava utilise la version 1.45.0 :

   ```bash
   npm install -g @openhands/agent-canvas
   ```

2. **Démarrez-le sous votre app**, depuis votre clone :

   ```bash
   pnpm agent-canvas
   ```

   La première fois, il demande l'**App ID** et le chemin du **fichier `.pem`** de
   l'[étape 2](../github-repository/), et garde les deux dans `~/.config/agent-app/`, lisibles par
   vous seul. Ensuite, à chaque fois, il :

   - démarre Agent Canvas avec l'app comme auteur des commits des agents, donc GitHub les affiche
     sous l'app ;
   - crée un des tokens de l'app, qui durent une heure, et le stocke dans Agent Canvas comme
     secret `GITHUB_PERSONAL_ACCESS_TOKEN`, celui que lisent les automatisations. Malgré le nom,
     n'importe quel token GitHub y fonctionne ;
   - remplace le token toutes les 45 minutes tant qu'il tourne.

   Attendez la ligne `Token stored in the GITHUB_PERSONAL_ACCESS_TOKEN secret`, puis ouvrez
   [http://127.0.0.1:8000](http://127.0.0.1:8000). Si Agent Canvas demande quel agent utiliser,
   choisissez Claude Code : il trouve la session que vous avez déjà, laissez donc vides les champs
   de clé d'API.

   Gardez le terminal ouvert, et démarrez toujours Agent Canvas de cette façon : les automatisations
   n'interrogent GitHub que tant qu'il est en marche, et le token ne reste à jour que tant que cette
   commande tourne.

3. **Créez deux profils d'agent**, un par rôle d'agent. Dans Agent Canvas, ouvrez **Settings → Agent**
   et cliquez sur **Add agent profile**, deux fois :

   | Nom | Type d'agent | Agent | Modèle |
   | --- | --- | --- | --- |
   | `developer` | ACP (external subprocess) | `claude-code` | `sonnet` |
   | `reviewer` | ACP (external subprocess) | `claude-code` | `opus` |

   ACP est l'Agent Client Protocol : l'agent de code que vous utilisez déjà fait le travail,
   connecté sous votre compte sur cette machine. N'importe quel agent et modèle conviennent. Gardez
   le Relecteur au moins aussi fort que le Développeur : c'est le dernier contrôle avant vous.

   Laissez tout le reste tel quel. Agent Canvas tourne déjà sans surveillance (pas de demande de
   confirmation), avec de quoi faire une phase entière en une conversation (500 itérations).

</Steps>

## Vérifier que ça marche

Dans Agent Canvas, **Settings → Secrets** liste `GITHUB_PERSONAL_ACCESS_TOKEN`. Démarrez une
conversation avec le profil `developer` et demandez-lui :

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

Il indique `<app-name>[bot]`, et une liste d'issues vide.

<Aside type="caution" title="Tenez votre propre login GitHub à l'écart des agents">
N'ajoutez pas de token GitHub sous **Integrations** dans Agent Canvas, et supprimez tout serveur
GitHub listé sous **MCP Servers** : l'un comme l'autre détient un token fixe, généralement le vôtre,
et un agent qui l'utilise agit en votre nom au lieu de celui de l'app.
</Aside>

<Aside type="caution">
L'agent exécute des commandes sur cette machine sous votre utilisateur. Ne gardez pas d'identifiants cloud dans son
environnement, et utilisez une machine ou une VM séparée dès que vous dépassez le stade de l'essai.
</Aside>

<Aside type="tip" title="Faire tourner Agent Canvas comme un service">
Une fois qu'Agent Canvas tourne comme un service plutôt que dans un terminal, faites lancer
`pnpm agent-canvas --once` par un timer toutes les 45 minutes : il crée un token, le stocke et
s'arrête. Discava le fait sous Linux avec systemd : voir
[La configuration OpenHands de Discava](../../discava/openhands-setup/#la-github-app).
</Aside>

Discava a un troisième profil, `tester`, pour l'agent Testeur. Il teste les changements mergés sur un
stage déployé, ce que l'application de notes n'a pas, donc vous n'en avez pas besoin ici.
