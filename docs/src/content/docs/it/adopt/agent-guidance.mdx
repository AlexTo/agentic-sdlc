**Alla fine avrai:** un `AGENTS.md` che ogni agente legge per primo, e i template delle issue in
`.github/ISSUE_TEMPLATE/`, la fonte delle istruzioni fisse di ogni issue di implementazione.

<Steps>

1. **Copia `AGENTS.md`** da questo repository, e riscrivi ogni sezione per il tuo progetto. È breve
   di proposito: ciò che serve a un agente a ogni esecuzione, e nient'altro.

   | Sezione | Scrivi |
   | --- | --- |
   | What this is | Un paragrafo: il prodotto, lo stack, lo strumento per il monorepo |
   | Commands | Installare; build, lint, test di tutto; i test di un progetto, una volta (non in watch mode); un file di test; `nx affected`; e2e; sviluppo locale |
   | Architecture | Un punto per package: cos'è, cosa può importare, dove va il nuovo codice di ogni tipo |
   | Conventions | Conventional Commits, il formatter per nome, dove vanno gli helper, e ogni regola che un reviewer ha dovuto ripetere due volte |

   <Aside type="tip">
   La sezione dei comandi è la più importante. Un agente che non trova "esegui un file di test, una volta" eseguirà
   l'intera suite in watch mode e resterà bloccato. Esegui una volta ogni comando che elenchi, per
   essere sicuro che funzioni.
   </Aside>

   Quando la sezione sull'architettura supera una riga per pacchetto, sposta il dettaglio di ogni pacchetto in un
   `AGENTS.md` annidato nella sua cartella, e lascia nella radice una riga che rimanda lì. Un agente carica un
   file annidato solo quando lavora in quella cartella, così un'esecuzione legge solo il dettaglio che le serve.
   `packages/tooling/agent/AGENTS.md` di questo repository è uno di questi; copialo insieme al collante
   al [passaggio 5](../glue-scripts/).

   Se il tuo agente legge un file con un nome diverso, come `CLAUDE.md`, fai in modo che quel file
   rimandi ad `AGENTS.md`. Il `CLAUDE.md` di questo repository inizia con `@AGENTS.md`, che Claude Code
   legge come "includi qui quel file".

2. **Copia `.github/ISSUE_TEMPLATE/`** da questo repository: `implement-phase.md` per il
   Developer, e `test-deployed-pr.md` per il Tester, se lo aggiungi al [passaggio 9](../deploy/).

   Lo script Agent Issues scrive da sé le sezioni sulla spec e sull'ambito della issue, e legge tutto
   ciò che sta sotto `## Instructions for the agent` in `implement-phase.md` al momento
   dell'esecuzione. Lascia quell'intestazione esattamente com'è, perché lo script la cerca e fallisce
   senza di essa. Lascia anche `#<parent>` così com'è: lo script lo sostituisce con la issue padre
   della spec, e toglie il punto quando la spec non ne ha una.

3. **Adatta le istruzioni al tuo stack**: i comandi, il percorso dell'helper per gli screenshot, e
   cosa significa per te "credenziali cloud".

</Steps>

## Verifica che funzioni

```bash
grep -c '^## Instructions for the agent$' .github/ISSUE_TEMPLATE/implement-phase.md
```

```text
1
```
