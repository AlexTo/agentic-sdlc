**Alla fine avrai:** un workflow **PR Checks** il cui fallimento alimenta il loop della CI, un check
**UI Screenshots**, e la **CI** su `main`.

<Steps>

1. **Copia quattro workflow** da `.github/workflows/` di questo repository:

   | File | Cosa fa |
   | --- | --- |
   | `pr-checks.yml` | Lint, test e build di ciò che la PR tocca; `Tasks format`; `Invariant coverage`; e2e divisi in shard raccolti in un unico check `E2E tests`; il commento `E2E screenshots` |
   | `ui-screenshots.yml` | La regola degli screenshot, come workflow a sé, così aggiungere o togliere la label `no-ui-screenshots` riesegue solo questo check. Discava invece la esegue come job di PR Checks. Vanno bene entrambi |
   | `ci.yml` | Gli stessi check a ogni push su `main`, Trivy, la cache di Playwright, e il deploy di questo sito di documentazione |
   | `cache-cleanup.yml` | Elimina le cache di una PR quando viene chiusa |

   Lascia il `name: PR Checks` di `pr-checks.yml` esattamente com'è: Agent CI Status ascolta un
   workflow con quel nome.

2. **Puntali sui tuoi progetti.** Cerca `@agentic-sdlc/` nei file copiati e cambia lo scope. Poi, in
   `pr-checks.yml`:

   | Job | Cosa cambiare |
   | --- | --- |
   | `invariant-coverage` | I `paths` del codice che potrebbe scrivere nella tua tabella, gli stessi di `WRITER_PACKAGES` al passaggio 5. Oppure elimina il job se per ora non controlli gli invarianti |
   | `e2e` | Il numero di shard in `matrix.shard`, in base alla tua suite. Uno shard costa circa due minuti prima del suo primo test, quindi smetti di aggiungerne quando i test di ciascuno durano più o meno così |
   | `e2e-screenshots` | Niente, una volta completato il [passaggio 8](../local-stack-and-e2e/) |

   In `ci.yml`, elimina il job `deploy_docs` e il suo permesso `pages: write`, a meno che tu non
   pubblichi un sito di documentazione da `docs/`.

3. **Mantieni ciò che rende veloce l'agente.** Il passaggio `Check for mutations` in `ci.yml` (`git diff
   --exit-code` dopo la build) intercetta i file generati che l'agente ha dimenticato di committare.
   Il job `playwright-cache` salva Chromium da `main`, perché le esecuzioni delle PR possono solo
   ripristinare cache salvate lì. Il job `build` salva la cache dei task di Nx da `main`, così la prima
   esecuzione di una PR riproduce ciò che `main` ha già compilato, e l'agente aspetta meno a ogni giro
   di correzione. Ogni ramo di `checks` in PR Checks tiene la propria cache allo stesso modo, tranne
   `lint`, che si limita a ripristinarla. `init-monorepo` limita la cache a 1 GB, e Cache Cleanup libera
   la parte di una PR chiusa nei 10 GB del repository. Vedi
   [Mantenerlo veloce](../../discava/pr-checks/#mantenerli-veloci) per quanto ha fatto risparmiare a Discava.

</Steps>

Ogni action è fissata a uno SHA di commit, e il `dependabot.yml` che hai copiato al passaggio 1
mantiene aggiornati i riferimenti.

## Verifica che funzioni

Apri una PR usa e getta che rompe una riga di `tasks.md`, per esempio indentando un task. Il
check **Tasks format** fallisce con un'annotazione su quella riga:

```text
A task must be written "- [ ] T<3 digits> <description>", starting in the first column
```

Aprine un'altra che modifica un file della UI senza toccare uno scenario. **UI Screenshots** fallisce:

```text
This pull request changes UI source (…) but no e2e scenario gained a `screenshot(page, 'name')` call.
```

<Aside type="note">
`codecov/codecov-action` nei file copiati ha bisogno di un secret `CODECOV_TOKEN`. Togli il passaggio se
non usi Codecov.
</Aside>
