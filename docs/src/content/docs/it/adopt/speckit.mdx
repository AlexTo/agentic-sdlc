**Alla fine avrai:** `.specify/` nel repository, i comandi `speckit-*` disponibili per il tuo
coding agent, e cartelle delle spec con nomi basati su timestamp.

<Steps>

1. **Installa la CLI**, fissata alla versione che usa Discava:

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. **Copia `.specify/`** da questo repository. È già configurato come serve al workflow:

   | Impostazione | Dove | Valore |
   | --- | --- | --- |
   | Cartelle delle spec con nomi basati su timestamp | `extensions/git/git-config.yml` | `branch_numbering: timestamp`, così due persone che scrivono spec nello stesso momento non entrano mai in conflitto: `specs/20261116-013307-course-reviews/`, non `specs/001-course-reviews/` |
   | Conventional commit per ogni passaggio | `extensions/git/git-config.yml` | `commit_style: conventional` |
   | Gli hook dell'estensione git girano senza chiedere | `extensions.yml` | `auto_execute_hooks: true`: un branch prima di `/speckit-specify`, un commit dopo ogni passaggio |
   | I template e la costituzione | `templates/`, `memory/` | Contengono già le modifiche del [passaggio 3](../constitution-and-templates/) |

3. **Aggiungi i comandi per il tuo coding agent.** Se legge le skill di Claude Code, copia
   `.claude/skills/speckit-*` da questo repository. Altrimenti, lascia che Speckit le scriva per il tuo
   agente in una cartella temporanea, e copia solo i file dei comandi:

   ```bash
   mkdir /tmp/speckit && cd /tmp/speckit
   specify init --here --integration <your-agent> --script sh --extension git
   ```

   Esegui `specify init --help` per l'elenco delle integrazioni. Copia la cartella che crea per i
   comandi del tuo agente, non il suo `.specify/`, che annullerebbe il passaggio 2.

4. **Fai il commit di `.specify/`** e dei file di comandi o skill.

</Steps>

## Verifica che funzioni

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, comandi, script
  - extensions.yml
  - init-options.json
  - memory/constitution.md quella dell'app di note, da riscrivere per la tua nel prossimo passaggio
  - scripts/bash/
  - templates/ template di spec, plan, tasks, checklist e costituzione
</FileTree>

Nel tuo coding agent compaiono i comandi `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`,
`speckit-analyze` e `speckit-constitution`.

<Aside type="tip">
Le PR delle spec vanno su un branch a sé (`spec/<name>`), non `openhands/...`. Il branch della feature
dell'estensione git va bene per questo. Solo i branch dell'agente usano il prefisso `openhands/`.
</Aside>

Avanti: [3. Costituzione e template](../constitution-and-templates/).
