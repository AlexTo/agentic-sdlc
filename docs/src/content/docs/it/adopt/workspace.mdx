**Alla fine avrai:** un workspace pnpm con Nx, Biome, Conventional Commits imposti su ogni
commit, e un controllo dei secret prima di ogni commit.

Il collante non ha bisogno di Nx. Ma `nx affected` è ciò che rende i check delle PR abbastanza veloci perché un agente possa
iterare, e ogni script del collante gira come target Nx. Se usi un altro strumento per monorepo, mantieni
l'idea: esegui solo ciò che la PR tocca, ed esponi ogni script come task con un nome.

<Steps>

1. **Crea il workspace**, se non ne hai uno. Discava e questo repository sono stati creati entrambi
   con il Nx Plugin for AWS:

   ```bash
   pnpm create @aws/nx-workspace your-project --iac=cdk --no-interactive
   ```

   Va bene anche un workspace Nx esistente. Fissa pnpm nel `package.json` della radice con
   `packageManager`, così la CI e l'agente usano la stessa versione.

2. **Copia questi file** da questo repository negli stessi percorsi del tuo:

   <FileTree>
   - commitlint.config.js Conventional Commits
   - lint-staged.config.js Biome sui file in stage
   - .husky/
     - commit-msg esegue commitlint
     - pre-commit git-secrets, poi lint-staged, e fallisce se Biome ha cambiato qualcosa, così l'agente rimette in stage e committa di nuovo
     - prepare-commit-msg Commitizen, per chi fa commit in modo interattivo. Si salta da solo con `git commit -m`, che è il modo in cui committano gli agenti
   - .git-secrets/ lo script git-secrets che esegue l'hook pre-commit
   - .gitallowed i pattern che git-secrets lascia passare
   - .github/
     - actions/init-monorepo/ setup condiviso della CI
     - actions/changed-paths/ "questa PR ha cambiato uno di questi percorsi?", per saltare dei job
     - actions/playwright-setup/ Chromium per Playwright, in cache per versione
     - dependabot.yml mantiene aggiornate le action fissate e le dipendenze
   </FileTree>

   Lascia `.husky/pre-push` fino al [passaggio 8](../local-stack-and-e2e/): controlla la mappa degli
   invarianti. `init-monorepo` installa pnpm (con tre tentativi, perché altrimenti un timeout del
   registry costerebbe all'agente un tentativo di correzione), Node 24 e facoltativamente uv,
   ripristina le cache di pnpm e Nx, installa le dipendenze, e imposta `NX_BASE`/`NX_HEAD` per
   `nx affected`.

3. **Copia gli script della radice e le dipendenze di sviluppo** dal `package.json` di questo
   repository: il blocco `scripts` (che chiamano `AGENTS.md`, la CI e l'agente) e, da
   `devDependencies`, `@commitlint/config-conventional`, `commitlint`, `commitizen`, `husky` e
   `lint-staged`. Poi:

   ```bash
   pnpm install
   ```

   Il suo script `prepare` installa gli hook.

4. **Cambia lo scope del package** in `.github/actions/playwright-setup/action.yml`
   (`@agentic-sdlc/e2e`) con il nome del tuo progetto e2e.

</Steps>

## Verifica che funzioni

```bash
git commit --allow-empty -m "not conventional"
```

```text
⧗   input: not conventional
✖   subject may not be empty [subject-empty]
✖   type may not be empty [type-empty]
```

Poi `git commit --allow-empty -m "chore: check hooks"` riesce.

<Aside type="note">
I titoli delle issue che scrive il collante sono intestazioni Conventional Commit, e l'agente li
riusa per i suoi commit e le sue pull request. Per questo commitlint viene per primo.
</Aside>
