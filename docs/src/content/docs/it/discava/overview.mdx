[Discava](https://github.com/AlexTo/discava) è un learning management system serverless su AWS: tre
portali React, tre API tRPC su Lambda, una singola tabella DynamoDB, una pipeline per i media e la
ricerca, con deploy tramite CDK da un monorepo Nx. È abbastanza grande che nessuno riesce a tenerlo
tutto a mente, ed è proprio lì che il workflow ripaga.

Questa sezione descrive cosa usa Discava, a novembre 2026, con i file dietro ogni pezzo.

## Gli strumenti e le versioni

| Strumento | Versione | Ruolo |
| --- | --- | --- |
| Speckit (`specify-cli`) | 1.3.2 | Generazione di spec, piano e task, con la sua estensione `git` |
| OpenHands Agent Canvas | 1.41.0 | Runtime dell'agente e le due automazioni, come servizio utente su una macchina Linux |
| Automazione `github-issue-to-pr` | 1.2.4 | Implementa le issue con label, rivede le PR fallite |
| Automazione `github-pr-reviewer` | 1.11.2 | Revisiona le PR quando i check finiscono |
| Agente per implementare | Claude Code tramite ACP, Sonnet | Agent profile `default` |
| Agente per revisionare | Claude Code tramite ACP, Opus | Agent profile `reviewer` |
| Nx + pnpm | Nx 23 | Monorepo, `nx affected` nella CI |
| Playwright | | Test E2E sullo stack locale, sei shard nella CI |
| Trivy, git-secrets, commitlint | | Scansione di sicurezza, controllo dei secret in pre-commit, formato dei messaggi di commit |

## Dalla lacuna al file

| Lacuna | La risposta di Discava | File |
| --- | --- | --- |
| Dalla spec alla issue | Il workflow Agent Issues e i suoi script | `.github/workflows/agent-issues.yml`, `packages/common/scripts/src/agent-issues/` |
| Dal fallimento della CI all'agente | Agent CI Status | `.github/workflows/agent-ci.yml`, `src/agent-ci/` |
| Dalla review all'agente | Agent Review Status | `.github/workflows/agent-review.yml`, `src/agent-review/` |
| Loop infiniti | Limiti di cinque tentativi con le label | `MAX_CI_FIX_ATTEMPTS` e `MAX_REVIEW_FIX_ATTEMPTS` in `plan.ts` |
| `tasks.md` malformato | Il job Tasks format | `pr-checks.yml` `tasks-format`, `src/agent-issues/validate.ts` |
| Modifiche alla UI non viste | Il job UI Screenshots, il commento E2E screenshots | `pr-checks.yml`, `src/ui-screenshots/`, `packages/e2e/src/helpers/screenshots.ts` |
| Il merge non porta avanti il lavoro | Agent Issues sui branch `openhands/` mergiati | `src/agent-issues/gate.ts` |
| Niente cloud per l'agente | Sostituti locali per ogni servizio AWS | `pnpm dev`, `packages/common/scripts/src/{dynamodb,s3mock,elasticmq,opensearch,local-oidc}` |
| Il merge non rilascia | CI su `main`, poi Deploy | `.github/workflows/ci.yml`, `deploy.yml`, `scripts/setup-stage.sh` |
| Secret e dipendenze vulnerabili | Trivy nella CI e prima del deploy, git-secrets al commit | `ci.yml` `trivy`, `deploy.yml`, `.husky/pre-commit`, `.trivyignore` |

E il testo che ogni agente legge:

| Istruzioni | File |
| --- | --- |
| Regole del progetto, verificate da ogni piano | `.specify/memory/constitution.md` (versione 1.2.1) |
| Comandi, architettura, convenzioni | `AGENTS.md` |
| Processo delle PR, stack locale, test | `CONTRIBUTING.md` |
| Istruzioni su ogni issue di implementazione | `.github/ISSUE_TEMPLATE/implement-phase.md` |
| Template di Speckit, personalizzati per l'automazione | `.specify/templates/tasks-template.md`, `spec-template.md` |

## I numeri

Dal 14 novembre, quando il workflow è entrato in funzione, al 18 novembre 2026:

- 12 spec di funzionalità scritte con Speckit, in `specs/`.
- 2.344 passaggi delle automazioni, uno ogni cinque minuti: 1.304 polling issue-to-PR e 1.040
  polling di review. 149 di questi hanno trovato lavoro e avviato un agente.
- 67 PR degli agenti mergiate. 42 non hanno avuto bisogno di correzioni automatiche, 17 di un giro,
  una ha esaurito un loop.
