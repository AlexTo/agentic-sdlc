[Discava](https://github.com/AlexTo/discava) è un learning management system serverless su AWS: tre
portali React, tre API tRPC su Lambda, una singola tabella DynamoDB, una pipeline per i media e la
ricerca, con deploy tramite CDK da un monorepo Nx. È abbastanza grande che nessuno riesce a tenerlo
tutto a mente, ed è proprio lì che il workflow ripaga.

Questa sezione descrive cosa usa Discava, a novembre 2026, con i file dietro ogni pezzo.

## Gli strumenti e le versioni

| Strumento | Versione | Ruolo |
| --- | --- | --- |
| Speckit (`specify-cli`) | 1.3.2 | Generazione di spec, piano e task, con la sua estensione `git` |
| OpenHands Agent Canvas | 1.41.0 | Runtime dell'agente e le tre automazioni, come servizio utente su una macchina Linux |
| Automazione `github-issue-to-pr` | 1.2.4 | Developer: implementa le issue con label, rivede le PR fallite |
| Automazione `github-pr-reviewer` | 1.11.2 | Reviewer: revisiona le PR quando i check finiscono |
| Automazione `github-issue-tester` | scritta a mano | Tester: testa le PR mergiate sullo stage di sviluppo deployato |
| Agente Developer | Claude Code tramite ACP, Sonnet | Agent profile `developer` |
| Agente Reviewer | Claude Code tramite ACP, Opus | Agent profile `reviewer` |
| Agente Tester | Claude Code tramite ACP, Opus | Agent profile `tester` |
| Nx + pnpm | Nx 23 | Monorepo, `nx affected` nella CI |
| Playwright | | Test E2E sullo stack locale, sei shard nella CI. Anche l'agente Tester lo usa per pilotare i portali deployati |
| Trivy, git-secrets, commitlint | | Scansione di sicurezza, controllo dei secret in pre-commit, formato dei messaggi di commit |

## Dalla lacuna al file

| Lacuna | La risposta di Discava | File |
| --- | --- | --- |
| Dalla spec alla issue | Il workflow Agent Issues e i suoi script | `.github/workflows/agent-issues.yml`, `packages/tooling/agent/src/agent-issues/` |
| Dal fallimento della CI all'agente | Agent CI Status | `.github/workflows/agent-ci.yml`, `src/agent-ci/` |
| Dalla review all'agente | Agent Review Status | `.github/workflows/agent-review.yml`, `src/agent-review/` |
| Loop infiniti | Limiti di cinque tentativi con le label | `MAX_CI_FIX_ATTEMPTS` e `MAX_REVIEW_FIX_ATTEMPTS` in `plan.ts` |
| `tasks.md` malformato | Il job Tasks format | `pr-checks.yml` `tasks-format`, `src/agent-issues/validate.ts` |
| Modifiche alla UI non viste | Il job UI Screenshots, il commento E2E screenshots | `pr-checks.yml`, `src/ui-screenshots/`, `packages/e2e/src/helpers/screenshots.ts` |
| Il merge non porta avanti il lavoro | Agent Issues sui branch `openhands/` mergiati | `src/agent-issues/gate.ts` |
| Niente cloud per l'agente | Sostituti locali per ogni servizio AWS | `pnpm dev`, `packages/tooling/local-dev/src/{dynamodb,s3mock,elasticmq,opensearch,local-oidc}` |
| Il merge non rilascia | CI su `main`, poi Deploy | `.github/workflows/ci.yml`, `deploy.yml`, `scripts/setup-stage.sh` |
| Secret e dipendenze vulnerabili | Trivy nella CI e prima del deploy, git-secrets al commit | `ci.yml` `trivy`, `deploy.yml`, `.husky/pre-commit`, `.trivyignore` |
| Modifica mergiata mai testata dove gira | Post-merge Verify apre una issue di test per ogni PR deployata, l'agente Tester la testa, e solo i collaboratori possono commentare ciò che gli agenti leggono | `.github/workflows/post-merge-verify.yml`, `src/post-merge-test/`, `src/helpers/conversation-lock.ts`, il limite di interazione del repository |

Il collante vive in `packages/tooling/agent/` (`@discava/tooling-agent`). I percorsi `src/…` di
questa sezione sono relativi a quella cartella.

E il testo che ogni agente legge:

| Istruzioni | File |
| --- | --- |
| Regole del progetto, verificate da ogni piano | `.specify/memory/constitution.md` (versione 1.2.1) |
| Comandi, architettura, convenzioni | `AGENTS.md` |
| Processo delle PR, stack locale, test | `CONTRIBUTING.md` |
| Istruzioni su ogni issue di implementazione | `.github/ISSUE_TEMPLATE/implement-phase.md` |
| La forma a mano di una issue di test | `.github/ISSUE_TEMPLATE/test-deployed-pr.md` |
| Il prompt permanente di ogni ruolo degli agenti | In OpenHands, fuori dal repository. Vedi [I prompt degli agenti](../agent-prompts/) |
| Template di Speckit, personalizzati per l'automazione | `.specify/templates/tasks-template.md`, `spec-template.md` |

## I numeri

Dal 14 novembre, quando il workflow è entrato in funzione, al 20 novembre 2026:

- 19 spec di funzionalità scritte con Speckit, in `specs/`.
- 3.287 passaggi delle automazioni, uno ogni cinque minuti: 1.738 polling issue-to-PR, 1.476
  polling di review e 73 polling di test. 256 di questi hanno trovato lavoro e avviato un agente.
- 132 PR degli agenti mergiate. 55 non hanno avuto bisogno di correzioni automatiche, 45 di un giro,
  una ha esaurito un loop.
