| Workflow | File | Trigger | Permessi | Fa il checkout di |
| --- | --- | --- | --- | --- |
| PR Checks | `pr-checks.yml` | `pull_request` verso `main` | `contents: read`, più `pull-requests: write` per il job del commento con gli screenshot | La PR, tranne il job del commento con gli screenshot: il branch predefinito |
| UI Screenshots | `ui-screenshots.yml` | `pull_request` verso `main`, inclusi `labeled`/`unlabeled` | `contents: read`, `pull-requests: read` | Il branch predefinito (legge il diff dall'API) |
| CI | `ci.yml` | `push` su `main`, `workflow_dispatch` | `contents: read`, `pages: write`, `id-token: write` | `main` |
| Agent Issues | `agent-issues.yml` | `pull_request: [closed, labeled]` verso `main`, `workflow_dispatch(spec_folder)` | `contents: read`, `issues: write`, `pull-requests: write` | Il merge commit |
| Archive Specs | `archive-specs.yml` | `push` su `main` che modifica `specs/*/tasks.md`, `workflow_dispatch` | `contents: write`, `issues: read`, `pull-requests: write` | `main` |
| Agent CI Status | `agent-ci.yml` | `workflow_run` di PR Checks, `completed` | `contents: read`, `actions: read`, `statuses: write`, `issues: write`, `pull-requests: write` | Il branch predefinito (tramite Agent Status) |
| Agent Review Status | `agent-review.yml` | `pull_request_review: submitted` | `contents: read`, `statuses: write`, `issues: write`, `pull-requests: write` | Il branch predefinito (tramite Agent Status) |
| Agent Status | `agent-status.yml` | `workflow_call` dai due sopra, con il target Nx da eseguire | Quelli del chiamante | Il branch predefinito |
| Cache Cleanup | `cache-cleanup.yml` | `pull_request: closed` | `actions: write` | Niente (passa il numero della PR a `gh`) |
| Deploy | `deploy.yml` | `workflow_run` della CI su `main` (solo quando `AUTO_DEPLOY_STAGE` è impostata), `workflow_dispatch(stage)` | `contents: read`, `id-token: write` | Il commit verificato dalla CI |
| Post-merge Verify | `post-merge-verify.yml` | `workflow_run` di Deploy, `completed`, `workflow_dispatch(pr_number)` | `contents: read`, `actions: read`, `issues: write`, `pull-requests: write` | Il branch predefinito |

## Nomi dei job da rendere obbligatori nella protezione del branch

| Check | Da |
| --- | --- |
| `Checks (lint)`, `Checks (test)`, `Checks (build)` | PR Checks |
| `Tasks format` | PR Checks |
| `Invariant coverage` | PR Checks |
| `E2E tests` | PR Checks (raccoglie gli shard) |
| `UI Screenshots` | UI Screenshots |

## Gruppi di concurrency

| Workflow | Gruppo | Annulla quelli in corso |
| --- | --- | --- |
| PR Checks | `pr-checks-<ref>` | sì: un nuovo push rende inutile la vecchia esecuzione |
| Agent Issues | `agent-issues-<PR number or folder>` | no |
| Archive Specs | `archive-specs` | no: un'esecuzione alla volta, così due non aprono mai la stessa PR |
| Agent CI Status | `agent-ci-<head branch>` | no |
| Agent Review Status | `agent-review-<PR number>` | no |
| Deploy | `deploy-<stage>` | no |
| Post-merge Verify | `post-merge-verify` | no: un'esecuzione alla volta, così due deploy ravvicinati non aprono mai due issue per la stessa PR |

I workflow degli agenti non annullano mai. Ogni esecuzione deve contare il suo tentativo o aprire la sua issue esattamente una volta,
e i gruppi per PR fanno sì che PR non correlate non si aspettino mai a vicenda.

## Variabili del repository

| Variabile | Letta da | Predefinito |
| --- | --- | --- |
| `AUTO_DEPLOY_STAGE` | Deploy | Non impostata: Deploy gira solo a mano |
| `TEST_STAGE` | Post-merge Verify | `AUTO_DEPLOY_STAGE` |
| `AWS_REGION`, `AWS_DEPLOY_ROLE_ARN`, `AWS_EXECUTION_ROLE_ARN` | Deploy, sull'environment GitHub di ogni stage | Nessuno. Deploy si ferma e indica cosa manca |
| `AWS_DOCKER_LOGIN_ROLE_ARN` | `init-monorepo`, per i pull da Amazon ECR Public | Non impostata: pull anonimi |
