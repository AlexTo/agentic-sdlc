Un [fork di questo repository](../../guides/fork-this-repo/) contiene tutto ciò che la configurazione di Discava tiene
nel repository. Questi passaggi aggiungono la parte che vive fuori: le impostazioni di GitHub, una
GitHub App con cui agiscono gli agenti, e un'installazione di OpenHands puntata sul tuo fork. Poi
scrivi una spec per l'app di note e la guardi passare dalla PR della spec alle PR degli agenti unite.

**Tempo:** circa un'ora, quasi tutta in attesa della prima esecuzione dell'agente.

## Cosa ti serve

Su macOS o Linux (su Windows, usa WSL):

| Requisito | Perché |
| --- | --- |
| Un account GitHub | Per fare il fork, scrivere le spec e fare review |
| GitHub CLI (`gh`), con accesso effettuato | La usano lo script di configurazione e gli agenti |
| Node.js 24 e pnpm | Per eseguire il repository e Agent Canvas |
| `uv` | Agent Canvas avvia il suo backend con `uvx` |
| Un coding agent, installato e con accesso effettuato | Scrive le spec con Speckit, e fa il lavoro degli agenti dentro OpenHands. Discava usa Claude Code |
| Docker (facoltativo) | Solo per eseguire sulla tua macchina l'app di note e i suoi test e2e. La CI li esegue per gli agenti |

<Aside type="note">
Agent Canvas gira sulla tua macchina e interroga GitHub, quindi non servono un indirizzo pubblico né un
webhook. Gli agenti lavorano solo mentre è in esecuzione.
</Aside>

## I passaggi

| # | Passaggio | Cosa fai | Alla fine avrai |
| --- | --- | --- | --- |
| 1 | [Fai il fork del repository](../fork/) | Tre comandi | La tua copia, clonata |
| 2 | [Configura il repository](../github-repository/) | Crei una GitHub App da un modulo già compilato, esegui un solo script | La GitHub App degli agenti sul tuo fork, le label, un `main` protetto, commenti limitati ai collaboratori |
| 3 | [Installa OpenHands](../openhands/) | Due comandi, due profili nell'interfaccia web | Agent Canvas in esecuzione come la tua app, con un profilo `developer` e un profilo `reviewer` |
| 4 | [Crea le due automazioni](../automations/) | Due moduli nell'interfaccia web, un prompt da incollare | Gli agenti Developer e Reviewer che implementano e fanno review nel tuo fork |
| 5 | [Esegui la tua prima feature](../first-feature/) | Scrivi una spec, fai la review delle pull request | Una spec per l'app di note, portata dagli agenti fino al codice unito |
