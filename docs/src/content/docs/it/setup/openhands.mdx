import { Steps, Aside } from '@astrojs/starlight/components';

**Alla fine avrai:** OpenHands Agent Canvas in esecuzione sulla tua macchina come la tua GitHub App,
e due profili agente: `developer` per l'agente Developer e `reviewer` per l'agente Reviewer.

<Steps>

1. **Installa Agent Canvas.** Discava usa la versione 1.45.0:

   ```bash
   npm install -g @openhands/agent-canvas
   ```

2. **Avvialo come la tua app**, dal tuo clone:

   ```bash
   pnpm agent-canvas
   ```

   La prima volta chiede l'**App ID** e il percorso del **file `.pem`** del
   [passaggio 2](../github-repository/), e li conserva entrambi in `~/.config/agent-app/`,
   leggibili solo da te. Poi, ogni volta:

   - avvia Agent Canvas con l'app come autore dei commit degli agenti, così GitHub li mostra
     sotto l'app;
   - crea uno dei token dell'app, che durano un'ora, e lo salva in Agent Canvas come secret
     `GITHUB_PERSONAL_ACCESS_TOKEN`, quello che leggono le automazioni. Nonostante il nome, lì va
     bene qualsiasi token GitHub;
   - sostituisce il token ogni 45 minuti per tutto il tempo in cui gira.

   Aspetta la riga `Token stored in the GITHUB_PERSONAL_ACCESS_TOKEN secret`, poi apri
   [http://127.0.0.1:8000](http://127.0.0.1:8000). Se Agent Canvas chiede quale agente usare,
   scegli Claude Code: trova l'accesso che hai già, quindi lascia vuoti gli eventuali campi per
   le API key.

   Tieni aperto il terminale, e avvia sempre Agent Canvas in questo modo: le automazioni fanno
   poll solo mentre è attivo, e il token resta aggiornato solo mentre gira questo comando.

3. **Crea due profili agente**, uno per ogni ruolo degli agenti. In Agent Canvas, apri
   **Settings → Agent** e clicca **Add agent profile**, due volte:

   | Name | Agent type | Agent | Model |
   | --- | --- | --- | --- |
   | `developer` | ACP (external subprocess) | `claude-code` | `sonnet` |
   | `reviewer` | ACP (external subprocess) | `claude-code` | `opus` |

   ACP è l'Agent Client Protocol: il lavoro lo fa il coding agent che già usi, con il tuo accesso
   su questa macchina. Va bene qualsiasi agente e modello. Tieni il Reviewer forte almeno quanto
   il Developer: è l'ultimo controllo prima di te.

   Lascia tutto il resto com'è. Agent Canvas gira già senza supervisione (nessuna richiesta di
   conferma), con spazio per un'intera fase in una sola conversazione (500 iterazioni).

</Steps>

## Verifica che funzioni

In Agent Canvas, **Settings → Secrets** elenca `GITHUB_PERSONAL_ACCESS_TOKEN`. Avvia una
conversazione con il profilo `developer` e chiedigli:

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

Riporta `<app-name>[bot]`, e un elenco di issue vuoto.

<Aside type="caution" title="Tieni il tuo login GitHub lontano dagli agenti">
Non aggiungere un token GitHub in **Integrations** di Agent Canvas, ed elimina ogni server GitHub
elencato in **MCP Servers**: entrambi contengono un token fisso, di solito il tuo, e un agente che
lo usa agisce come te invece che come l'app.
</Aside>

<Aside type="caution">
L'agente esegue comandi su questa macchina con il tuo utente. Non tenere credenziali cloud nel suo
ambiente, e usa una macchina separata o una VM quando vai oltre la semplice prova.
</Aside>

<Aside type="tip" title="Eseguire Agent Canvas come servizio">
Quando Agent Canvas gira come servizio invece che in un terminale, fai eseguire a un timer
`pnpm agent-canvas --once` ogni 45 minuti: crea un token, lo salva ed esce. Discava lo fa su Linux
con systemd: vedi
[La configurazione di OpenHands in Discava](../../discava/openhands-setup/#la-github-app).
</Aside>

Discava ha un terzo profilo, `tester`, per l'agente Tester. Testa le modifiche unite su uno stage
deployato, che l'app di note non ha, quindi qui non ti serve.
