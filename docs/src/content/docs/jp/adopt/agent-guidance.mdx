**このステップで得られるもの:** すべてのエージェントが最初に読む `AGENTS.md` と、すべての実装 issue に入る定型の指示の元になる
`.github/ISSUE_TEMPLATE/` 以下の issue テンプレート。

<Steps>

1. このリポジトリから **`AGENTS.md` をコピーし**、各セクションを自分のプロジェクト用に書き直します。
   意図的に短くしてあります。エージェントが毎回の実行で必要とすることだけで、それ以外は何もありません。

   | セクション | 書くこと |
   | --- | --- |
   | What this is | 1 段落: プロダクト、スタック、モノレポツール |
   | Commands | インストール。すべてのビルド、lint、テスト。1 つのプロジェクトのテストを 1 回だけ（watch モードではなく）。1 つのテストファイル。`nx affected`。e2e。ローカル開発 |
   | Architecture | パッケージごとに 1 項目: それが何か、何を import してよいか、各種類の新しいコードをどこに置くか |
   | Conventions | Conventional Commits、フォーマッターの名前、ヘルパーの置き場所、そしてレビュアーが 2 回繰り返す必要があったすべてのルール |

   <Aside type="tip">
   最も重要なのはコマンドのセクションです。「テストファイルを 1 つ、1 回だけ実行する」方法を見つけられないエージェントは、
   スイート全体を watch モードで実行して止まってしまいます。挙げたコマンドは、動くことを確かめるために一度ずつ実行してください。
   </Aside>

   アーキテクチャのセクションがパッケージごとに 1 行では収まらなくなったら、各パッケージの詳細をそのフォルダー内の
   ネストした `AGENTS.md` に移し、ルートにはそこを指す 1 行を残します。エージェントはネストしたファイルを
   そのフォルダーで作業するときにだけ読み込むので、1 回の実行で読むのは必要な詳細だけになります。
   このリポジトリの `packages/tooling/agent/AGENTS.md` がその一つです。[ステップ 5](../glue-scripts/) でグルーと一緒に
   コピーしてください。

   エージェントが `CLAUDE.md` のような別の名前のファイルを読む場合は、そのファイルが `AGENTS.md` を指すようにします。
   このリポジトリの `CLAUDE.md` は `@AGENTS.md` で始まっていて、Claude Code はこれを「そのファイルをここに含める」と読みます。

2. このリポジトリから **`.github/ISSUE_TEMPLATE/` をコピーします**。開発担当用の `implement-phase.md` と、
   [ステップ 9](../deploy/) で追加する場合はテスト担当用の `test-deployed-pr.md` です。

   Agent Issues スクリプトは issue の spec とスコープのセクションを自分で書き、`implement-phase.md` の
   `## Instructions for the agent` 以下のすべてを実行時に読み込みます。この見出しは正確にそのまま残してください。
   スクリプトはこの見出しを探し、見つからないと失敗するためです。`#<parent>` もそのまま残します。スクリプトが
   これを spec の親 issue に置き換え、spec に親 issue がない場合はその箇条書きを削除します。

3. **指示を自分のスタックに合わせて編集します**。コマンド、スクリーンショットのヘルパーのパス、
   そして自分の環境で「cloud credentials」が何を指すかです。

</Steps>

## 動作を確認する

```bash
grep -c '^## Instructions for the agent$' .github/ISSUE_TEMPLATE/implement-phase.md
```
