import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**このステップで得られるもの:** ローカルの代替サービスでアプリ全体を起動する `pnpm dev`、CI がすべての PR で実行する
Playwright スイート、PR に投稿されるスクリーンショット、そして各テストの後にチェックされる invariant。

これは最もスタックに依存するステップです。同時に、クラウドの認証情報なしで CI がエージェントに本物のフィードバックを
返せるようにするステップでもあります。

<Steps>

1. **すべてのクラウドサービスにローカルの代替を用意し**、`dev` ターゲットで起動して、`pnpm dev` ですべてが
   動くようにします。このリポジトリの `packages/tooling/local-dev/` は、notes のテーブル用に Docker で DynamoDB local を
   起動します。[Discava のローカル代替](../../discava/local-stack/#ローカルで動くもの) はさらに S3、SQS、OpenSearch、
   Cognito をカバーし、クラウドで Lambda のトリガー、ストリーム、EventBridge が呼び出すのと同じハンドラーを
   呼び出す「イベントランナー」プロセスも含みます。

   バックエンドのコードは 1 つのフラグ（`LOCAL_DEV=true`）で切り替え、エンドポイントは 1 つの共有モジュールにまとめます。
   まだクラウドでしか動かないものはコントリビューションガイドに列挙し、それを必要とするタスクには
   **(human)** を付けます。

2. このリポジトリから **e2e プロジェクト** `packages/e2e/` を**コピーし**、そのシナリオを自分のものに置き換えます。
   ユーザーフローごとに 1 ファイルです。残すものは次のとおりです。

   <FileTree>
   - packages/e2e/
     - playwright.config.ts CI のマトリックスがスイートを分割できるように `E2E_SHARD` を読み、`pnpm dev` を起動し、ワーカーは 1 つ、リトライは CI でのみ
     - src/helpers/
       - screenshots.ts `screenshot(page, 'name')`。PR Checks の `e2e` ジョブがアップロードする画像を保存する
       - table-invariants.ts シナリオのたびに invariant をチェックする Playwright の `test`
   </FileTree>

   各シナリオは自分のユーザーと一意な名前のデータを作り、どのシナリオもローカルのデータをリセットしないので、
   どの順番でも実行できます。人が目で確認する箇所で、表示内容に対する `expect` の後に `screenshot` を呼び出します。

   ```ts
   await expect(page.getByRole('heading', { name: 'Reviews' })).toBeVisible();
   await screenshot(page, 'reviews section with three reviews');
   ```

3. `packages/notes-table/src/helpers/invariants/` から、自分のテーブルを持つパッケージに **invariant をコピーします**。
   異なるコードが書き込むレコードにまたがるルール（カウンター、集計、順序）ごとに、データのスナップショットを走査して
   違反を返すチェックを書き、それを破るユニットテストも書きます。`packages/notes-table/README.md` の
   「Rules that span records」で、追加の手順を説明しています。

   シナリオは `@playwright/test` ではなく `table-invariants.ts` から `test` を取得します。各シナリオの後、
   以前にはなかった違反がテーブルにあれば、そのシナリオを失敗させます。数えるのは *新しい* 違反だけなので、
   古いローカルデータが原因で失敗することはなく、`expect.poll` はバックグラウンドの処理（ストリームハンドラー、再計算）が
   追いつくまでの時間を与えます。

4. **書き込み元マップを生成し、pre-push フックをコピーします。**
   `pnpm nx run @your-scope/tooling-agent:entity-writers` を実行し、それが書き出す `entity-writers.json` をコミットします。
   このリポジトリから `.husky/pre-push` をコピーし、その `MAP` と `PATHS` を自分のものに向けます。ブランチが
   テーブルに書き込む可能性のあるコードを変更すると、このフックはマップを再生成し、マップが変わっていれば push を止めます。
   その後、`Invariant coverage` PR チェックがマップをベースブランチのものと比較し、書き込み元を追加する PR を、
   invariant がそのエンティティを挙げるまで保留します。

5. 2 人のユーザーが競合しうる書き込みについて **並行性テストを追加します**。`Promise.all` で同じ API リクエストを
   同時に送り、その結果と invariant をアサートします。

</Steps>

## 動作を確認する

```bash
pnpm nx e2e @your-scope/e2e
ls dist/packages/e2e/screenshots/*/
```

次に、ページを変更し `screenshot(` の呼び出しを 1 つ追加する PR を開きます。PR Checks が終わると、PR には
見出しが **E2E screenshots** のコメントが付き、「Added by this pull
request」の下に新しい画像が一覧表示されます。

<Aside type="tip">
アプリをまだ完全にはローカルで動かせない場合は、動かせる部分から始めてください。API とデータベースだけをカバーする
スイートでも、エージェントのミスの大半を検出できます。代替はサービスを 1 つずつ追加し、それまでは残りを
**(human)** タスクとして残しておきます。
</Aside>
