**最終的に手に入るもの:** リポジトリ内の `.specify/`、コーディングエージェントで使える `speckit-*` コマンド、
そしてタイムスタンプで名前が付く spec フォルダ。

<Steps>

1. Discava が使っているバージョンに固定して、**CLI をインストールします**。

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. 同梱の git 拡張を付けて、コーディングエージェント向けに**リポジトリで初期化します**。
   Discava は `claude` インテグレーションを使いました。これはコマンドをスキルとしてインストールします。

   ```bash
   specify init --here --integration claude --script sh --extension git
   ```

   ほかのインテグレーションは `specify init --help` で確認できます。チームのエージェントが読むものを選んでください。

3. **タイムスタンプによる番号付けに切り替えます。** `.specify/extensions/git/git-config.yml` で次のようにします。

   ```yaml
   branch_numbering: timestamp
   commit_style: conventional
   ```

   フォルダは `specs/001-course-reviews/` ではなく `specs/20261116-013307-course-reviews/` になるので、
   2 人が同時に spec を書いても衝突しません。

4. `.specify/extensions.yml` で **git 拡張のフックを確認します**。Discava はデフォルトのままです。
   `/speckit-specify` の前に `speckit.git.feature`（ブランチを作成）、各ステップの後に `speckit.git.commit`
   （ステップごとに 1 コミット）。`auto_execute_hooks: true` を設定して、確認なしで実行されるようにしています。

5. **`.specify/`** と、インテグレーションのコマンドまたはスキルのファイルを**コミットします**。

</Steps>

## 動作を確認する

<FileTree>
- .specify/
  - extensions/git/ git-config.yml、コマンド、スクリプト
  - extensions.yml
  - init-options.json
  - memory/constitution.md まだテンプレートのまま。次のステップで記入する
  - scripts/bash/
  - templates/ spec、plan、tasks、checklist、constitution のテンプレート
</FileTree>

コーディングエージェントに、`speckit-specify`、`speckit-clarify`、`speckit-plan`、`speckit-tasks`、
`speckit-analyze`、`speckit-constitution` の各コマンドが表示されます。

<Aside type="tip">
spec の PR は `openhands/...` ではなく、専用のブランチ（`spec/<name>`）に置きます。それには git 拡張の
feature ブランチで問題ありません。`openhands/` プレフィックスを使うのはエージェントのブランチだけです。
</Aside>
