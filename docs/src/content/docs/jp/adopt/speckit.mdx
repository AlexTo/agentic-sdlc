**最終的に手に入るもの:** リポジトリ内の `.specify/`、コーディングエージェントで使える `speckit-*` コマンド、
そしてタイムスタンプで名前が付く spec フォルダ。

<Steps>

1. Discava が使っているバージョンに固定して、**CLI をインストールします**。

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. このリポジトリから **`.specify/` をコピーします**。workflow が必要とするとおりにすでに設定されています。

   | 設定 | 場所 | 値 |
   | --- | --- | --- |
   | タイムスタンプで名前が付く spec フォルダ | `extensions/git/git-config.yml` | `branch_numbering: timestamp`。`specs/001-course-reviews/` ではなく `specs/20261116-013307-course-reviews/` になるので、2 人が同時に spec を書いても衝突しない |
   | ステップごとの Conventional Commits | `extensions/git/git-config.yml` | `commit_style: conventional` |
   | git 拡張のフックが確認なしで実行される | `extensions.yml` | `auto_execute_hooks: true`。`/speckit-specify` の前にブランチ、各ステップの後にコミット |
   | テンプレートと憲章 | `templates/`、`memory/` | [ステップ 3](../constitution-and-templates/) の変更がすでに入っている |

3. **コーディングエージェント用のコマンドを追加します。** エージェントが Claude Code のスキルを読む場合は、
   このリポジトリから `.claude/skills/speckit-*` をコピーします。そうでない場合は、作業用のフォルダで Speckit に
   エージェント用のコマンドを書かせ、コマンドのファイルだけをコピーします。

   ```bash
   mkdir /tmp/speckit && cd /tmp/speckit
   specify init --here --integration <your-agent> --script sh --extension git
   ```

   インテグレーションの一覧は `specify init --help` で確認できます。エージェントのコマンド用に作られたフォルダを
   コピーし、その `.specify/` はコピーしないでください。ステップ 2 が元に戻ってしまいます。

4. **`.specify/`** と、コマンドまたはスキルのファイルを**コミットします**。

</Steps>

## 動作を確認する

<FileTree>
- .specify/
  - extensions/git/ git-config.yml、コマンド、スクリプト
  - extensions.yml
  - init-options.json
  - memory/constitution.md notes アプリのもの。次のステップで自分用に書き直す
  - scripts/bash/
  - templates/ spec、plan、tasks、checklist、constitution のテンプレート
</FileTree>

コーディングエージェントに、`speckit-specify`、`speckit-clarify`、`speckit-plan`、`speckit-tasks`、
`speckit-analyze`、`speckit-constitution` の各コマンドが表示されます。

<Aside type="tip">
spec の PR は `openhands/...` ではなく、専用のブランチ（`spec/<name>`）に置きます。それには git 拡張の
feature ブランチで問題ありません。`openhands/` プレフィックスを使うのはエージェントのブランチだけです。
</Aside>
