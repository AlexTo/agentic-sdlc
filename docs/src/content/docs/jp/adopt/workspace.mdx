**最終的に手に入るもの:** Nx と Biome を備えた pnpm ワークスペース、すべてのコミットで強制される
Conventional Commits、そしてコミットのたびに行われるシークレットのチェック。

グルーに Nx は必須ではありません。ただし、エージェントが繰り返し試せるほど PR チェックを速く保っているのは
`nx affected` であり、グルースクリプトはすべて Nx のターゲットとして実行されます。別のモノレポツールを使う場合も、
考え方は同じです。PR が影響する部分だけを実行し、すべてのスクリプトを名前付きのタスクとして公開してください。

<Steps>

1. まだない場合は、**ワークスペースを作成します**。Discava もこのリポジトリも、Nx Plugin for AWS で
   作成されました。

   ```bash
   pnpm create @aws/nx-workspace your-project --iac=cdk --no-interactive
   ```

   既存の Nx ワークスペースでも構いません。CI とエージェントが同じバージョンを使うよう、ルートの
   `package.json` で `packageManager` を使って pnpm を固定します。

2. このリポジトリから、自分のリポジトリの同じパスに**次のファイルをコピーします**。

   <FileTree>
   - commitlint.config.js Conventional Commits
   - lint-staged.config.js ステージされたファイルに Biome を実行
   - .husky/
     - commit-msg commitlint を実行
     - pre-commit git-secrets、続いて lint-staged を実行し、Biome が何かを変えた場合は失敗する。そうするとエージェントはステージし直して再度コミットする
     - prepare-commit-msg 対話的にコミットする人のための Commitizen。エージェントのコミット方法である `git commit -m` では自動でスキップされる
   - .git-secrets/ pre-commit フックが実行する git-secrets スクリプト
   - .gitallowed git-secrets が通すパターン
   - .github/
     - actions/init-monorepo/ 共通の CI セットアップ
     - actions/changed-paths/ ジョブをスキップするための「この PR はこれらのパスのどれかを変更したか?」
     - actions/playwright-setup/ Playwright 用の Chromium。バージョンごとにキャッシュ
     - dependabot.yml 固定したアクションと依存関係を最新に保つ
   </FileTree>

   `.husky/pre-push` は [ステップ 8](../local-stack-and-e2e/) まで置いておきます。これは invariant マップをチェックします。
   `init-monorepo` は pnpm を（3 回までリトライして。レジストリのタイムアウトでエージェントが修正の試行を 1 回失わないように）、
   Node 24 と、必要に応じて uv をインストールし、pnpm と Nx のキャッシュを復元し、依存関係をインストールし、
   `nx affected` 用に `NX_BASE`/`NX_HEAD` を設定します。

3. このリポジトリの `package.json` から**ルートのスクリプトと dev 依存関係をコピーします**。`scripts` ブロック
   （`AGENTS.md`、CI、エージェントが呼び出すもの）と、`devDependencies` のうち
   `@commitlint/config-conventional`、`commitlint`、`commitizen`、`husky`、`lint-staged` です。続いて:

   ```bash
   pnpm install
   ```

   その `prepare` スクリプトがフックをインストールします。

4. `.github/actions/playwright-setup/action.yml` の**パッケージスコープ**（`@agentic-sdlc/e2e`）を、
   自分の e2e プロジェクトの名前に変更します。

</Steps>

## 動作を確認する

```bash
git commit --allow-empty -m "not conventional"
```

```text
⧗   input: not conventional
✖   subject may not be empty [subject-empty]
✖   type may not be empty [type-empty]
```

続いて `git commit --allow-empty -m "chore: check hooks"` は成功します。

<Aside type="note">
グルーが書く issue のタイトルは Conventional Commit のヘッダーで、エージェントはそれをコミットと
pull request に再利用します。commitlint が最初に来るのはそのためです。
</Aside>
