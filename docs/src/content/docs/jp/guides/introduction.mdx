このガイドでは、**エージェントがコードを書き、人は 2 つの判断をする**ソフトウェアライフサイクルの動かし方を示します。
2 つの判断とは、spec の承認と、結果の承認です。その間のすべて (issue を開く、コードとテストを書く、CI に反応する、
レビューに応える) は、通常の GitHub のプロセスを通じて自動で進みます。

このワークフローは、AWS 上のサーバーレスな学習管理システムである [Discava](https://github.com/AlexTo/discava)
で毎日動いています。2026 年 11 月 14 日に稼働を始めてからの 6 日間で、16 個の機能 spec がこの方法で書かれ、
それを実装するために 105 個のエージェントの pull request がマージされました。どれもエージェントが書き、修正し、レビューしたものです。
同じ期間に、main には 173 個のコミットが入りました。これをすべて、メンテナー 1 人でこなしています。フルタイムの仕事を持つ父親で、
空いた時間に気軽に Discava に取り組んでいる人です。😅

## 要約

既製の 3 つのツールが作業の大半を担います。

| ツール | ここでの役割 |
| --- | --- |
| [Speckit](https://github.com/github/spec-kit) | アイデアを `spec.md`、`plan.md`、`tasks.md` にし、プロジェクトの constitution と照合する |
| [OpenHands](https://github.com/OpenHands/OpenHands) | ラベル付きの issue を pull request にし、問題を指摘されたら pull request を修正する。2 つ目の OpenHands automation がそれをレビューする |
| GitHub Actions | チェックを実行し、他の 2 つをつなぐグルーを保持する |

どのツールも他のツールのことを知りません。**このガイドの大部分はグルーについてです**。完了した spec をエージェントに、
CI をエージェントに、レビュアーをエージェントにつなぐ、小さくてテスト済みの 10 個の自動化で、何も無限にループしないよう上限を設けています。

## 対象読者

- **ワークフローを採用するかどうかを判断するテックリードやスタッフエンジニア。** まず
  [コンセプト](../../concepts/principles/)から読んでください。
- **試してみたい人。** [このリポジトリを fork し](../fork-this-repo/)、
  [セットアップ](../../setup/before-you-start/)に従って 1 つの機能をループ全体に通してください。
- **プロダクトのリポジトリに導入するエンジニア。**
  [Discava のやり方](../../discava/overview/)を読み、次に
  [自分のリポジトリに導入する](../../adopt/overview/)を読んでください。
- **日々使う開発者。** [チュートリアル](../../tutorial/the-case/)で、1 つの機能をアイデアからマージまで追います。

Git、GitHub の pull request、GitHub Actions に慣れている必要があります。Speckit や OpenHands の経験は不要です。

## このガイドの構成

| セクション | 答える問い |
| --- | --- |
| **ここから始める** | これは何で、機能はどのように流れていくのか? |
| **コンセプト** | なぜこのように作られているのか? |
| **Discava のやり方** | 各ギャップを具体的に何が、どのファイルで埋めているのか? |
| **セットアップ: fork して動かす** | サンプルアプリでどうやって動かすのか? |
| **自分のリポジトリに導入する** | 既存のリポジトリに各要素をどう追加するのか? |
| **チュートリアル** | 1 つの小さな機能で使うと、どんな感じなのか? |
| **リファレンス** | ラベル、ステータス、ワークフロー、`tasks.md` の形式、トラブルシューティング、用語集 |

## 表記の約束

- `AGENTS.md` は、リポジトリのルートにあるエージェント向けガイダンスファイルを指します。名前は、使っているコーディング
  エージェントが読むものに合わせてください。
- `<you>/agentic-sdlc` はあなたの fork、`owner/repo` は任意のリポジトリです。
- `@your-scope` はワークスペースの npm スコープです。このリポジトリでは `@agentic-sdlc`、Discava では
  `@discava` を使っています。
- ステップで別途指示がない限り、コマンドはリポジトリのルートから実行します。
- **(human)** は、エージェントが行ってはならないタスクを示します。これは `tasks.md` で使われる文字どおりのマーカーでもあります。
