**完了時の状態:** 自分のマシンで GitHub App として動く OpenHands Agent Canvas と、開発担当エージェント用の
`developer` とレビュー担当エージェント用の `reviewer` の 2 つのエージェントプロファイル。

<Steps>

1. **Agent Canvas をインストールします。** Discava はバージョン 1.45.0 を使っています:

   ```bash
   npm install -g @openhands/agent-canvas
   ```

2. クローンから、**自分の App として起動します**:

   ```bash
   pnpm agent-canvas
   ```

   初回は、[手順 2](../github-repository/) の **App ID** と **`.pem` ファイル** のパスを尋ね、どちらも
   自分だけが読める状態で `~/.config/agent-app/` に保存します。その後は毎回、次のことを行います。

   - App をエージェントのコミットの作成者として Agent Canvas を起動します。これで GitHub はコミットを
     App の名前で表示します。
   - 1 時間有効な App のトークンを 1 つ作り、Agent Canvas のシークレット `GITHUB_PERSONAL_ACCESS_TOKEN` に
     保存します。automation が読むのはこのシークレットです。名前に反して、ここにはどんな GitHub の
     トークンでも入れられます。
   - 動いている間は、45 分ごとにトークンを置き換えます。

   `Token stored in the GITHUB_PERSONAL_ACCESS_TOKEN secret` という行が出るのを待ってから、
   [http://127.0.0.1:8000](http://127.0.0.1:8000) を開きます。Agent Canvas にどのエージェントを使うか
   尋ねられたら、Claude Code を選びます。すでにあるログインを見つけるので、API キーの欄は空のままにします。

   ターミナルは開いたままにし、Agent Canvas は必ずこの方法で起動してください。automation は Agent Canvas が
   動いている間だけポーリングし、トークンはこのコマンドが動いている間だけ新しく保たれます。

3. エージェントの役割ごとに 1 つ、**2 つのエージェントプロファイルを作成します。** Agent Canvas で
   **Settings → Agent** を開き、**Add agent profile** を 2 回クリックします:

   | Name | Agent type | Agent | Model |
   | --- | --- | --- | --- |
   | `developer` | ACP (external subprocess) | `claude-code` | `sonnet` |
   | `reviewer` | ACP (external subprocess) | `claude-code` | `opus` |

   ACP は Agent Client Protocol のことです。普段使っているコーディングエージェントが、このマシンであなたとして
   サインインした状態で作業を行います。どのエージェントとモデルでも動きます。レビュー担当は少なくとも開発担当と
   同等の強さにしてください。あなたの前の最後のチェックだからです。

   それ以外はそのままにします。Agent Canvas は最初から無人で動き (確認のプロンプトなし)、1 つの会話に
   1 つのフェーズ全体が収まる余裕 (500 イテレーション) があります。

</Steps>

## 動作を確認する

Agent Canvas の **Settings → Secrets** に `GITHUB_PERSONAL_ACCESS_TOKEN` が一覧されます。`developer`
プロファイルを使って会話を始め、次のように依頼します:

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

`<app-name>[bot]` と、空の issue 一覧が報告されます。

<Aside type="caution" title="自分の GitHub ログインをエージェントから遠ざける">
Agent Canvas の **Integrations** に GitHub のトークンを追加せず、**MCP Servers** に一覧されている GitHub の
サーバーは削除してください。どちらも固定のトークン (たいていはあなたのもの) を持ち、それを使うエージェントは
App ではなくあなたとして動きます。
</Aside>

<Aside type="caution">
エージェントはこのマシン上で、あなたのユーザーとしてコマンドを実行します。その環境にクラウドの認証情報を置かず、
試用の範囲を超えたら別のマシンか VM を使ってください。
</Aside>

<Aside type="tip" title="Agent Canvas をサービスとして動かす">
Agent Canvas をターミナルではなくサービスとして動かすようになったら、タイマーで
`pnpm agent-canvas --once` を 45 分ごとに実行します。これはトークンを 1 つ作って保存し、終了します。
Discava は Linux で systemd を使ってこうしています。
[Discava の OpenHands のセットアップ](../../discava/openhands-setup/#github-app) を参照してください。
</Aside>

Discava には 3 つ目のプロファイル `tester` があり、テスト担当エージェントが使います。テスト担当はマージされた変更を
デプロイされたステージでテストしますが、notes アプリにはそれがないので、ここでは不要です。
