**現在地:** 🤖 エージェント、無人。**成果物:** `openhands/...` ブランチ上のフェーズ 1 の pull request。

次のポーリングで、OpenHands は `openhands` ラベルの付いた issue を見つけ、その会話を始めます。
あなたは何もしません。

## エージェントがすること

1. `AGENTS.md`、憲章、spec フォルダーを読みます。
2. まずそのフェーズのテストを書きます: spec にあるタグのルールをユニットテストとして書きます。
3. テストが通るまで実装し、`tasks.md` の各タスクに、それを完了したのと同じコミットでチェックを付けます。
4. 変更した部分に対して lint、型チェック、ビルド、ユニットテストを、watch モードではなく一度だけ実行します。
5. Conventional Commit 形式のタイトルで PR を開きます。たとえば
   `feat(notes): add tags to notes in the data and API layers` で、本文には `Refs #<parent>` を入れます。
6. スキップした **(human)** タスクを一覧にします。

## してはいけないと指示されていること

issue に制限が明記されています:

- タスク範囲の外では決して作業しない。
- テストを通すためにテストを弱めない。
- `.github/workflows/` を編集しない、マージしない、認証情報に触れない。
- 行き詰まったら issue にコメントして止まる。推測はしない。

## 確認すること

PR を開いて、上から読みます:

- タイトルと本文から、何が変わり、どのタスクが完了したかがわかるか?
- テストは *spec の* ルールをテストしているか、それとも実装の癖をテストしているか?
- `tasks.md` のチェックは、ちょうどこのフェーズの分だけで、それ以上ではないか?

<Aside type="tip">
まだレビューする必要はありません。CI とレビュー担当エージェントが先に見て、彼らが納得してはじめて
PR があなたに届きます。次のステップを参照してください。
</Aside>
