**現在地:** ⚙️ 自動化、無人。**成果物:** グリーンで、エージェントレビューで承認された PR。

エージェントの PR への push のたびに、ゲートが実行されます。失敗はエージェントに戻され、あなたには来ません。

## ゲート

| ゲート | タグの題材で捕まえるもの |
| --- | --- |
| Lint、型チェック、ビルド | エンティティと合わなくなった API の型 |
| ユニットテスト | 6 つ目のタグが受け入れられる、または `Work` と `work` が 2 つのタグとして保存される |
| invariant | e2e テストのたびに確認される、タグが 5 つを超えるテーブル内のノート |
| E2E テスト | タグ入力が保存されない、またはフィルターが間違ったノートを表示する |
| 並行性テスト | 2 つの同時追加が互いを上書きし、タグが 1 つ失われる |
| スクリーンショット | 新しい UI が一度も見られていない: `UI Screenshots` チェックが失敗する |
| Tasks format チェック | チェーンを停滞させる、形式の崩れた `tasks.md` |

## ゲートが失敗したとき

1. **Agent CI Status** workflow が、PR の head コミットを失敗としてマークします。
2. エージェントは元の会話の中で、失敗の出力を使って *同じ* PR を修正します。
3. CI が再び実行されます。

例: タグの追加がノートを読み、メモリ上で追記して書き戻すため、2 つのリクエストが競合して並行性テストが失敗します。
エージェントはこれを、件数に条件を付けたアトミックな追記に変え、テストがグリーンになります。あなたはそれを目にすることもありません。

## エージェントレビュー

CI がグリーンになると、2 つ目の OpenHands エージェントであるレビュー担当エージェントが、人と同じように PR をレビューします: 正しさ、見落とされた
エッジケース、どのテストもカバーしていない spec のルールなどです。承認するか、変更を要求します。変更要求は、
CI が失敗したときと同じように、開発担当エージェントを差し戻します。

## 上限

各ループは PR ごとに **5 回** の試行に制限され、ラベルで数えられます: CI は `ci-fix-1` から `ci-fix-5`、
レビューは `review-fix-1` から `review-fix-5` です。5 回目の後、workflow はコメントし、
`ci-fix-exhausted` または `review-fix-exhausted` を付けて止まります。

<Aside type="caution">
ループの上限に達したときが、あなたが早い段階で呼ばれる唯一の場面です。
[人間のゲート](../../concepts/human-gates/#早い段階で呼ばれるとき) にどうすればよいかが書かれています。
</Aside>
