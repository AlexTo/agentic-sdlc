このチュートリアルでは、1 つの機能をアイデアからマージ済みのコードまで追いかけます: **ノートへのタグ** です。

> A user can add up to five tags to a note, and filter the note list by tag.

数個の PR で終えられるほど小さく、それでいてサンプルの notes アプリのすべてのレイヤーに関わるので、
workflow のどの段階にも実際の作業があります。

| レイヤー | 何が変わるか | どのゲートが誤りを捕まえるか |
| --- | --- | --- |
| `notes-table` | `note` エンティティの `tags` 属性 | ユニットテスト |
| `notes-api` | 作成と更新での `tags`、一覧での `tag` フィルター | ユニットテスト、型チェック |
| `notes-website` | ノートフォームのタグ入力、タグチップ、タグフィルター | スクリーンショット、e2e |
| ビジネスルール | タグは最大 5 つ、重複なし、大文字小文字を区別しない | invariant、ユニットテスト |
| 並行性 | 2 つのタブが同時にタグを追加しても、どちらも失われてはならない | 並行性テスト |
| `docs/` | notes アプリのページがタグを説明する | エージェントレビュー、人間のレビュー |

## フェーズ

spec は 3 つのフェーズに分かれるので、issue も PR も 3 つずつになります:

1. **データと API。** エンティティ、プロシージャ、検証ルール、ユニットテスト。
2. **ウェブサイト。** タグ入力、チップ、フィルター、スクリーンショット付きの e2e シナリオ、invariant テストと並行性テスト。
3. **ドキュメント。** タグを説明するようにドキュメントを更新します。

<Aside type="note">
この題材のフェーズは一例です。あなた自身の spec は違う分け方になるでしょう。ルールは、
各フェーズが `main` を動く状態に保つ、レビュー可能な 1 つの PR であることだけです。
</Aside>

## 始める前に

- このリポジトリの fork を
  [セットアップ: fork して実行する](../../setup/before-you-start/) のとおりに準備してあること。
- OpenHands が `openhands` ラベルの付いた issue をポーリングしていること。
- クリーンな作業ツリーの `main` で作業していること。
