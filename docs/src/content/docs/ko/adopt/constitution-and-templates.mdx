**결과:** 여러분만의 비준된 constitution, 그리고 Agent Issues workflow가 읽을 수 있는 파일을 만드는
Speckit 템플릿.

[2단계](../speckit/)에서 복사한 `.specify/`에는 노트 앱용으로 작성된, 동작하는 constitution과 템플릿이
이미 들어 있습니다. 이 단계에서 그것을 여러분의 것으로 만듭니다.

<Steps>

1. **프로젝트에 맞게 constitution을 다시 씁니다.** 코딩 에이전트에서:

   ```text
   /speckit-constitution
   ```

   프로젝트만의 원칙을 알려 주세요: 아키텍처, 데이터 모델, 보안 기본값, 코드
   컨벤션. [Discava의 constitution](../../discava/constitution-and-guidance/)이 완전한 예시입니다. 복사한
   constitution의 다음 부분은 유지하되, 명령과 패키지 이름은 여러분의 스택에 맞게 고치세요. 나머지
   workflow가 이 부분들에 의존합니다.

   | 유지할 것 | 복사한 constitution의 위치 | 이유 |
   | --- | --- | --- |
   | 단위 테스트, invariant, e2e 테스트는 필수이며, 테스트는 명세다 | III. Layered Tests | 에이전트가 CI를 초록색으로 만들려고 테스트를 약화시킬 수 없습니다 |
   | 모든 것이 클라우드 계정 없이 `pnpm dev`로 실행된다 | II. Everything Runs Locally | 그래야 PR CI가 e2e 스위트를 실행해 에이전트에게 실제 피드백을 줄 수 있습니다 |
   | 에이전트는 자신의 브랜치와 PR에서 구현하고, 로컬 스택을 실행하지 않으며, 그것이 필요한 task는 **(human)**으로 표시한다 | Development Workflow | 에이전트에게는 Docker가 없습니다. 에이전트가 실행할 수 없는 것은 CI가 실행합니다 |
   | PR CI가 관문이다. 에이전트는 절대 merge하거나, `main`에 push하거나, CI workflow를 수정하거나, 테스트를 약화시키지 않는다 | Development Workflow | 에이전트를 자기 영역 안에 머물게 하는 것 |

2. **`tasks-template.md`의 패키지 경로를 바꿉니다.** 테스트 task가 이 저장소의 패키지를 가리킵니다:
   `packages/notes-table/src/helpers/invariants/`와 `@agentic-sdlc/e2e`. 여러분의 패키지를 가리키게
   하세요. 템플릿의 나머지는 그대로 두세요: **Read by automation** 아래의 형식 규칙, **(human)** 표시,
   필수 테스트, 기존 테스트를 수정하지 말라는 메모는 Agent Issues workflow와 `Tasks format` 검사가
   의존하는 것들입니다.

3. `spec-template.md`의 **상위 issue 줄을 유지**합니다.

   ```markdown
   **Parent issue**: [#<number>, or "none" if there is no tracking issue]
   ```

   Agent Issues는 이 줄을 바탕으로 각 issue에 `Refs #<parent>`를 씁니다.

</Steps>

## 동작 확인

작은 기능으로 버릴 spec과 task를 생성합니다. 그런 다음 glue가 준비되면
([5단계](../glue-scripts/)):

```bash
pnpm nx run @your-scope/tooling-agent:validate-tasks
```

```text
1 tasks.md file(s) are in the expected format.
```

확인이 끝나면 버릴 spec 폴더를 삭제합니다.

<Aside type="caution">
`/speckit-tasks`는 가끔 `### Phase 2`라고 쓰거나 task를 들여씁니다. 그것이 바로 validator가 잡아내는
것이므로 validator를 느슨하게 만들지 마세요. 생성된 파일이 통과할 때까지 템플릿 문구를 고치세요.
</Aside>
