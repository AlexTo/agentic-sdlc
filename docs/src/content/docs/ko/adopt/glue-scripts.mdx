import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**결과:** Nx target 여섯 개와 통과하는 단위 테스트 143개가 있는 `common-scripts` 프로젝트.
6단계와 7단계의 workflow는 이 target만 호출합니다.

<Steps>

1. **프로젝트를 만듭니다.** 이 저장소에서 `packages/common/scripts/`를 복사하고 (그 안의
   `package.json`, `project.json`, `tsconfig*.json`, `vitest.config.mts`), 예제 앱에 속하는
   `src/dynamodb/`는 삭제합니다. `package.json`과 `project.json`, 그리고 `vitest.config.mts`의 `name`에서
   이름을 `@your-scope/common-scripts`로 바꿉니다. 직접 생성하고 싶다면 Nx Plugin for AWS로 생성한
   TypeScript 프로젝트도 같은 구조입니다.

2. 이 저장소의 `packages/common/scripts/src/`에서 **glue 폴더 네 개를 복사**합니다.

   <FileTree>
   - packages/common/scripts/src/
     - agent-issues/ spec → issue: gate, discover, tasks, validate, issue, plan-issue, create-next-issue, main, validate-main, 그리고 archive용 archive, archive-specs, archive-main
     - agent-ci/ CI → 에이전트: plan, run, main
     - agent-review/ 리뷰 → 에이전트: plan, run, main
     - ui-screenshots/ 스크린샷 규칙: check, main
   </FileTree>

   이 폴더들은 Node 내장 모듈과 `gh` CLI에만 의존합니다. `tsx`가 이들을 실행합니다.

3. 프로젝트의 `project.json`의 `targets` 아래에 **target을 추가**합니다.

   ```json
   "agent-issue":         { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-issues/main.ts",    "cwd": "{projectRoot}" } },
   "archive-specs":       { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-issues/archive-main.ts", "cwd": "{projectRoot}" } },
   "agent-ci-status":     { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-ci/main.ts",        "cwd": "{projectRoot}" } },
   "agent-review-status": { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-review/main.ts",    "cwd": "{projectRoot}" } },
   "ui-screenshots":      { "executor": "nx:run-commands", "options": { "command": "tsx src/ui-screenshots/main.ts",  "cwd": "{projectRoot}" } },
   "validate-tasks":      { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-issues/validate-main.ts", "cwd": "{projectRoot}" } }
   ```

4. [개요](../overview/)의 결정 중 바꾼 것이 있다면 **여러분의 설정에 맞게 상수를
   바꿉니다**.

   | 상수 | 파일 | 기본값 |
   | --- | --- | --- |
   | `SPEC_READY_LABEL`, `AGENT_BRANCH_PREFIX` | `agent-issues/gate.ts` | `spec-ready`, `openhands/` |
   | `AGENT_LABEL` | `agent-issues/issue.ts` | `openhands` |
   | `AGENT_BRANCH`, `REVIEW_STATUS_CONTEXT`, `MAX_CI_FIX_ATTEMPTS` | `agent-ci/plan.ts` | `^openhands\/issue-\d+$`, `software-factory/review`, `5` |
   | `MAX_REVIEW_FIX_ATTEMPTS`, `CHANGES_REQUESTED` | `agent-review/plan.ts` | `5`, `🔄 CHANGES REQUESTED` |
   | `UI_SOURCE`, `SCENARIO`, `WAIVER_LABEL` | `ui-screenshots/check.ts` | portal과 공유 UI의 `.tsx`/`.css`, `packages/e2e/src/scenarios/*.e2e.ts`, `no-ui-screenshots` |

   거의 확실히 바꾸게 될 것은 `UI_SOURCE`입니다. frontend 소스를 가리키도록 하세요.

   <Aside type="caution">
   `REVIEW_STATUS_CONTEXT`는 바꾸지 마세요. `software-factory/review`는 OpenHands
   issue-to-PR worker가 찾는 상태입니다. 다른 이름이면 에이전트가 절대 되돌아가지 않습니다.
   </Aside>

5. **테스트를 실행합니다.**

   ```bash
   pnpm nx run @your-scope/common-scripts:test
   ```

</Steps>

## Dry run 해 보기

세 개의 에이전트 script는 각각 `GITHUB_EVENT_PATH`에서 GitHub event를 읽고,
`DRY_RUN=true`이면 실행하는 대신 결정을 출력합니다. 실제 사례를 재현하려면 지난 workflow 실행의
payload를 저장하고 script가 그것을 가리키게 하세요.

```bash
DRY_RUN=true GITHUB_REPOSITORY=owner/repo GITHUB_EVENT_PATH=./event.json \
  pnpm nx run @your-scope/common-scripts:agent-ci-status
```

```json
{
  "pullRequest": 470,
  "plan": {
    "action": "send-back",
    "attempt": 1,
    "label": "ci-fix-1",
    "description": "CI failed (fix attempt 1 of 5): E2E tests (4/4)"
  }
}
```
