그럴 수 없을 때를 위한 것입니다: 기존 제품 저장소가 있고, 거기에 같은 설정을 원하는 경우입니다.

각 단계는 이 저장소에서 복사한 구성 요소 하나를 추가하고, 확인하는 방법을 알려 줍니다. 모두
끝내면 여러분의 저장소에는 fork에 있는 것이 갖춰지며,
[2. 저장소 설정하기](../../setup/github-repository/)부터 이어서 진행합니다.

<Aside type="tip">
그래도 이 저장소를 fork해서 노트 앱으로 [첫 기능](../../setup/first-feature/)을 먼저 실행해 보세요.
전체 루프가 한 번 동작하는 것을 보고 나면 여기의 각 단계를 훨씬 쉽게 따라갈 수 있습니다.

## 먼저 정할 것

| 결정 | 기본값 | 바꿔야 하는 경우 |
| --- | --- | --- |
| 구현용 trigger label | `openhands` | 이미 그 label을 쓰고 있을 때 |
| Branch prefix | `openhands/issue` | 거의 없습니다. glue는 정확히 `openhands/issue-<n>`과 일치하는지 봅니다. 바꾼다면 `AGENT_BRANCH`와 workflow 조건도 바꾸세요 |
| 리뷰 label | `openhands-review` | 위와 같습니다 |
| Polling 간격 | 5분마다 | 비용을 줄이고 더 오래 기다릴 수 있을 때 (catalog 기본값은 15) |
| 최대 수정 시도 | 루프당 5회 | 거의 없습니다. 두 `plan.ts` 파일의 `MAX_*_FIX_ATTEMPTS`입니다 |
| Spec 폴더 번호 매기기 | timestamp | spec 작성자가 둘 이상이라면 절대 바꾸지 마세요 |

모든 명령과 복사한 파일에서 `@your-scope` 또는 `@agentic-sdlc`를 여러분 workspace의
npm scope로 바꾸세요.
