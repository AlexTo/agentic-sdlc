import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**결과:** 저장소의 `.specify/`, 코딩 에이전트에서 사용할 수 있는 `speckit-*` 명령,
그리고 timestamp로 이름이 붙는 spec 폴더.

<Steps>

1. Discava가 쓰는 버전으로 고정해 **CLI를 설치**합니다.

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. 이 저장소에서 **`.specify/`를 복사**합니다. workflow에 필요한 방식으로 이미 설정되어 있습니다.

   | 설정 | 위치 | 값 |
   | --- | --- | --- |
   | timestamp로 이름이 붙는 spec 폴더 | `extensions/git/git-config.yml` | `branch_numbering: timestamp`. 두 사람이 동시에 spec을 작성해도 충돌하지 않습니다: `specs/001-course-reviews/`가 아니라 `specs/20261116-013307-course-reviews/` |
   | 각 step마다 conventional commit | `extensions/git/git-config.yml` | `commit_style: conventional` |
   | git extension의 hook이 묻지 않고 실행됨 | `extensions.yml` | `auto_execute_hooks: true`: `/speckit-specify` 전에 브랜치 생성, 모든 step 후에 커밋 |
   | 템플릿과 constitution | `templates/`, `memory/` | [3단계](../constitution-and-templates/)의 변경 사항이 이미 들어 있음 |

3. **코딩 에이전트용 명령을 추가**합니다. 에이전트가 Claude Code skill을 읽는다면 이 저장소의
   `.claude/skills/speckit-*`를 복사하세요. 그렇지 않다면 임시 폴더에서 Speckit이 여러분의 에이전트용
   명령을 작성하게 하고, 명령 파일만 복사합니다.

   ```bash
   mkdir /tmp/speckit && cd /tmp/speckit
   specify init --here --integration <your-agent> --script sh --extension git
   ```

   integration 목록은 `specify init --help`로 확인하세요. 에이전트의 명령용으로 만들어진 폴더를
   복사하고, `.specify/`는 복사하지 마세요. 그러면 2단계가 되돌려집니다.

4. **`.specify/`를 커밋**하고, 명령 파일이나 skill 파일도 커밋합니다.

</Steps>

## 동작 확인

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, 명령, script
  - extensions.yml
  - init-options.json
  - memory/constitution.md 노트 앱의 것이며, 다음 단계에서 여러분의 것으로 다시 씁니다
  - scripts/bash/
  - templates/ spec, plan, tasks, checklist, constitution 템플릿
</FileTree>

코딩 에이전트에 `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`,
`speckit-analyze`, `speckit-constitution` 명령이 나열됩니다.

<Aside type="tip">
spec PR은 `openhands/...`가 아니라 자체 브랜치 (`spec/<name>`)에 올립니다. git extension의 기능
브랜치를 그 용도로 써도 됩니다. `openhands/` prefix는 에이전트의 브랜치만 씁니다.
</Aside>
