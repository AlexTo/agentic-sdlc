import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**결과:** 저장소의 `.specify/`, 코딩 에이전트에서 사용할 수 있는 `speckit-*` 명령,
그리고 timestamp로 이름이 붙는 spec 폴더.

<Steps>

1. Discava가 쓰는 버전으로 고정해 **CLI를 설치**합니다.

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. 번들된 git extension과 함께, 코딩 에이전트용으로 **저장소에서 초기화**합니다.
   Discava는 명령을 skill로 설치하는 `claude` integration을 사용했습니다.

   ```bash
   specify init --here --integration claude --script sh --extension git
   ```

   다른 integration을 보려면 `specify init --help`를 실행하세요. 팀의 에이전트가 읽는 것을 고르세요.

3. **timestamp 번호 매기기로 바꿉니다.** `.specify/extensions/git/git-config.yml`에서:

   ```yaml
   branch_numbering: timestamp
   commit_style: conventional
   ```

   폴더 이름이 `specs/001-course-reviews/` 대신 `specs/20261116-013307-course-reviews/`가 되므로,
   두 사람이 동시에 spec을 작성해도 충돌하지 않습니다.

4. `.specify/extensions.yml`에서 **git extension의 hook을 확인**합니다. Discava는 기본값을 유지합니다:
   `/speckit-specify` 전에 `speckit.git.feature` (브랜치 생성), 그리고 모든 step 후에
   `speckit.git.commit` (step당 커밋 하나). 묻지 않고 실행되도록 `auto_execute_hooks: true`를 설정합니다.

5. **`.specify/`를 커밋**하고, integration의 명령 파일이나 skill 파일도 커밋합니다.

</Steps>

## 동작 확인

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, 명령, script
  - extensions.yml
  - init-options.json
  - memory/constitution.md 아직 템플릿이며, 다음 단계에서 채웁니다
  - scripts/bash/
  - templates/ spec, plan, tasks, checklist, constitution 템플릿
</FileTree>

코딩 에이전트에 `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`,
`speckit-analyze`, `speckit-constitution` 명령이 나열됩니다.

<Aside type="tip">
spec PR은 `openhands/...`가 아니라 자체 브랜치 (`spec/<name>`)에 올립니다. git extension의 기능
브랜치를 그 용도로 써도 됩니다. `openhands/` prefix는 에이전트의 브랜치만 씁니다.
</Aside>
