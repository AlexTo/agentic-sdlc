**결과:** Nx와 Biome가 있고, 모든 커밋에 Conventional Commits가 강제되며, 매 커밋 전에
secret 검사를 하는 pnpm workspace.

glue는 Nx가 필요하지 않습니다. 하지만 `nx affected` 덕분에 PR 검사가 에이전트가 반복 작업할 수 있을
만큼 빨라지고, 모든 glue script는 Nx target으로 실행됩니다. 다른 monorepo 도구를 쓴다면 아이디어를
유지하세요: PR이 영향을 주는 것만 실행하고, 모든 script를 이름 있는 task로 노출합니다.

<Steps>

1. workspace가 없다면 **workspace를 만듭니다**. Discava와 이 저장소는 모두
   Nx Plugin for AWS로 만들었습니다.

   ```bash
   pnpm create @aws/nx-workspace your-project --iac=cdk --no-interactive
   ```

   기존 Nx workspace도 됩니다. CI와 에이전트가 같은 버전을 쓰도록 루트 `package.json`에
   `packageManager`로 pnpm 버전을 고정하세요.

2. 이 저장소에서 다음 **파일을 복사**해 여러분 저장소의 같은 경로에 둡니다.

   <FileTree>
   - commitlint.config.js Conventional Commits
   - lint-staged.config.js staged 파일에 Biome 실행
   - .husky/
     - commit-msg commitlint 실행
     - pre-commit git-secrets, 그다음 lint-staged를 실행하고, Biome가 무언가를 바꿨다면 실패하므로 에이전트가 다시 stage하고 다시 커밋함
     - prepare-commit-msg 대화형으로 커밋하는 사람을 위한 Commitizen. 에이전트가 커밋하는 방식인 `git commit -m`에서는 스스로 건너뜀
   - .git-secrets/ pre-commit hook이 실행하는 git-secrets script
   - .gitallowed git-secrets가 통과시키는 패턴
   - .github/
     - actions/init-monorepo/ 공유 CI 설정
     - actions/changed-paths/ job을 건너뛰기 위한 "이 PR이 이 경로들 중 하나라도 바꿨는가?"
     - actions/playwright-setup/ Playwright용 Chromium, 버전별로 캐시
     - dependabot.yml 고정된 action과 의존성을 최신으로 유지
   </FileTree>

   `.husky/pre-push`는 [8단계](../local-stack-and-e2e/)까지 남겨 두세요: invariant 맵을 검사하는
   hook입니다. `init-monorepo`는 pnpm을 설치하고 (registry timeout이 나면 에이전트가 수정 시도 한 번을
   잃게 되므로 세 번 시도합니다), Node 24와 선택적으로 uv를 설치하고, pnpm과 Nx 캐시를 복원하고,
   의존성을 설치하고, `nx affected`를 위해 `NX_BASE`/`NX_HEAD`를 설정합니다.

3. 이 저장소의 `package.json`에서 **루트 script와 dev 의존성을 복사**합니다: `scripts` 블록
   (`AGENTS.md`, CI, 에이전트가 호출함), 그리고 `devDependencies`에서
   `@commitlint/config-conventional`, `commitlint`, `commitizen`, `husky`, `lint-staged`. 그다음:

   ```bash
   pnpm install
   ```

   `prepare` script가 hook을 설치합니다.

4. `.github/actions/playwright-setup/action.yml`의 **패키지 scope**(`@agentic-sdlc/e2e`)를
   여러분의 e2e 프로젝트 이름으로 바꿉니다.

</Steps>

## 동작 확인

```bash
git commit --allow-empty -m "not conventional"
```

```text
⧗   input: not conventional
✖   subject may not be empty [subject-empty]
✖   type may not be empty [type-empty]
```

그다음 `git commit --allow-empty -m "chore: check hooks"`는 성공합니다.

<Aside type="note">
glue가 작성하는 issue 제목은 Conventional Commit header이고, 에이전트는 이를 커밋과 pull request에
재사용합니다. commitlint가 가장 먼저 오는 이유입니다.
</Aside>
