Discava의 에이전트는 Linux 워크스테이션 한 대에서 OpenHands Agent Canvas로 실행됩니다. OpenHands의 클라우드 배포도,
webhook도 없습니다. 모든 것이 GitHub를 향한 아웃바운드 폴링입니다.

## Agent Canvas

Agent Canvas 1.45.0, npm(`@openhands/agent-canvas`)에서 설치하고 사용자 서비스로 실행합니다. 상태는
`~/.openhands/`에 있습니다. 설정, agent profile, secret, automation의 SQLite 데이터베이스입니다.

## 대화 설정

에이전트의 작업 방식을 결정하는 설정입니다.

| 설정 | 값 | 이유 |
| --- | --- | --- |
| Agent | ACP, 서버 `claude-code` | Agent Client Protocol을 통한 외부 코딩 에이전트 |
| ACP prompt timeout | 30분 | 구현 턴은 깁니다 |
| Max iterations | 500 | 대화 하나에서 phase 전체를 처리할 여유 |
| Confirmation mode | off | 무인 실행. 확인해 줄 사람이 없습니다 |
| Security analyzer | LLM | 명령은 여전히 위험성을 검사받습니다 |
| Runtime | local | Node, pnpm, git이 이미 있는 호스트에서 실행됩니다 |
| Worktree branch prefix | `openhands/` | 에이전트가 만드는 모든 브랜치는 이것으로 시작합니다. glue는 이를 기준으로 동작합니다 |

## Agent profile

에이전트 역할마다 profile이 하나씩 있습니다.

| Profile | 역할 | 에이전트 | 모델 | 사용처 |
| --- | --- | --- | --- | --- |
| `developer` | 개발자 | Claude Code (ACP) | Sonnet | GitHub issue to PR |
| `reviewer` | 리뷰어 | Claude Code (ACP) | Opus | GitHub code review |
| `tester` | 테스터 | Claude Code (ACP) | Opus | GitHub issue tester |

각각 프롬프트 타임아웃은 30분입니다.

## Secret

Agent Canvas(**Settings → Secrets**)에 이름으로 저장됩니다.

| 이름 | 용도 |
| --- | --- |
| `GITHUB_PERSONAL_ACCESS_TOKEN` | 이름과 달리 GitHub App의 현재 installation token입니다. automation이 이것으로 GitHub를 읽습니다. 대화는 clone, push, PR 열기, 리뷰, 댓글 달기를 위해 이를 받습니다 |
| `OPENHANDS_AUTOMATION_API_KEY` | automation 백엔드 자체의 키 |
| `DISCAVA_STUDENT_USERNAME`, `DISCAVA_STUDENT_PASSWORD` | `discava-development`에 있는 테스터의 학생 사용자 |
| `DISCAVA_INSTRUCTOR_USERNAME`, `DISCAVA_INSTRUCTOR_PASSWORD` | 테스터의 강사 사용자 |
| `DISCAVA_ADMIN_USERNAME`, `DISCAVA_ADMIN_PASSWORD` | 테스터의 관리자 사용자 |

여섯 개의 `DISCAVA_*` secret은 development stage의 Cognito 테스트 사용자로, 앱의 역할마다 하나씩입니다. 테스터는
이들로 포털에 로그인하고 API 토큰을 받습니다.

## GitHub App

에이전트는 `AlexTo/discava`에만 설치된 GitHub App `alex-coding-agent`로 동작하므로, 에이전트가 열고 push하고
말하는 모든 것이 `alex-coding-agent[bot]`으로 표시됩니다. webhook은 없고, contents, issues, pull requests에 대한
읽기와 쓰기 권한이 있습니다.

2026년 11월 25일까지 에이전트는 classic personal access token을 가진 머신 계정 `discava-bot`으로 일했습니다.
GitHub가 이 계정에 플래그를 달았고, 그 결과 이 계정의 issue와 pull request 210개 모두가 계정 자신의 목록을
포함해 모든 사람에게서 숨겨졌습니다. 열려 있던 issue 44개와 pull request 11개는 앱으로 다시 열었고(#1129–#1183),
원본은 각 사본으로 가는 링크와 함께 닫았습니다. merge된 작업은 여전히 `main`에 있으며, 작성자는 `discava-bot`입니다.

installation token은 한 시간 동안 유효하므로, 앱의 private key는 Agent Canvas 밖의 머신에 두고 타이머가 이를
토큰으로 바꿉니다.

| 구성 요소 | 하는 일 |
| --- | --- |
| `~/.ssh/alex-coding-agent.pem` | 앱의 private key: 유일하게 오래 유지되는 secret |
| `alex-coding-agent-token.timer` | 발급 스크립트를 45분마다, 그리고 부팅 1분 후에 한 번 실행하는 systemd 사용자 타이머 |
| 발급 스크립트 | 템플릿의 [`scripts/agent-app-token.sh`](https://github.com/AlexTo/agentic-sdlc/blob/main/scripts/agent-app-token.sh)가 그 사본입니다. key로 JSON Web Token에 서명하고, 이를 installation token으로 교환해 소유자만 읽을 수 있는 파일에 쓰고, Agent Canvas 자체 API를 통해 `GITHUB_PERSONAL_ACCESS_TOKEN` secret에 넣습니다 |
| `canvas.service`용 drop-in | Agent Canvas가 시작되기 전에 발급 스크립트를 실행하고, `GIT_AUTHOR_*`와 `GIT_COMMITTER_*`를 `alex-coding-agent[bot]`과 그 noreply 주소로 설정하며, Agent Canvas에 자체 `GIT_CONFIG_GLOBAL`과 토큰 파일을 읽는 `gh`를 줍니다 |

그래서 대화형 대화는 git과 `gh`를 통해, automation은 secret을 통해 앱을 사용합니다. 여러분의 터미널은 여러분의
로그인을 그대로 유지합니다. 커밋을 앱의 것으로 만드는 것은 drop-in의 환경 변수입니다. automation 템플릿은 각
checkout에 작성자로 `OpenHands`를 쓰고, Agent Canvas의 **Git Settings** 양식은 대괄호가 들어간 이메일을 거부하므로,
Discava는 bot의 이름과 주소를 `~/.openhands/settings.json`에도 직접 써 넣었습니다.

bot이 아니라 메인테이너로 동작하던 남은 것 두 가지는 제거했습니다. 메인테이너의 토큰을 가진 GitHub MCP
서버(`api.githubcopilot.com`)와 예전 personal access token입니다.

glue는 repository 변수 `AGENT_APP_LOGIN`(`alex-coding-agent[bot]`)으로 앱의 리뷰를 셉니다. GitHub는 앱에
repository와의 association을 주지 않으므로, 이것이 없으면 리뷰어의 판정이 더 이상 개발자를 되돌려 보내지 못합니다
([#1184](https://github.com/AlexTo/discava/pull/1184)).

## 테스터가 컴퓨터에 갖고 있는 것

개발자 에이전트와 리뷰어 에이전트에게는 Node, pnpm, git, `gh`만 있으면 됩니다. 테스터는 다음도 사용합니다.

| 도구 | 용도 |
| --- | --- |
| `discava-development-*` 스택이 있는 계정에 로그인된 AWS CLI | stage 찾기(스택 output), Cognito 토큰 받기, DynamoDB, S3, CloudWatch 로그 읽기. 프롬프트는 이를 읽기 전용으로 쓰라고 지시합니다 |
| Playwright와 Chromium | 배포된 포털 조작 |
| Discava checkout의 `tmp/screenshots/` | 스크린샷이 저장되는 곳, pull request마다 폴더 하나 |

<Aside type="caution">
Discava에서 에이전트가 클라우드 접근 권한을 가지고 일하는 곳은 여기 하나뿐입니다. stage가 버려도 되는 데이터를 가진
`discava-development`인 이유이자, 에이전트가 읽는 것에
[collaborator만 댓글을 달 수 있는](../post-merge-verify/#누가-댓글을-달-수-있나) 이유입니다.
팀이라면 테스터에게 자체 읽기 전용 role과 자체 컴퓨터나 VM을 주세요.
</Aside>

## 세 automation

앞의 둘은 직접 작성한 것이 아니라 Agent Canvas automation 카탈로그에서 설치했습니다. 세 번째는 Discava가 직접
만든 것입니다. 각각이 폴링 때 하는 일은 [에이전트 런타임](../../concepts/the-agent-runtime/#세-가지-automation)에
있고, 각각이 에이전트에게 주는 프롬프트는 [에이전트 프롬프트](../agent-prompts/)에 있습니다.

### 개발자: GitHub issue to PR

| 필드 | 값 |
| --- | --- |
| Template | `github-issue-to-pr` 1.2.4 |
| Repository | `AlexTo/discava` |
| Trigger label | `openhands` |
| Branch prefix | `openhands/issue` → 브랜치 `openhands/issue-<n>` |
| Pull request mode | Ready for review |
| GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
| Schedule | `*/2 * * * *`, Australia/Sydney |
| Agent profile | `developer` |

revise 턴은 에이전트에게 끝난 뒤 `openhands-review` label을 다시 붙이라고 지시하므로, 새 head가 리뷰됩니다.

### 리뷰어: GitHub code review

| 필드 | 값 |
| --- | --- |
| Template | `github-pr-reviewer` 1.11.2, 앱의 토큰에 맞게 패치함(아래 참조) |
| Repository | `alexto/discava` |
| Trigger label | `openhands-review` |
| Requested reviewer | `all-hands-bot` (실제로는 쓰이지 않음: label이 그 일을 합니다) |
| New reviews per scan | 2 |
| Review tone | Concise |
| Maintainers | 없음 |
| Schedule | `*/2 * * * *`, Australia/Sydney |
| Agent profile | `reviewer` |

이 템플릿은 자신이 어떤 계정으로 동작하는지 `GET /user`로 묻는데, GitHub는 installation token에 대해 이를
`403 Resource not accessible by integration`으로 거부합니다. 그래서 앱으로 바꾼 뒤 모든 스캔이 리뷰하기 전에
실패했습니다. Discava의 사본은 worker의 로그인 조회와 토큰 검사 모두에서 `/user`가 거부하면 GraphQL
`viewer { login }`에 묻도록 바꾸었고, 카탈로그의 번들 대신 다시 업로드했습니다. 카탈로그의 1.11.3에도 여전히 이
문제가 있습니다.

검사가 아직 실행 중이면 리뷰어는 "⏳ Review waiting on checks" 댓글을 남기고 이후 스캔에서 다시 시도합니다. 리뷰어의
리뷰는 "_This review was posted by an AI agent (OpenHands)._"로 시작하며, 숨겨진
`<!-- openhands-review-run: <id> -->` 마커를 담고 있습니다.

### 테스터: GitHub issue tester

이것을 위한 카탈로그 템플릿은 없습니다. 카탈로그 템플릿이 쓰는 것과 같은 GitHub helper와 대화 helper 위에 만든
약 백 줄짜리 worker이며, 프롬프트는 그 옆의 파일에 있습니다.

| 필드 | 값 |
| --- | --- |
| Template | 없음: 직접 작성한 `worker.py`, `prompt.md`, `config.json` |
| Repository | `AlexTo/discava` |
| Trigger label | `openhands-test` |
| Issue authors | `github-actions[bot]` |
| Branch prefix | `openhands/test-fix` → 수정 브랜치 `openhands/test-fix-<n>` |
| New tests per scan | 2 |
| Prompt file | `prompt.md` |
| GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
| Schedule | `*/2 * * * *`, Australia/Sydney |
| Agent profile | `tester` |

폴링할 때마다 worker는 다음을 합니다.

1. `openhands-test`가 붙은 열린 issue를 번호가 낮은 것부터 나열합니다.
2. **issue authors** 중 하나가 열지 않은 issue는 건너뜁니다. issue의 본문은 에이전트가 읽는 것의 일부가 되므로,
   workflow 자체의 issue만 테스트합니다.
3. label을 붙인 가장 최근 이벤트를 찾습니다. issue 번호와 그 이벤트의 ID가 하나의 전달 단위를 이루므로, 같은 label
   부착에 대한 이후의 폴링은 무시되고, 테스터 자신의 댓글이 두 번째 테스트를 시작하는 일도 없습니다. label을
   제거했다가 다시 붙이면 새 이벤트이고, 따라서 새 테스트입니다.
4. 프롬프트와 함께 issue의 대화를 시작하거나 재개합니다. 폴링당 새 테스트는 최대 두 개입니다.

worker가 폴링하는 issue는 [Post-merge Verify](../post-merge-verify/)가 엽니다. 테스터의 댓글은
"_This comment was posted by an AI agent (OpenHands)._"로 끝납니다.

<Aside title="에이전트용 신원 하나">
Discava에서는 개발자 에이전트, 리뷰어 에이전트, 테스터 에이전트가 모두 `alex-coding-agent[bot]`으로 동작하고,
메인테이너는 자신의 계정을 사용합니다. 그래서 메인테이너는 에이전트의 PR을 평소처럼 승인할 수 있고, 어떤 댓글이
에이전트에게서 왔는지 알 수 있습니다. 리뷰어와 개발자는 여전히 그 신원을 공유하고, GitHub는 누구도 자기 PR을
승인하도록 허용하지 않으므로, 리뷰어의 판정은 `COMMENTED` 리뷰로 게시됩니다. glue는 리뷰 상태가 아니라 판정 줄을 읽으므로 문제가
되지 않습니다.
</Aside>
