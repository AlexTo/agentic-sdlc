이 저장소가 *곧* 워크플로입니다. Discava가 실행하는 것과 같은 Speckit 설정, issue 템플릿, PR 검사, 에이전트
workflow, 단위 테스트를 갖춘 glue가 작은 노트 앱을 감싸고 있습니다.

**fork하면 Discava의 설정을 얻습니다.** 여러분의 OpenHands가 fork를 가리키게 하고, 노트 앱에 대한 spec을
작성하면, [동작 방식](../how-it-works/)에서 설명하는 루프를 거칩니다.

## 얻는 것

<FileTree>
- AGENTS.md 모든 에이전트가 가장 먼저 읽는 파일, 노트 앱에 맞춰 작성됨
- .specify/ Speckit 템플릿, 스크립트, constitution
- .husky/ 커밋 시 Conventional Commits, secret 스캔, Biome, push 시 invariant 맵
- scripts/
  - setup-repository.sh label, branch protection, 그리고 fork가 복사하지 않는 그 밖의 설정
  - start-agent-canvas.mjs 에이전트의 GitHub App으로 Agent Canvas를 시작하고 토큰을 새로 유지
- .github/
  - ISSUE_TEMPLATE/
    - implement-phase.md 모든 구현 issue에 담기는 지시 사항
    - test-deployed-pr.md 테스터 에이전트를 위한 테스트 issue, 직접 작성
  - actions/ 공유 CI 설정, Playwright의 Chromium, 변경 경로 검사
  - dependabot.yml 고정된 action과 의존성을 최신으로 유지
  - workflows/
    - pr-checks.yml lint, test, build, tasks 형식, invariant 커버리지, e2e, 스크린샷 댓글
    - ui-screenshots.yml 스크린샷 규칙
    - ci.yml main에서의 검사, Trivy, 문서 배포
    - agent-issues.yml spec → issue, merge → 다음 issue
    - archive-specs.yml 완료된 spec → 아카이브 PR
    - agent-ci.yml 빨간 CI → 에이전트
    - agent-review.yml "changes requested" → 에이전트
    - agent-status.yml 위 두 workflow가 공유하는 step
    - deploy.yml 초록색 main → stage, 인프라를 추가하기 전까지는 꺼져 있음
    - post-merge-verify.yml 배포된 PR → 테스터를 위한 테스트 issue
    - cache-cleanup.yml 닫힌 PR의 캐시 정리
- packages/
  - tooling/agent/ glue의 규칙, 단위 테스트 223개
  - tooling/local-dev/ `pnpm dev`용 DynamoDB local 시작
  - notes-table/ ElectroDB 엔터티, DynamoDB local, invariant
  - notes-api/ tRPC 프로시저
  - notes-website/ React, Vite, TanStack Router, shadcn/ui
  - e2e/ Playwright 시나리오, `screenshot()` 헬퍼, 모든 테스트 후의 invariant 검사
- docs/ 이 사이트
</FileTree>

노트 앱은 완전히 로컬에서 실행되므로(`pnpm dev`, DynamoDB local용 Docker 포함), CI가 e2e 테스트를 실행할 수
있고 에이전트에게는 클라우드 자격 증명이 전혀 필요 없습니다.

## 추가해야 하는 것

저장소에 담을 수 없는 것만 추가하면 됩니다.

1. **GitHub 설정**: 에이전트가 동작하는 GitHub App, 그리고 fork가 복사하지 않는 설정.
   설정은 `scripts/setup-repository.sh`가 한 번의 실행으로 적용합니다.
2. **OpenHands**: `pnpm agent-canvas`로 앱으로서 시작하는 여러분 컴퓨터의 Agent Canvas,
   그리고 fork를 가리키는 automation.

## 추가하기 전까지 꺼져 있는 것

클라우드입니다. 노트 앱에는 클라우드 인프라가 없으므로, merge해도 문서 사이트 외에는 아무것도
배포되지 않습니다. `deploy.yml`과 `post-merge-verify.yml`은 들어 있지만 저절로 실행되지는 않습니다:
`packages/infra`에 CDK 앱을 추가하고 `AUTO_DEPLOY_STAGE`를 설정하면, 초록색 `main`마다 배포되고
테스터 에이전트가 배포된 것을 테스트합니다. [도입: 배포](../../adopt/deploy/)에 단계가 있고,
[배포와 보안](../../discava/deploy-and-security/)에서 Discava의 파이프라인을 설명합니다.
