| 용어 | 의미 |
| --- | --- |
| **ACP** | Agent Client Protocol. OpenHands가 Claude Code 같은 외부 코딩 에이전트를 구동하는 방식 |
| **Agent Canvas** | 직접 호스팅하는 OpenHands 앱: agent server, automation backend, web UI |
| **Agent profile** | 대화가 사용할 에이전트와 model을 지정하는 OpenHands 설정 |
| **`AGENTS.md`** | 저장소 루트에 있는 에이전트 가이드 파일: 명령, 아키텍처, 컨벤션 |
| **Automation** | GitHub를 읽고 에이전트 대화를 시작하는, 일정에 따라 실행되는 OpenHands worker |
| **Constitution** | `.specify/memory/constitution.md`. 모든 plan을 대조해 확인하는 프로젝트 규칙 |
| **Constitution Check** | plan을 constitution과 대조해 확인하는 `plan.md`의 섹션 |
| **수정 시도** | 에이전트를 되돌려 보내는 자동 라운드 한 번. `ci-fix-<n>` 또는 `review-fix-<n>`으로 셉니다 |
| **Glue** | Speckit, OpenHands, CI 사이에서 작업을 넘겨주는 workflow와 script |
| **그룹** | 하나의 구현 issue가 다루는 phase들. 그룹 0은 첫 번째 user story까지입니다 |
| **사람 게이트** | 사람만 내리는 결정: spec 승인, PR 승인, production 배포 |
| **(human) task** | 사람이나 실행 중인 스택이 필요한 `tasks.md`의 task. 에이전트는 건너뜁니다 |
| **Invariant** | 모든 데이터에 대한 규칙으로, 매 e2e 테스트 이후 확인합니다 |
| **마커** | glue가 자신의 issue와 댓글을 찾는 데 쓰는 숨겨진 HTML 주석 |
| **상위 issue** | 기능의 추적 issue로, `spec.md`에 명시되고 모든 PR이 참조합니다 |
| **Phase** | `tasks.md`의 `## Phase <n>: <title>` 섹션 |
| **revise 턴** | 기존 에이전트 대화에 PR을 고치라고 요청하는 메시지 |
| **spec 폴더** | 하나의 기능의 spec, plan, task를 담은 `specs/<timestamp>-<name>/` |
| **`software-factory/review`** | `failure` 상태일 때 OpenHands가 PR을 수정하게 만드는 commit status |
| **Speckit** | GitHub의 spec 중심 개발 toolkit (`specify-cli`) |
| **멈춘 그룹** | issue는 있지만 task가 모두 체크되지 않아 새 issue가 열리지 않는 그룹 |
