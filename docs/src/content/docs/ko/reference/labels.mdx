`scripts/setup-repository.sh`가 이 label을 모두 만듭니다.
[2. 저장소 설정하기](../../setup/github-repository/)를 참고하세요.

| Label | 대상 | 설정 주체 | 읽는 주체 | 의미 |
| --- | --- | --- | --- | --- |
| `spec-ready` | Spec PR | 사람 | Agent Issues | 이 PR을 merge하면 구현이 시작됩니다. 이미 merge된 PR에 추가해도 마찬가지입니다 |
| `openhands` | Issue | Agent Issues 또는 사람 | Issue-to-PR automation (개발자) | 이 issue를 구현합니다. 제거했다가 다시 붙이면 새 브랜치에서 처음부터 다시 시도합니다 |
| `openhands-review` | PR | 개발자 에이전트, PR을 열거나 수정한 뒤 | Code review automation (리뷰어) | 이 PR의 현재 head를 리뷰합니다 |
| `openhands-test` | Issue | Post-merge Verify 또는 사람 | Issue tester automation (테스터) | 이 issue가 지정한 merge된 pull request를 배포된 개발 stage에서 테스트합니다. 제거했다가 다시 붙이면 다시 테스트합니다 |
| `skip-deploy-test` | PR | 사람 | Post-merge Verify | 이 pull request가 배포될 때 테스트 issue를 열지 않습니다 |
| `ci-fix-1` … `ci-fix-5` | 에이전트 PR | Agent CI Status | Agent CI Status | 빨간 CI에 대한 자동 수정을 그 횟수만큼 사용했습니다 |
| `ci-fix-exhausted` | 에이전트 PR | Agent CI Status | Agent CI Status, 사람 | CI 수정을 모두 사용했습니다. 사람이 넘겨받습니다 |
| `review-fix-1` … `review-fix-5` | 에이전트 PR | Agent Review Status | Agent Review Status | "changes requested"에 대한 수정을 그 횟수만큼 사용했습니다 |
| `review-fix-exhausted` | 에이전트 PR | Agent Review Status | Agent Review Status, 사람 | 리뷰 수정을 모두 사용했습니다. 사람이 넘겨받습니다 |
| `no-ui-screenshots` | PR | maintainer | UI Screenshots | 스크린샷 규칙을 면제합니다: UI 변경에 볼 것이 없습니다. 추가한 뒤 검사를 다시 실행합니다 |
| `no-new-invariant` | PR | maintainer | PR Checks (`Invariant coverage`) | invariant 커버리지 규칙을 면제합니다: 새 writer에 걸치는 규칙이 없습니다. 추가한 뒤 검사를 다시 실행합니다 |
| `priority:high` | Issue | 사람 | Issue-to-PR automation | 같은 폴링에서 다른 issue보다 이 issue를 먼저 시작합니다 |

## 루프 초기화

가이드를 추가한 뒤 에이전트가 다시 시도하게 하려면, 카운터 label과
`*-exhausted` label을 모두 제거한 다음:

- **CI 루프:** 실패한 PR Checks 실행을 다시 실행합니다.
- **리뷰 루프:** 리뷰를 다시 요청하거나, `openhands-review`를 다시 붙입니다.

횟수는 PR에 있는 가장 큰 `*-fix-<n>` label이므로, `exhausted` label만 제거해서는
충분하지 않습니다.
