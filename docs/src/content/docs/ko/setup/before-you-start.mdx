[이 저장소의 fork](../../guides/fork-this-repo/)에는 Discava의 설정 중 저장소 안에 있는
모든 것이 들어 있습니다. 이 단계들은 저장소 밖에 있는 부분, 즉 GitHub 설정, 에이전트가 동작할
GitHub App, 그리고 fork를 가리키는 OpenHands 설치를 추가합니다. 그런 다음 노트 앱의 spec을 작성하고,
그것이 spec PR에서 merge된 에이전트 PR까지 진행되는 과정을 지켜봅니다.

**소요 시간:** 약 한 시간. 대부분은 첫 에이전트 실행을 기다리는 시간입니다.

## 필요한 것

macOS 또는 Linux에서 (Windows에서는 WSL을 사용하세요):

| 필요한 것 | 이유 |
| --- | --- |
| GitHub 계정 | fork하고, spec을 작성하고, 리뷰하기 위해 |
| 로그인된 GitHub CLI (`gh`) | 설정 스크립트와 에이전트가 사용합니다 |
| Node.js 24와 pnpm | 저장소와 Agent Canvas를 실행하기 위해 |
| `uv` | Agent Canvas는 `uvx`로 backend를 시작합니다 |
| 설치되고 로그인된 코딩 에이전트 | Speckit으로 spec을 작성하고, OpenHands 안에서 에이전트의 작업을 합니다. Discava는 Claude Code를 사용합니다 |
| Docker (선택) | 노트 앱과 e2e 테스트를 여러분의 컴퓨터에서 실행할 때만 필요합니다. 에이전트를 위해서는 CI가 실행합니다 |

<Aside type="note">
Agent Canvas는 여러분의 컴퓨터에서 실행되며 GitHub를 폴링하므로, 공개 주소나
webhook이 필요 없습니다. 에이전트는 Agent Canvas가 실행 중일 때만 작업합니다.
</Aside>

## 단계

| # | 단계 | 할 일 | 결과 |
| --- | --- | --- | --- |
| 1 | [저장소 fork하기](../fork/) | 명령 세 개 | clone된 나만의 사본 |
| 2 | [저장소 설정하기](../github-repository/) | 내용이 채워진 양식으로 GitHub App을 만들고, 스크립트 하나를 실행 | fork에 설치된 에이전트의 GitHub App, label, 보호된 `main`, collaborator로 제한된 댓글 |
| 3 | [OpenHands 설치하기](../openhands/) | 명령 두 개, 웹 UI에서 profile 두 개 | 여러분의 앱으로 실행 중인 Agent Canvas, 그리고 `developer`와 `reviewer` profile |
| 4 | [두 개의 automation 만들기](../automations/) | 웹 UI에서 양식 두 개, 붙여 넣는 prompt 하나 | fork에서 구현과 리뷰를 하는 개발자 에이전트와 리뷰어 에이전트 |
| 5 | [첫 기능 실행하기](../first-feature/) | spec을 작성하고, pull request를 리뷰 | 에이전트가 merge된 코드까지 이끌어 간 노트 앱의 spec |

대신 기존 저장소에 이 설정을 적용하고 싶다면
[여러분의 저장소에 도입하기](../../adopt/overview/)를 참고하세요.
