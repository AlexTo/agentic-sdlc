import { Steps, Aside } from '@astrojs/starlight/components';

**결과:** 여러분의 컴퓨터에서 여러분의 GitHub App으로 실행 중인 OpenHands Agent Canvas, 그리고 두 개의
agent profile: 개발자 에이전트용 `developer`와 리뷰어 에이전트용 `reviewer`.

<Steps>

1. **Agent Canvas를 설치합니다.** Discava는 버전 1.45.0을 사용합니다.

   ```bash
   npm install -g @openhands/agent-canvas
   ```

2. clone한 저장소에서 **여러분의 앱으로 시작합니다.**

   ```bash
   pnpm agent-canvas
   ```

   처음 실행할 때는 [2단계](../github-repository/)의 **App ID**와 **`.pem` 파일**의 경로를 묻고, 둘 다
   여러분만 읽을 수 있게 `~/.config/agent-app/`에 보관합니다. 그런 다음, 실행할 때마다:

   - 앱을 에이전트 커밋의 작성자로 하여 Agent Canvas를 시작하므로, GitHub가 커밋을 앱의 것으로
     표시합니다.
   - 한 시간 동안 유효한 앱의 토큰을 하나 만들어 Agent Canvas에 secret
     `GITHUB_PERSONAL_ACCESS_TOKEN`으로 저장하며, automation이 읽는 것이 이 secret입니다. 이름과 달리
     어떤 GitHub 토큰이든 그곳에 넣을 수 있습니다.
   - 실행되는 동안 45분마다 토큰을 교체합니다.

   `Token stored in the GITHUB_PERSONAL_ACCESS_TOKEN secret` 줄이 나올 때까지 기다린 뒤
   [http://127.0.0.1:8000](http://127.0.0.1:8000)을 엽니다. Agent Canvas가 어떤 에이전트를 쓸지 물으면
   Claude Code를 선택하세요. 이미 있는 로그인을 찾아내므로, API key 필드는 비워 둡니다.

   터미널을 열어 두고, Agent Canvas는 항상 이 방법으로 시작하세요. automation은 Agent Canvas가 실행
   중일 때만 폴링하고, 토큰은 이 명령이 실행되는 동안에만 새로 유지됩니다.

3. 에이전트 역할마다 하나씩, **두 개의 agent profile을 만듭니다.** Agent Canvas에서 **Settings → Agent**를
   열고 **Add agent profile**을 두 번 클릭합니다.

   | Name | Agent type | Agent | Model |
   | --- | --- | --- | --- |
   | `developer` | ACP (external subprocess) | `claude-code` | `sonnet` |
   | `reviewer` | ACP (external subprocess) | `claude-code` | `opus` |

   ACP는 Agent Client Protocol입니다. 이미 사용하는 코딩 에이전트가 이 컴퓨터에서 여러분으로 로그인한
   채로 작업을 합니다. 어떤 에이전트와 model이든 동작합니다. 리뷰어 에이전트는 최소한 개발자 에이전트만큼
   강하게 유지하세요. 리뷰어 에이전트는 여러분에게 오기 전의 마지막 검사입니다.

   나머지는 모두 그대로 둡니다. Agent Canvas는 이미 사람 없이 실행되며(확인 prompt 없음), 대화 하나에
   phase 하나 전체가 들어갈 여유(500 iteration)가 있습니다.

</Steps>

## 동작 확인

Agent Canvas의 **Settings → Secrets**에 `GITHUB_PERSONAL_ACCESS_TOKEN`이 나열됩니다. `developer`
profile로 대화를 시작하고 이렇게 요청합니다.

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

`<app-name>[bot]`과 빈 issue 목록을 보고합니다.

<Aside type="caution" title="여러분의 GitHub 로그인을 에이전트에게서 떼어 두세요">
Agent Canvas의 **Integrations**에 GitHub 토큰을 추가하지 말고, **MCP Servers**에 나열된 GitHub 서버는
삭제하세요. 둘 다 고정된 토큰(대개 여러분의 것)을 담고 있어서, 이를 쓰는 에이전트는 앱이 아니라 여러분으로
동작합니다.
</Aside>

<Aside type="caution">
에이전트는 이 컴퓨터에서 여러분의 사용자로 명령을 실행합니다. 그 환경에 cloud 자격 증명을 두지 말고,
시험 삼아 써 보는 단계를 넘어서면 별도의 컴퓨터나 VM을 사용하세요.
</Aside>

<Aside type="tip" title="Agent Canvas를 서비스로 실행하기">
Agent Canvas를 터미널이 아니라 서비스로 실행하게 되면, 타이머가 45분마다
`pnpm agent-canvas --once`를 실행하게 하세요. 이 명령은 토큰을 하나 만들어 저장하고 종료합니다.
Discava는 Linux에서 systemd로 이렇게 합니다.
[Discava의 OpenHands 설정](../../discava/openhands-setup/#github-app)을 참고하세요.
</Aside>

Discava에는 테스터 에이전트를 위한 세 번째 profile인 `tester`가 있습니다. 테스터는 merge된 변경을 배포된
stage에서 테스트하는데, 노트 앱에는 그런 stage가 없으므로 여기서는 필요하지 않습니다.
