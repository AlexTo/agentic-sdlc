import { Steps, Aside } from '@astrojs/starlight/components';

**결과:** 여러분의 컴퓨터에서 실행 중인 OpenHands Agent Canvas, secret으로 저장된 GitHub 토큰,
그리고 두 개의 agent profile: 개발자 에이전트용 `developer`와 리뷰어 에이전트용 `reviewer`.

<Steps>

1. **Agent Canvas를 설치하고 시작합니다.** Discava는 버전 1.41.0을 사용합니다.

   ```bash
   npm install -g @openhands/agent-canvas
   agent-canvas
   ```

   [http://127.0.0.1:8000](http://127.0.0.1:8000)을 엽니다. 계속 실행해 두세요. automation은
   Agent Canvas가 실행 중일 때만 폴링합니다.

2. [2단계](../github-repository/)의 에이전트 계정으로 로그인한 상태에서 **GitHub 토큰을 만듭니다**.
   `repo`와 `workflow` scope가 있는 classic personal access token입니다. fine-grained 토큰은 자기
   계정이나 organization이 소유한 저장소에만 접근할 수 있어서 여러분의 fork에는 쓸 수 없습니다.

   에이전트는 workflow를 수정하지 않지만, 브랜치가 `.github/workflows/`를 건드릴 때마다
   (예를 들어 `main`을 merge하면서) GitHub는 `workflow` scope가 없는 토큰의 push 전체를 거부합니다.

3. Agent Canvas의 **Settings → Secrets**에서 **토큰을 secret으로 저장**합니다. 이름은
   `GITHUB_PERSONAL_ACCESS_TOKEN`입니다.

4. **에이전트를 선택합니다.** Discava는 Claude Code를 ACP (Agent Client Protocol)로 실행하므로,
   이미 사용하는 코딩 에이전트가 작업을 합니다. agent 설정에서 다음과 같이 설정합니다.

   | 설정 | 값 |
   | --- | --- |
   | Agent | ACP, server `claude-code` |
   | Confirmation mode | 끔 (확인할 사람이 없습니다) |
   | Max iterations | 500 (phase 하나 전체를 위한 여유) |

   코딩 에이전트는 이 컴퓨터에 같은 사용자로 설치되고 로그인되어 있어야 합니다.

5. 에이전트 역할마다 하나씩, **두 개의 agent profile을 만듭니다.**

   | Profile | 역할 | Agent | Model |
   | --- | --- | --- | --- |
   | `developer` | 개발자 | ACP, `claude-code` | `sonnet` |
   | `reviewer` | 리뷰어 | ACP, `claude-code` | `opus` |

   어떤 에이전트와 model이든 동작합니다. 리뷰어 에이전트는 최소한 개발자 에이전트만큼 강하게 유지하세요.
   리뷰어 에이전트는 여러분에게 오기 전의 마지막 검사입니다.

   Discava에는 테스터 에이전트를 위한 세 번째 profile인 `tester`가 있습니다. 테스터는 merge된 변경을 배포된
   stage에서 테스트하는데, 노트 앱에는 그런 stage가 없으므로 여기서는 필요하지 않습니다.

</Steps>

## 동작 확인

Agent Canvas에서 `developer` profile로 대화를 시작하고
`GITHUB_PERSONAL_ACCESS_TOKEN` secret을 줍니다. 그리고 이렇게 요청합니다.

```text
Run gh auth status using the GITHUB_PERSONAL_ACCESS_TOKEN secret, and list the open issues in <you>/agentic-sdlc.
```

에이전트의 계정과 빈 issue 목록을 보고합니다.

<Aside type="caution">
에이전트는 이 컴퓨터에서 여러분의 사용자로 명령을 실행합니다. 그 환경에 cloud 자격 증명을 두지 말고,
시험 삼아 써 보는 단계를 넘어서면 별도의 컴퓨터나 VM을 사용하세요.
</Aside>
