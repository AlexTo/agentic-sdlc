**현재 위치:** 🤖 에이전트, 무인 진행. **산출물:** `openhands/...` 브랜치에 있는 phase 1의 pull request.

다음 폴링에서 OpenHands가 `openhands` label이 붙은 issue를 찾아 그 issue의 대화를 시작합니다.
여러분은 아무것도 하지 않습니다.

## 에이전트가 하는 일

1. `AGENTS.md`, constitution, spec 폴더를 읽습니다.
2. phase의 테스트를 먼저 작성합니다. spec의 tag 규칙을 단위 테스트로 작성합니다.
3. 테스트가 통과할 때까지 구현하며, 각 task를 완료하는 커밋에서 `tasks.md`의 해당 task를 체크합니다.
4. 변경한 부분에 대해 lint, typecheck, build, 단위 테스트를 watch mode가 아닌 한 번만 실행합니다.
5. Conventional Commit 형식의 제목으로 PR을 엽니다. 예를 들어
   `feat(notes): add tags to notes in the data and API layers`이며, 본문에는 `Refs #<parent>`가 들어갑니다.
6. 건너뛴 **(human)** task를 나열합니다.

## 하지 말라고 지시받은 일

issue에 제한 사항이 명시되어 있습니다.

- task 범위 밖에서 작업하지 않습니다.
- 테스트를 통과시키려고 테스트를 약하게 만들지 않습니다.
- `.github/workflows/`를 수정하지 않고, merge하지 않으며, 자격 증명을 건드리지 않습니다.
- 막히면 issue에 댓글을 남기고 멈춥니다. 추측하지 않습니다.

## 여러분이 확인할 것

PR을 열고 위에서부터 읽습니다.

- 제목과 본문이 무엇이 바뀌었고 어떤 task가 완료되었는지 알려 주나요?
- 테스트가 *spec의* 규칙을 테스트하나요, 아니면 구현의 특이한 동작을 테스트하나요?
- `tasks.md`에서 정확히 이 phase만, 그 이상은 없이 체크되어 있나요?

<Aside type="tip">
아직 리뷰할 필요는 없습니다. CI와 에이전트 리뷰어가 먼저 보고, 그들이 만족해야만 PR이
여러분에게 옵니다. 다음 단계를 보세요.
</Aside>
