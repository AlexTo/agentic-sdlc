import { Steps } from '@astrojs/starlight/components';

**현재 위치:** 🧑 여러분 + 🤖 에이전트. **산출물:** `plan.md`, `data-model.md`, `contracts/`, `tasks.md`.

<Steps>

1. plan을 생성합니다.

   ```text
   /speckit-plan
   ```

   plan은 spec과 프로젝트 constitution (`.specify/memory/constitution.md`)을 읽고
   *어떻게* 할지를 정합니다: ElectroDB entity에 `tags`를 추가하고, tRPC input schema를 확장하고,
   `notes.list`에 `tag` 필터를 추가합니다.

2. task를 생성합니다.

   ```text
   /speckit-tasks
   ```

   `tasks.md`는 순서가 있고, 체크할 수 있으며, phase별로 묶여 있습니다. 나중에 script가 이 파일을 읽으므로
   [형식](../../reference/tasks-format/)이 고정되어 있으며, 다음 단계에서 PR 검사가 이를 검증합니다.

   ```markdown
   ## Phase 1: User Story 1 - Tags in the data and API (Priority: P1) 🎯 MVP
   - [ ] T001 Add `tags` to the note entity in packages/notes-table/src/entities/note.ts
   - [ ] T002 [P] Unit tests for tag rules (max five, unique, case-insensitive)
   - [ ] T003 Extend create and update procedures in packages/notes-api/src/procedures/notes.ts

   ## Phase 2: User Story 2 - Tags on the website (Priority: P2)
   - [ ] T004 Tag input on the note form
   - [ ] T005 Tag filter on the list page
   - [ ] T006 e2e scenario with screenshots, invariant and concurrency tests

   ## Phase 3: Docs
   - [ ] T007 Describe tags on the notes app page in docs/
   - [ ] T008 **(human)** Confirm the screenshots match the docs wording
   ```

3. 코드가 존재하기 전에 모든 것을 교차 확인합니다.

   ```text
   /speckit-analyze
   ```

   task가 없는 요구 사항, 요구 사항이 없는 task, 세 파일 사이의 모순을 보고합니다. 지금 고치세요.
   지금은 문장 하나로 끝나지만, 구현 후에는 PR 하나가 듭니다.

</Steps>

**(human)**으로 표시된 task는 에이전트가 건너뛰고, PR 설명에 여러분을 위해 나열합니다.

다음: [Spec 승인하기](../approve-the-spec/).
