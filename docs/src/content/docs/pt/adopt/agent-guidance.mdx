**No final você terá:** um `AGENTS.md` que todo agent lê primeiro, e os templates de issue em
`.github/ISSUE_TEMPLATE/`, a fonte das instruções permanentes de toda issue de implementação.

<Steps>

1. **Copie o `AGENTS.md`** deste repositório, e reescreva cada seção para o seu projeto. Ele é
   curto de propósito: o que um agent precisa em toda execução, e nada mais.

   | Seção | Escreva |
   | --- | --- |
   | What this is | Um parágrafo: o produto, a stack, a ferramenta de monorepo |
   | Commands | Instalar; build, lint e testes de tudo; os testes de um projeto, uma vez (não em watch mode); um arquivo de teste; `nx affected`; e2e; dev local |
   | Architecture | Um item por pacote: o que ele é, o que pode importar, onde entra cada tipo de código novo |
   | Conventions | Conventional Commits, o formatter pelo nome, onde ficam os helpers, e toda regra que um revisor já teve que repetir duas vezes |

   <Aside type="tip">
   A seção de comandos é a que mais importa. Um agent que não encontra "rodar um arquivo de teste,
   uma vez" vai rodar a suíte inteira em watch mode e travar. Rode uma vez cada comando que você
   listar, para ter certeza de que funciona.
   </Aside>

   Quando a seção de arquitetura passar de uma linha por pacote, mova o detalhe de cada pacote para
   um `AGENTS.md` aninhado na pasta dele, e deixe na raiz uma linha apontando para lá. Um agent só
   carrega um arquivo aninhado quando trabalha naquela pasta, então uma execução lê só o detalhe de
   que precisa. O `packages/tooling/agent/AGENTS.md` deste repositório é um deles; copie-o junto com
   a cola no [passo 5](../glue-scripts/).

   Se o seu agent lê um arquivo com outro nome, como `CLAUDE.md`, faça esse arquivo apontar para o
   `AGENTS.md`. O `CLAUDE.md` deste repositório começa com `@AGENTS.md`, que o Claude Code lê como
   "inclua esse arquivo aqui".

2. **Copie o `.github/ISSUE_TEMPLATE/`** deste repositório: `implement-phase.md` para o
   Desenvolvedor, e `test-deployed-pr.md` para o Testador, se você adicioná-lo no
   [passo 9](../deploy/).

   O script do Agent Issues escreve ele mesmo as seções de spec e de escopo da issue, e lê tudo o
   que está abaixo de `## Instructions for the agent` no `implement-phase.md` em tempo de execução.
   Mantenha esse heading exatamente assim, porque o script procura por ele e falha sem ele. Mantenha
   também `#<parent>` literalmente: o script o substitui pela issue pai da spec, e remove o item
   quando a spec não tem uma.

3. **Edite as instruções para combinar com a sua stack**: os comandos, o caminho do helper de
   screenshots, e o que "credenciais de cloud" significa para você.

</Steps>
