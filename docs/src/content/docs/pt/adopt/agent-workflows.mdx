**No final você terá:** workflows que abrem issues a partir de specs, mandam o agent de volta
quando o CI fica vermelho ou um review pede mudanças, e arquivam uma spec quando todas as tasks
estão marcadas.

<Steps>

1. **Copie os quatro workflows** de `.github/workflows/` deste repositório: `agent-issues.yml`,
   `agent-ci.yml`, `agent-review.yml` e `agent-status.yml`, que guarda os passos que os dois
   workflows de status compartilham. Troque o scope `@agentic-sdlc/` neles. Os gatilhos e as
   permissões deles estão listados em [Referência: workflows](../../reference/workflows/).

2. **Confira se as condições `if:` batem com as suas decisões.** Se você mudou o prefixo de branch
   ou os labels, mude aqui também:

   ```yaml
   # agent-issues.yml
   if: >-
     github.event_name == 'workflow_dispatch' ||
     (github.event.pull_request.merged == true &&
     ((github.event.action == 'closed' &&
     (contains(github.event.pull_request.labels.*.name, 'spec-ready') ||
     startsWith(github.event.pull_request.head.ref, 'openhands/'))) ||
     (github.event.action == 'labeled' &&
     github.event.label.name == 'spec-ready')))

   # agent-ci.yml
   if: >-
     github.event.workflow_run.event == 'pull_request' &&
     startsWith(github.event.workflow_run.head_branch, 'openhands/issue-') &&
     (github.event.workflow_run.conclusion == 'failure' ||
     github.event.workflow_run.conclusion == 'timed_out')

   # agent-review.yml
   if: >-
     startsWith(github.event.pull_request.head.ref, 'openhands/issue-') &&
     github.event.pull_request.head.repo.full_name == github.repository &&
     contains(github.event.review.body, 'CHANGES REQUESTED')
   ```

3. **Mantenha as permissões e o checkout exatamente como copiados.** Cada workflow pede só o que
   escreve. `pull-requests: write` parece sobrar, mas não sobra: labels e comentários em um PR
   passam pela API de issues, que recusa o token do workflow sem isso.

   Os dois workflows de status fazem checkout da **branch padrão**, no `agent-status.yml`. O Agent Issues faz checkout do
   **merge commit**, para ver as marcações que o PR mergeado fez. Nunca mude nenhum deles para fazer
   checkout do head do PR: esses jobs têm um token que pode escrever.

4. **Mantenha o trancamento antes do label.** O Agent Issues abre cada issue sem o label
   `openhands`, tranca a conversa dela para que só colaboradores possam comentar no que o agent lê,
   e só então adiciona o label. Se o trancamento falhar, o label nunca é adicionado e a execução
   falha, nomeando a issue a trancar à mão. O código é `helpers/conversation-lock.ts`.

5. **Mantenha os grupos de concurrency.** Cada um é por PR ou por branch, com
   `cancel-in-progress: false`. Assim, dois eventos de um mesmo PR não podem contar cada um uma
   tentativa, e merges de PRs diferentes nunca cancelam um ao outro.

6. **Copie `archive-specs.yml`**, se você quiser que as specs concluídas saiam do caminho. Quando um
   push na `main` muda um `specs/*/tasks.md` ativo, ele abre um PR na branch `archive-spec/<folder>`
   para cada spec com todas as tasks marcadas, incluindo as **(human)**. O PR move a pasta para
   `specs/_archive/` e reescreve os links para ela e a partir dela. O Agent Issues pula
   `specs/_archive/`, e o `Tasks format` falha se um `tasks.md` arquivado tiver uma task não marcada.

   Ele pula uma spec com uma issue de agent aberta, e uma que já teve um PR de arquivamento. Feche
   esse PR sem merge para manter a spec ativa.

   <Aside type="caution">
   O workflow não consegue abrir os PRs dele a menos que as Actions possam criar pull requests, o
   que o `scripts/setup-repository.sh` ativa. PRs abertos com o token do workflow não
   disparam o PR Checks: feche e reabra cada um para rodá-los.
   </Aside>

</Steps>

## Confira se funcionou

Os workflows aparecem na aba **Actions** do repositório depois que chegam à `main`. Abra
**Actions → Agent Issues → Run workflow** e informe uma pasta de spec que não existe, como
`does-not-exist`.

A execução termina com sucesso e um aviso: `No issue created: no spec folder with a tasks.md was found`.

<Aside type="note">
Workflows `workflow_run` e `pull_request_review` só rodam a partir da versão na branch padrão.
Mudanças neles só valem depois do merge. É também por isso que um agent não consegue mudá-los no
próprio PR.
</Aside>
