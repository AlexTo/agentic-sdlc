import { Steps, Aside } from '@astrojs/starlight/components';

**No final você terá:** uma constitution ratificada sua, e templates do Speckit que geram arquivos
que o workflow Agent Issues consegue ler.

O `.specify/` que você copiou no [passo 2](../speckit/) já traz uma constitution e templates que
funcionam, escritos para o app de notas. Este passo os torna seus.

<Steps>

1. **Reescreva a constitution para o seu projeto.** No seu coding agent:

   ```text
   /speckit-constitution
   ```

   Passe para ele os princípios do seu próprio projeto: arquitetura, modelo de dados, padrões de
   segurança, convenções de código. A [do Discava](../../discava/constitution-and-guidance/) é um
   exemplo completo. Mantenha estas partes da copiada, adaptando os comandos e os nomes de pacote à
   sua stack, porque o resto do workflow depende delas:

   | Mantenha | Da constitution copiada | Por quê |
   | --- | --- | --- |
   | Testes unitários, invariantes e testes e2e são obrigatórios, e testes são uma especificação | III. Layered Tests | O agent não pode enfraquecer um teste para deixar o CI verde |
   | Tudo roda com `pnpm dev`, sem conta de cloud | II. Everything Runs Locally | Assim o CI do PR consegue rodar a suíte e2e e dar ao agent feedback real |
   | Os agents implementam na própria branch e PR, nunca rodam a stack local, e marcam como **(human)** as tasks que precisam dela | Development Workflow | O agent não tem Docker. O CI roda o que ele não consegue |
   | O CI do PR é o portão. Um agent nunca faz merge, push na `main`, edita workflows de CI ou enfraquece um teste | Development Workflow | O que mantém um agent na sua raia |

2. **Troque os caminhos de pacote no `tasks-template.md`.** As tasks de teste dele nomeiam os pacotes
   deste repositório: `packages/notes-table/src/helpers/invariants/` e `@agentic-sdlc/e2e`. Aponte-as
   para os seus. Mantenha o resto do template como está: as regras de formato em **Read by
   automation**, o marcador **(human)**, os testes obrigatórios e a nota contra editar testes
   existentes são o que o workflow Agent Issues e o check `Tasks format` usam.

3. **Mantenha a linha de issue pai** no `spec-template.md`:

   ```markdown
   **Parent issue**: [#<number>, or "none" if there is no tracking issue]
   ```

   O Agent Issues escreve `Refs #<parent>` em cada issue a partir dela.

</Steps>

## Confira se funcionou

Gere uma spec e tasks descartáveis para uma feature minúscula. Depois, quando a cola estiver no
lugar ([passo 5](../glue-scripts/)):

```bash
pnpm nx run @your-scope/tooling-agent:validate-tasks
```

```text
1 tasks.md file(s) are in the expected format.
```

Depois, apague a pasta da spec descartável.

<Aside type="caution">
O `/speckit-tasks` às vezes escreve `### Phase 2` ou indenta uma task. É exatamente isso que o
validador pega, então não afrouxe o validador. Ajuste o texto do template até os arquivos gerados
passarem.
</Aside>
