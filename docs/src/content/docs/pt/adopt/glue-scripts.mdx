import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**No final você terá:** um projeto `tooling-agent` com dez targets do Nx e 223 testes unitários
passando. Os workflows dos passos 6, 7 e 9 só chamam esses targets.

<Steps>

1. **Copie `packages/tooling/agent/`** deste repositório, inteiro. O `project.json` dele já
   declara todo target que os workflows chamam, e o `AGENTS.md` dele diz a um agent o que cada
   pasta contém:

   <FileTree>
   - packages/tooling/agent/src/
     - agent-issues/ spec → issue, o validador de `tasks.md` e o arquivamento de specs concluídas
     - agent-ci/ CI vermelho → agent
     - agent-review/ "changes requested" → agent
     - helpers/ trancar as issues que um agent lê, e distinguir autores confiáveis de estranhos
     - ui-screenshots/ a regra dos screenshots, e o comentário `E2E screenshots`
     - invariant-coverage/ qual código escreve qual entidade, e a regra de que novos writers precisam de invariantes
     - post-merge-test/ PR com deploy → issue de teste para o Testador
   </FileTree>

   Eles dependem só dos módulos nativos do Node, do TypeScript (para o scan de invariantes) e da
   CLI `gh`. O `tsx` os roda. Adicione a pasta ao `pnpm-workspace.yaml` do seu workspace e às
   references do `tsconfig.json` raiz se os seus globs ainda não cobrem `packages/tooling/*`.

2. **Renomeie o scope.** Substitua `@agentic-sdlc/` pelo scope do seu workspace no `package.json`,
   no `project.json` e no `vitest.config.mts` do projeto, e nos comentários dos arquivos `main.ts`
   dele. Todo workflow que você copiar depois também nomeia `@agentic-sdlc/tooling-agent`.

3. **Mude as constantes para o seu setup.** As que estão em negrito apontam para o app de notas
   deste repositório, então você quase certamente vai mudá-las. O resto só muda se você mudou
   alguma decisão na [visão geral](../overview/):

   | Constante | Arquivo | Padrão |
   | --- | --- | --- |
   | **`UI_SOURCE`** | `ui-screenshots/check.ts` | `.tsx`/`.css` em `packages/notes-website/src/` e `packages/common/shadcn/src/` |
   | **`WRITER_PACKAGES`**, **`ENTITIES_PACKAGE`** | `invariant-coverage/scan.ts` | Os pacotes cujo código escreve na tabela, e o que guarda as entidades dela (`notes-table`) |
   | **`WRITER_MAP_PATH`**, **`INVARIANTS_PATH`**, **`HELPERS`** | `invariant-coverage/check.ts` | `packages/notes-table/entity-writers.json`, `packages/notes-table/src/helpers/invariants`, `notes-table` |
   | **`UI_PATHS`**, **`NOT_DEPLOYED`** | `post-merge-test/plan.ts` | O que conta como uma mudança de UI que vale percorrer clicando, e caminhos que nunca chegam a uma stack com deploy |
   | `SPEC_READY_LABEL`, `AGENT_BRANCH_PREFIX` | `agent-issues/gate.ts` | `spec-ready`, `openhands/` |
   | `AGENT_LABEL` | `agent-issues/issue.ts` | `openhands` |
   | `AGENT_BRANCH`, `REVIEW_STATUS_CONTEXT`, `MAX_CI_FIX_ATTEMPTS` | `agent-ci/plan.ts` | `^openhands\/issue-\d+$`, `software-factory/review`, `5` |
   | `MAX_REVIEW_FIX_ATTEMPTS`, `CHANGES_REQUESTED` | `agent-review/plan.ts` | `5`, `🔄 CHANGES REQUESTED` |
   | `WAIVER_LABEL` | `ui-screenshots/check.ts`, `invariant-coverage/check.ts` | `no-ui-screenshots`, `no-new-invariant` |

   Se você ainda não vai checar invariantes, deixe a pasta `invariant-coverage` no lugar e não
   copie o job dela no PR Checks no passo 6. Alguns testes unitários leem os arquivos de
   invariantes reais, então atualize esses testes (em `invariant-coverage/check.test.ts`) ou os
   caminhos acima.

   <Aside type="caution">
   Não mude `REVIEW_STATUS_CONTEXT`. `software-factory/review` é o status que o worker issue-to-PR
   do OpenHands procura. Com qualquer outro nome, o agent nunca é mandado de volta.
   </Aside>

4. **Rode os testes.**

   ```bash
   pnpm nx run @your-scope/tooling-agent:test
   ```

</Steps>

## Faça um dry run

Cada um dos scripts de agent lê o evento do GitHub de `GITHUB_EVENT_PATH` e, com
`DRY_RUN=true`, imprime sua decisão em vez de agir. Para reproduzir um caso real, salve um payload
de uma execução anterior de workflow e aponte o script para ele:

```bash
DRY_RUN=true GITHUB_REPOSITORY=owner/repo GITHUB_EVENT_PATH=./event.json \
  pnpm nx run @your-scope/tooling-agent:agent-ci-status
```

```json
{
  "pullRequest": 470,
  "plan": {
    "action": "send-back",
    "attempt": 1,
    "label": "ci-fix-1",
    "description": "CI failed (fix attempt 1 of 5): E2E tests (4/4)"
  }
}
```
