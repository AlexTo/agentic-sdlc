**No final você terá:** um workflow **PR Checks** cuja falha alimenta o loop de CI, um check
**UI Screenshots**, e o **CI** na `main`.

<Steps>

1. **Copie quatro workflows** de `.github/workflows/` deste repositório:

   | Arquivo | O que faz |
   | --- | --- |
   | `pr-checks.yml` | Lint, test e build do que o PR afeta; `Tasks format`; `Invariant coverage`; e2e em shards juntados em um único check `E2E tests`; o comentário `E2E screenshots` |
   | `ui-screenshots.yml` | A regra dos screenshots, como workflow próprio, para que adicionar ou remover o label `no-ui-screenshots` rode de novo só este check. O Discava a roda como um job do PR Checks. Os dois jeitos funcionam |
   | `ci.yml` | Os mesmos checks em todo push na `main`, Trivy, o cache do Playwright e o deploy deste site de documentação |
   | `cache-cleanup.yml` | Apaga os caches de um PR quando ele é fechado |

   Mantenha o `name: PR Checks` do `pr-checks.yml` exatamente assim: o Agent CI Status escuta um
   workflow com esse nome.

2. **Aponte-os para os seus projetos.** Procure `@agentic-sdlc/` nos arquivos copiados e troque o
   scope. Depois, no `pr-checks.yml`:

   | Job | Mudança |
   | --- | --- |
   | `invariant-coverage` | Os `paths` do código que poderia escrever na sua tabela, os mesmos de `WRITER_PACKAGES` no passo 5. Ou apague o job se você ainda não checa invariantes |
   | `e2e` | O número de shards em `matrix.shard`, de acordo com a sua suíte. Um shard custa uns dois minutos antes do primeiro teste, então pare de adicioná-los quando os testes de cada um levarem mais ou menos isso |
   | `e2e-screenshots` | Nada, depois que o [passo 8](../local-stack-and-e2e/) estiver feito |

   No `ci.yml`, apague o job `deploy_docs` e a permissão `pages: write` dele, a menos que você
   publique um site de documentação a partir de `docs/`.

3. **Mantenha o que deixa o agent rápido.** O passo `Check for mutations` no `ci.yml` (`git diff
   --exit-code` depois do build) pega arquivos gerados que o agent esqueceu de commitar. O job
   `playwright-cache` salva o Chromium a partir da `main`, já que execuções de PR só conseguem
   restaurar caches salvos lá. O job `build` salva o cache de tasks do Nx a partir da `main`, então a
   primeira execução de um PR reaproveita o que a `main` já buildou, e o agent espera menos a cada
   rodada de correção. Cada perna de `checks` no PR Checks mantém o próprio cache do mesmo jeito,
   exceto `lint`, que só restaura. O `init-monorepo` limita o cache a 1 GB, e o Cache Cleanup libera a
   parte de um PR fechado nos 10 GB do repositório. Veja
   [Mantendo tudo rápido](../../discava/pr-checks/#mantendo-tudo-rápido) para o quanto isso economizou para o
   Discava.

</Steps>

Toda action está fixada em um SHA de commit, e o `dependabot.yml` que você copiou no passo 1 mantém
as versões fixadas atualizadas.

## Confira se funcionou

Abra um PR descartável que quebra uma linha do `tasks.md`, por exemplo indentando uma task. O check
**Tasks format** falha com uma anotação nessa linha:

```text
A task must be written "- [ ] T<3 digits> <description>", starting in the first column
```

Abra outro que muda um arquivo de UI sem mexer em nenhum cenário. O **UI Screenshots** falha:

```text
This pull request changes UI source (…) but no e2e scenario gained a `screenshot(page, 'name')` call.
```

<Aside type="note">
O `codecov/codecov-action` nos arquivos copiados precisa de um secret `CODECOV_TOKEN`. Remova o
passo se você não usa o Codecov.
</Aside>
