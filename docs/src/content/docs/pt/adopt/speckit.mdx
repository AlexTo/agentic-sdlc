**No final você terá:** `.specify/` no repositório, os comandos `speckit-*` disponíveis para o seu
coding agent, e pastas de spec nomeadas por timestamp.

<Steps>

1. **Instale a CLI**, fixada na versão que o Discava usa:

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. **Copie o `.specify/`** deste repositório. Ele já está configurado do jeito que o workflow precisa:

   | Configuração | Onde | Valor |
   | --- | --- | --- |
   | Pastas de spec nomeadas por timestamp | `extensions/git/git-config.yml` | `branch_numbering: timestamp`, para que duas pessoas escrevendo specs ao mesmo tempo nunca colidam: `specs/20261116-013307-course-reviews/`, não `specs/001-course-reviews/` |
   | Conventional commits a cada passo | `extensions/git/git-config.yml` | `commit_style: conventional` |
   | Os hooks da extensão git rodam sem perguntar | `extensions.yml` | `auto_execute_hooks: true`: uma branch antes de `/speckit-specify`, um commit depois de cada passo |
   | Os templates e a constitution | `templates/`, `memory/` | Já trazem as mudanças do [passo 3](../constitution-and-templates/) |

3. **Adicione os comandos para o seu coding agent.** Se ele lê skills do Claude Code, copie
   `.claude/skills/speckit-*` deste repositório. Caso contrário, deixe o Speckit escrevê-los para o
   seu agent em uma pasta temporária e copie só os arquivos de comandos:

   ```bash
   mkdir /tmp/speckit && cd /tmp/speckit
   specify init --here --integration <your-agent> --script sh --extension git
   ```

   Rode `specify init --help` para ver a lista de integrações. Copie a pasta que ele cria para os
   comandos do seu agent, não o `.specify/` dele, que desfaria o passo 2.

4. **Faça commit de `.specify/`** e dos arquivos de comandos ou skills.

</Steps>

## Confira se funcionou

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, comandos, scripts
  - extensions.yml
  - init-options.json
  - memory/constitution.md a do app de notas, reescrita para o seu no próximo passo
  - scripts/bash/
  - templates/ templates de spec, plan, tasks, checklist e constitution
</FileTree>

No seu coding agent, os comandos `speckit-specify`, `speckit-clarify`, `speckit-plan`,
`speckit-tasks`, `speckit-analyze` e `speckit-constitution` aparecem na lista.

<Aside type="tip">
PRs de spec ficam na própria branch (`spec/<name>`), não em `openhands/...`. A branch de feature da
extensão git serve para isso. Só as branches do agent usam o prefixo `openhands/`.
</Aside>
