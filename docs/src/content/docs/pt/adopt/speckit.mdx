**No final você terá:** `.specify/` no repositório, os comandos `speckit-*` disponíveis para o seu
coding agent, e pastas de spec nomeadas por timestamp.

<Steps>

1. **Instale a CLI**, fixada na versão que o Discava usa:

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. **Inicialize no repositório** para o seu coding agent, com a extensão git incluída. O Discava
   usou a integração `claude`, que instala os comandos como skills:

   ```bash
   specify init --here --integration claude --script sh --extension git
   ```

   Rode `specify init --help` para ver as outras integrações. Escolha a que o agent do seu time lê.

3. **Mude para numeração por timestamp.** Em `.specify/extensions/git/git-config.yml`:

   ```yaml
   branch_numbering: timestamp
   commit_style: conventional
   ```

   As pastas viram `specs/20261116-013307-course-reviews/` em vez de `specs/001-course-reviews/`,
   então duas pessoas escrevendo specs ao mesmo tempo nunca colidem.

4. **Confira os hooks da extensão git** em `.specify/extensions.yml`. O Discava mantém os padrões:
   `speckit.git.feature` antes de `/speckit-specify` (cria uma branch), e `speckit.git.commit` depois
   de cada passo (um commit por passo). Ele define `auto_execute_hooks: true` para que eles rodem
   sem perguntar.

5. **Faça commit de `.specify/`** e dos arquivos de comandos ou skills da integração.

</Steps>

## Confira se funcionou

<FileTree>
- .specify/
  - extensions/git/ git-config.yml, comandos, scripts
  - extensions.yml
  - init-options.json
  - memory/constitution.md ainda o template, preenchido no próximo passo
  - scripts/bash/
  - templates/ templates de spec, plan, tasks, checklist e constitution
</FileTree>

No seu coding agent, os comandos `speckit-specify`, `speckit-clarify`, `speckit-plan`,
`speckit-tasks`, `speckit-analyze` e `speckit-constitution` aparecem na lista.

<Aside type="tip">
PRs de spec ficam na própria branch (`spec/<name>`), não em `openhands/...`. A branch de feature da
extensão git serve para isso. Só as branches do agent usam o prefixo `openhands/`.
</Aside>
