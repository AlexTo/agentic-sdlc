**No final você terá:** um workspace pnpm com Nx, Biome, Conventional Commits aplicado em todo
commit, e uma verificação de secrets antes de cada commit.

A cola não precisa do Nx. Mas o `nx affected` é o que mantém os PR checks rápidos o bastante para um
agent iterar, e todo script de cola roda como um target do Nx. Se você usa outra ferramenta de
monorepo, mantenha a ideia: rode só o que o PR afeta, e exponha cada script como uma task nomeada.

<Steps>

1. **Crie o workspace**, se você não tiver um. O Discava e este repositório foram ambos criados com
   o Nx Plugin for AWS:

   ```bash
   pnpm create @aws/nx-workspace your-project --iac=cdk --no-interactive
   ```

   Um workspace Nx existente também funciona. Fixe o pnpm no `package.json` raiz com
   `packageManager`, para que o CI e o agent usem a mesma versão.

2. **Copie estes arquivos** deste repositório para os mesmos caminhos no seu:

   <FileTree>
   - commitlint.config.js Conventional Commits
   - lint-staged.config.js Biome nos arquivos em stage
   - .husky/
     - commit-msg roda o commitlint
     - pre-commit git-secrets, depois lint-staged, e falha se o Biome mudou alguma coisa, para que o agent coloque em stage de novo e faça commit outra vez
     - prepare-commit-msg Commitizen, para quem faz commits de forma interativa. Ele se pula com `git commit -m`, que é como os agents fazem commit
   - .git-secrets/ o script do git-secrets que o hook de pre-commit roda
   - .gitallowed padrões que o git-secrets deixa passar
   - .github/
     - actions/init-monorepo/ configuração de CI compartilhada
     - actions/changed-paths/ "este PR mudou algum destes caminhos?", para pular jobs
     - actions/playwright-setup/ Chromium para o Playwright, em cache por versão
     - dependabot.yml mantém atualizadas as actions fixadas e as dependências
   </FileTree>

   Deixe o `.husky/pre-push` para o [passo 8](../local-stack-and-e2e/): ele confere o mapa de
   invariantes. O `init-monorepo` instala o pnpm (com três tentativas, porque um timeout do registry
   custaria ao agent uma tentativa de correção), o Node 24 e opcionalmente o uv, restaura os caches
   do pnpm e do Nx, instala as dependências e define `NX_BASE`/`NX_HEAD` para o `nx affected`.

3. **Copie os scripts raiz e as dev dependencies** do `package.json` deste repositório: o bloco
   `scripts` (que o `AGENTS.md`, o CI e o agent chamam), e, de `devDependencies`,
   `@commitlint/config-conventional`, `commitlint`, `commitizen`, `husky` e `lint-staged`. Depois:

   ```bash
   pnpm install
   ```

   O script `prepare` dele instala os hooks.

4. **Troque o scope do pacote** em `.github/actions/playwright-setup/action.yml`
   (`@agentic-sdlc/e2e`) pelo nome do seu projeto de e2e.

</Steps>

## Confira se funcionou

```bash
git commit --allow-empty -m "not conventional"
```

```text
⧗   input: not conventional
✖   subject may not be empty [subject-empty]
✖   type may not be empty [type-empty]
```

Depois, `git commit --allow-empty -m "chore: check hooks"` funciona.

<Aside type="note">
Os títulos de issue que a cola escreve são cabeçalhos de Conventional Commit, e o agent os reutiliza
nos commits e pull requests dele. É por isso que o commitlint vem primeiro.
</Aside>
