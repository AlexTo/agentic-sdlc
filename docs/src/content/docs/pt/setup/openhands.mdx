**No final você terá:** o OpenHands Agent Canvas rodando na sua máquina como o seu GitHub App, e
dois perfis de agent: `developer` para o agent Desenvolvedor e `reviewer` para o agent Revisor.

<Steps>

1. **Instale o Agent Canvas.** O Discava roda a versão 1.45.0:

   ```bash
   npm install -g @openhands/agent-canvas
   ```

2. **Inicie ele como o seu app**, a partir do seu clone:

   ```bash
   pnpm agent-canvas
   ```

   Na primeira vez, ele pede o **App ID** e o caminho do **arquivo `.pem`** do
   [passo 2](../github-repository/), e guarda os dois em `~/.config/agent-app/`, legíveis só por
   você. Depois, todas as vezes, ele:

   - inicia o Agent Canvas com o app como autor dos commits dos agents, então o GitHub os mostra
     com o app;
   - gera um dos tokens do app, que duram uma hora, e o guarda no Agent Canvas como o secret
     `GITHUB_PERSONAL_ACCESS_TOKEN`, o que as automações leem. Apesar do nome, qualquer token do
     GitHub funciona ali;
   - substitui o token a cada 45 minutos enquanto estiver rodando.

   Espere a linha `Token stored in the GITHUB_PERSONAL_ACCESS_TOKEN secret`, depois abra
   [http://127.0.0.1:8000](http://127.0.0.1:8000). Se o Agent Canvas perguntar qual agent usar,
   escolha o Claude Code: ele encontra o login que você já tem, então deixe em branco qualquer
   campo de API key.

   Deixe o terminal aberto, e sempre inicie o Agent Canvas assim: as automações só fazem polling
   enquanto ele está no ar, e o token só fica atualizado enquanto este comando roda.

3. **Crie dois perfis de agent**, um por papel de agent. No Agent Canvas, abra
   **Settings → Agent** e clique em **Add agent profile**, duas vezes:

   | Name | Agent type | Agent | Model |
   | --- | --- | --- | --- |
   | `developer` | ACP (external subprocess) | `claude-code` | `sonnet` |
   | `reviewer` | ACP (external subprocess) | `claude-code` | `opus` |

   ACP é o Agent Client Protocol: o coding agent que você já usa faz o trabalho, com o seu login
   nesta máquina. Qualquer agent e modelo funciona. Mantenha o Revisor pelo menos tão forte quanto
   o Desenvolvedor: ele é o último check antes de você.

   Deixe todo o resto como está. O Agent Canvas já roda sem supervisão (sem pedidos de
   confirmação), com espaço para uma fase inteira em uma conversa (500 iterações).

</Steps>

## Confira se funcionou

No Agent Canvas, **Settings → Secrets** lista `GITHUB_PERSONAL_ACCESS_TOKEN`. Inicie uma conversa
com o perfil `developer` e peça:

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

Ele informa `<app-name>[bot]` e uma lista de issues vazia.

<Aside type="caution" title="Mantenha o seu próprio login do GitHub longe dos agents">
Não adicione um token do GitHub em **Integrations** do Agent Canvas, e apague qualquer servidor do
GitHub listado em **MCP Servers**: os dois guardam um token fixo, normalmente o seu, e um agent que
o usa age como você em vez do app.
</Aside>

<Aside type="caution">
O agent roda comandos nesta máquina com o seu usuário. Não deixe credenciais de cloud no ambiente
dele, e use uma máquina ou VM separada quando for além de testar.
</Aside>

<Aside type="tip" title="Rodando o Agent Canvas como serviço">
Quando o Agent Canvas rodar como serviço em vez de em um terminal, faça um timer rodar
`pnpm agent-canvas --once` a cada 45 minutos: ele gera um token, guarda e sai. O Discava faz isso
no Linux com o systemd: veja
[A configuração do OpenHands no Discava](../../discava/openhands-setup/#o-github-app).
</Aside>

O Discava tem um terceiro perfil, `tester`, para o agent Testador. Ele testa mudanças mergeadas em
um stage com deploy, que o app de notas não tem, então você não precisa dele aqui.
