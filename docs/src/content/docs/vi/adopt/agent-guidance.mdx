**Kết quả:** một `AGENTS.md` mà mọi agent đọc đầu tiên, và các issue template dưới
`.github/ISSUE_TEMPLATE/`, nguồn của các hướng dẫn cố định trong mọi issue triển khai.

<Steps>

1. **Chép `AGENTS.md`** từ repository này, và viết lại từng mục cho dự án của bạn. Nó ngắn một cách
   có chủ ý: những gì agent cần trong mọi lần chạy, và không gì khác.

   | Mục | Viết gì |
   | --- | --- |
   | What this is | Một đoạn: sản phẩm, stack, công cụ monorepo |
   | Commands | Cài đặt; build, lint, test mọi thứ; test của một project, một lần (không ở chế độ watch); một file test; `nx affected`; e2e; dev ở local |
   | Architecture | Một gạch đầu dòng cho mỗi package: nó là gì, nó được import gì, code mới mỗi loại đặt ở đâu |
   | Conventions | Conventional Commits, tên của formatter, helper đặt ở đâu, và mọi quy tắc mà người review đã phải nhắc lại hai lần |

   <Aside type="tip">
   Mục lệnh là quan trọng nhất. Một agent không tìm thấy cách "chạy một file test, một lần" sẽ chạy
   cả bộ test ở chế độ watch và bị treo. Chạy thử mỗi lệnh bạn liệt kê một lần, để chắc nó hoạt động.
   </Aside>

   Khi mục kiến trúc không còn gói gọn trong một dòng cho mỗi package, hãy chuyển chi tiết của từng
   package vào một `AGENTS.md` lồng trong thư mục của nó, và để ở file gốc một dòng trỏ tới đó. Agent
   chỉ nạp một file lồng khi nó làm việc trong thư mục đó, nên mỗi lần chạy chỉ đọc chi tiết nó cần.
   `packages/tooling/agent/AGENTS.md` của repository này là một ví dụ; chép nó cùng với glue ở
   [bước 5](../glue-scripts/).

   Nếu agent của bạn đọc một file có tên khác, như `CLAUDE.md`, hãy cho file đó trỏ tới `AGENTS.md`.
   `CLAUDE.md` của repository này bắt đầu bằng `@AGENTS.md`, mà Claude Code hiểu là "chèn file đó vào
   đây".

2. **Chép `.github/ISSUE_TEMPLATE/`** từ repository này: `implement-phase.md` cho Developer, và
   `test-deployed-pr.md` cho Tester, nếu bạn thêm nó ở [bước 9](../deploy/).

   Script Agent Issues tự viết các mục spec và scope của issue, và đọc mọi thứ dưới
   `## Instructions for the agent` trong `implement-phase.md` lúc chạy. Giữ chính xác heading đó, vì
   script tìm nó và sẽ thất bại nếu không có. Giữ nguyên văn cả `#<parent>`: script thay nó bằng
   parent issue của spec, và bỏ gạch đầu dòng đó khi spec không có parent issue.

3. **Sửa các hướng dẫn cho khớp với stack của bạn**: các lệnh, đường dẫn helper ảnh chụp màn hình, và
   "thông tin đăng nhập cloud" có nghĩa là gì với bạn.

</Steps>

## Kiểm tra kết quả

```bash
grep -c '^## Instructions for the agent$' .github/ISSUE_TEMPLATE/implement-phase.md
```
