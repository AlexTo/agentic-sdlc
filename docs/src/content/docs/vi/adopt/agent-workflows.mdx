**Kết quả:** ba workflow mở issue từ spec và gửi agent quay lại khi CI đỏ hoặc có review "changes
requested", và một workflow thứ tư lưu trữ spec khi mọi task đã được đánh dấu.

<Steps>

1. **Chép ba workflow** từ `.github/workflows/` của repository này: `agent-issues.yml`,
   `agent-ci.yml` và `agent-review.yml`. Kích hoạt và permission của chúng được liệt kê trong
   [Tham khảo: workflow](../../reference/workflows/).

2. **Kiểm tra các điều kiện `if:` khớp với quyết định của bạn.** Nếu bạn đã đổi tiền tố nhánh hoặc
   label, hãy đổi chúng ở đây nữa:

   ```yaml
   # agent-issues.yml
   if: >-
     github.event_name == 'workflow_dispatch' ||
     (github.event.pull_request.merged == true &&
     ((github.event.action == 'closed' &&
     (contains(github.event.pull_request.labels.*.name, 'spec-ready') ||
     startsWith(github.event.pull_request.head.ref, 'openhands/'))) ||
     (github.event.action == 'labeled' &&
     github.event.label.name == 'spec-ready')))

   # agent-ci.yml
   if: >-
     github.event.workflow_run.event == 'pull_request' &&
     startsWith(github.event.workflow_run.head_branch, 'openhands/issue-') &&
     (github.event.workflow_run.conclusion == 'failure' ||
     github.event.workflow_run.conclusion == 'timed_out')

   # agent-review.yml
   if: >-
     startsWith(github.event.pull_request.head.ref, 'openhands/issue-') &&
     github.event.pull_request.head.repo.full_name == github.repository &&
     contains(github.event.review.body, 'CHANGES REQUESTED')
   ```

3. **Giữ nguyên permission và checkout như khi chép.** Mỗi workflow chỉ xin những gì nó ghi.
   `pull-requests: write` trông có vẻ thừa nhưng không phải: label và comment trên một PR đi qua
   issues API, vốn từ chối token của workflow nếu thiếu quyền này.

   Hai workflow status checkout **nhánh mặc định**. Agent Issues checkout **merge commit**, để nó
   thấy các dấu tích mà PR đã merge tạo ra. Không bao giờ đổi cái nào sang checkout head của PR: các
   job này giữ một token có quyền ghi.

4. **Giữ các nhóm concurrency.** Mỗi nhóm là theo PR hoặc theo nhánh, với `cancel-in-progress: false`.
   Như vậy hai sự kiện cho một PR không thể mỗi cái tính một lượt thử, và merge của các PR khác nhau
   không bao giờ hủy lẫn nhau.

5. **Chép `archive-specs.yml`**, nếu bạn muốn các spec đã xong được dọn sang một bên. Khi một push
   lên `main` thay đổi một `specs/*/tasks.md` đang hoạt động, nó mở một PR trên nhánh
   `archive-spec/<folder>` cho mỗi spec mà mọi task đã được đánh dấu, kể cả task **(human)**. PR đó
   chuyển thư mục vào `specs/_archive/` và sửa các liên kết đến và đi từ nó. Agent Issues bỏ qua
   `specs/_archive/`, và `Tasks format` thất bại nếu một `tasks.md` đã lưu trữ còn task chưa được
   đánh dấu.

   Nó bỏ qua spec còn agent issue đang mở, và spec đã từng có PR lưu trữ. Đóng PR đó mà không merge
   để giữ spec ở trạng thái đang hoạt động.

   <Aside type="caution">
   Bật **Settings → Actions → General → Allow GitHub Actions to create and approve pull requests**,
   nếu không workflow không mở được PR. PR mở bằng token của workflow không khởi động PR Checks:
   đóng rồi mở lại từng PR để chạy chúng.
   </Aside>

</Steps>

## Kiểm tra kết quả

Các workflow xuất hiện dưới tab **Actions** của repository sau khi chúng vào `main`. Mở
**Actions → Agent Issues → Run workflow**, và nhập một thư mục spec không tồn tại, chẳng hạn
`does-not-exist`.

Lần chạy thành công kèm một notice: `No issue created: no spec folder with a tasks.md was found`.

<Aside type="note">
Workflow `workflow_run` và `pull_request_review` chỉ chạy từ phiên bản trên nhánh mặc định. Thay đổi
với chúng chỉ có hiệu lực khi được merge. Đó cũng là lý do agent không thể thay đổi chúng trong PR của
chính nó.
</Aside>
