**Kết quả:** một constitution đã phê chuẩn của riêng bạn, và các template Speckit tạo ra file mà
workflow Agent Issues đọc được.

`.specify/` bạn đã chép ở [bước 2](../speckit/) đã chứa sẵn một constitution và các template hoạt
động được, viết cho ứng dụng ghi chú. Bước này biến chúng thành của bạn.

<Steps>

1. **Viết lại constitution cho dự án của bạn.** Trong coding agent của bạn:

   ```text
   /speckit-constitution
   ```

   Đưa cho nó các nguyên tắc riêng của dự án: kiến trúc, mô hình dữ liệu, mặc định bảo mật, quy ước
   code. [Constitution của Discava](../../discava/constitution-and-guidance/) là một ví dụ đầy đủ.
   Giữ lại những phần sau của bản đã chép, điều chỉnh các lệnh và tên package cho phù hợp với stack
   của bạn, vì phần còn lại của quy trình phụ thuộc vào chúng:

   | Giữ | Từ constitution đã chép | Vì sao |
   | --- | --- | --- |
   | Unit test, invariant và e2e test là bắt buộc, và test là một đặc tả | III. Layered Tests | Agent không được làm yếu một test để CI chuyển xanh |
   | Mọi thứ chạy dưới `pnpm dev`, không cần tài khoản cloud | II. Everything Runs Locally | Nhờ đó CI của PR chạy được bộ e2e và cho agent phản hồi thật |
   | Agent triển khai trên nhánh và PR riêng, không bao giờ chạy local stack, và đánh dấu **(human)** cho task cần nó | Development Workflow | Agent không có Docker. CI chạy những gì agent không chạy được |
   | CI của PR là cổng kiểm soát. Agent không bao giờ merge, push lên `main`, sửa CI workflow hay làm yếu một test | Development Workflow | Thứ giữ agent trong làn của nó |

2. **Đổi các đường dẫn package trong `tasks-template.md`.** Các task test của nó nêu tên package của
   repository này: `packages/notes-table/src/helpers/invariants/` và `@agentic-sdlc/e2e`. Trỏ chúng
   vào package của bạn. Giữ nguyên phần còn lại của template: các quy tắc định dạng dưới
   **Read by automation**, dấu **(human)**, các test bắt buộc, và ghi chú cấm sửa test có sẵn là
   những thứ mà workflow Agent Issues và check `Tasks format` dựa vào.

3. **Giữ dòng parent issue** trong `spec-template.md`:

   ```markdown
   **Parent issue**: [#<number>, or "none" if there is no tracking issue]
   ```

   Agent Issues viết `Refs #<parent>` vào mỗi issue từ dòng này.

</Steps>

## Kiểm tra kết quả

Sinh một spec và task dùng thử cho một tính năng nhỏ xíu. Sau đó, khi các script glue đã có
([bước 5](../glue-scripts/)):

```bash
pnpm nx run @your-scope/tooling-agent:validate-tasks
```

```text
1 tasks.md file(s) are in the expected format.
```

Xóa thư mục spec dùng thử sau đó.

<Aside type="caution">
`/speckit-tasks` đôi khi viết `### Phase 2` hoặc thụt lề một task. Đó chính xác là thứ bộ validate
bắt được, nên đừng nới lỏng bộ validate. Sửa câu chữ trong template cho đến khi các file được sinh ra
pass.
</Aside>
