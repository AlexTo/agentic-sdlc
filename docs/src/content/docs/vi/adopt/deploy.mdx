import { Steps, Aside } from '@astrojs/starlight/components';

**Kết quả:** một lần quét Trivy trên mọi lần push lên `main`, một workflow Deploy ship mỗi `main` xanh
lên một stage development, các lần deploy production chờ một người, và, nếu bạn muốn, một agent
Tester test mỗi thay đổi đã merge trên stage development.

Chi tiết của bước này là riêng cho Discava (AWS, CDK), nhưng cấu trúc thì dùng được cho mọi cloud. Ứng
dụng ghi chú ví dụ trong repository này không có deploy, nên hãy chép từ
[`deploy.yml` của Discava](https://github.com/AlexTo/discava/blob/main/.github/workflows/deploy.yml).

<Steps>

1. **Thêm target `trivy`** vào các project bạn muốn quét (`pnpm trivy` ở gốc chạy
   `nx run-many --target trivy --all`). Thêm job `trivy` vào `ci.yml`, như trong repository này. Giữ
   nó là một job tách khỏi `build`, để một CVE mới công bố gắn cờ `main` mà không chặn thứ gì khác. Ghi
   các phát hiện được chấp nhận, mỗi dòng một ID, trong `.trivyignore`.

2. **Thiết lập truy cập cloud không cần key.** Trên AWS, `scripts/setup-stage.sh` của Discava tạo,
   cho mỗi stage: GitHub OIDC provider, một deploy role chỉ được tin cậy cho
   `repo:owner/repo:environment:<stage>`, một CloudFormation execution role với permissions boundary,
   và các biến của GitHub environment (`AWS_REGION`, `AWS_DEPLOY_ROLE_ARN`, `AWS_EXECUTION_ROLE_ARN`).
   Dùng OIDC federation của cloud bạn cho GitHub Actions theo cùng cách. Đừng lưu access key.

3. **Thêm workflow Deploy**, kích hoạt khi CI hoàn tất trên `main` và chạy thủ công:

   ```yaml
   on:
     workflow_run: { workflows: [CI], types: [completed], branches: [main] }
     workflow_dispatch:
       inputs: { stage: { type: string, required: true } }

   jobs:
     deploy:
       if: ${{ github.event_name == 'workflow_dispatch' ||
               (github.event.workflow_run.conclusion == 'success' && vars.AUTO_DEPLOY_STAGE != '') }}
       environment: ${{ inputs.stage || vars.AUTO_DEPLOY_STAGE }}
       concurrency: { group: 'deploy-${{ inputs.stage || vars.AUTO_DEPLOY_STAGE }}', cancel-in-progress: false }
       steps:
         - uses: actions/checkout@<sha>
           with: { ref: '${{ github.event.workflow_run.head_sha || github.sha }}' }
         # init, then: pnpm trivy, configure credentials (OIDC), synth
         - name: Check commit is still main's latest
           id: freshness
           if: ${{ github.event_name == 'workflow_run' }}
           run: |
             main_sha="$(git ls-remote --exit-code origin refs/heads/main | cut -f1)"
             if [[ "$main_sha" == "$(git rev-parse HEAD)" ]]; then
               echo "current=true" >> "$GITHUB_OUTPUT"
             else
               echo "::notice::Skipping deploy: no longer main's latest commit"
               echo "current=false" >> "$GITHUB_OUTPUT"
             fi
         - name: Deploy
           if: ${{ github.event_name != 'workflow_run' || steps.freshness.outputs.current == 'true' }}
           run: pnpm nx run @your-scope/infra:deploy-ci "$STAGE/*" --role-arn "$AWS_EXECUTION_ROLE_ARN"
   ```

   Kiểm tra độ mới nằm *bên trong* slot concurrency, nên nó phản ánh `main` ngay trước khi deploy, kể
   cả khi lần chạy phải chờ sau một lần chạy khác.

4. **Bật deploy tự động** cho stage development. Trong **Settings → Secrets and
   variables → Actions → Variables**, thêm một repository variable `AUTO_DEPLOY_STAGE` với tên
   stage development của bạn.

5. **Bảo vệ production.** Trong **Settings → Environments**, mở environment của stage production
   và thêm **Required reviewers**. Để deploy nó, mở **Actions → Deploy → Run workflow** và nhập
   stage production. Job khi đó chờ được duyệt.

6. **Thêm agent Tester**, nếu bạn muốn mỗi thay đổi đã deploy được test (khoảng trống 11). Đây là
   mảnh mới nhất, và nó nằm trong Discava, không phải trong repository này. Hãy chép từ đó:

   - `packages/tooling/agent/src/post-merge-test/` và `src/helpers/`, cùng Nx target
     `post-merge-test`
   - `.github/workflows/post-merge-verify.yml`
   - `.github/ISSUE_TEMPLATE/test-deployed-pr.md`, để mở một issue test thủ công

   Sau đó đặt tên stage (`TEST_STAGE`), và các đường dẫn không bao giờ đến một stack đã deploy
   (`NOT_DEPLOYED` trong `plan.ts`), cho khớp với repository của bạn.

   Ở phía OpenHands, thêm một agent profile `tester` và một automation poll các issue có label
   `openhands-test`. Không có template catalog nào cho nó. Worker của Discava và prompt của nó được
   mô tả ở [Thiết lập OpenHands](../../discava/openhands-setup/#tester-github-issue-tester)
   và [Prompt của các agent](../../discava/agent-prompts/#tester). Hãy cấp cho Tester:

   - một cloud CLI đã đăng nhập vào tài khoản development, với quyền truy cập ít nhất mà việc test cần
   - một người dùng test cho mỗi vai trò trong ứng dụng của bạn, lưu dưới dạng secret của OpenHands
   - một trình duyệt nó điều khiển được, như Playwright với Chromium

   <Aside type="caution" title="Repository công khai? Hãy giới hạn comment cho collaborator trước">
   Tester đọc issue, pull request và các comment của chúng trong khi đang giữ các thông tin đăng nhập
   đó. Nếu repository của bạn công khai, comment của một người lạ có thể mang chỉ dẫn đến nó. Trước
   khi bật nó, hãy mở **Settings → Moderation options → Interaction limits** và chọn **Limit to
   repository collaborators**. Giới hạn này kéo dài tối đa sáu tháng, nên hãy ghi lại khi nào cần gia
   hạn.

   Đồng thời giữ việc khóa trong `helpers/conversation-lock.ts`, giữ phần "test như thế nào" trong prompt
   riêng của automation thay vì trong issue, và đừng bao giờ trỏ nó vào một stage có dữ liệu quan trọng.
   </Aside>

</Steps>

## Kiểm tra kết quả

Merge một PR bất kỳ. CI chạy, rồi **Deploy** tự khởi động với stage development. Chạy lại CI thủ công
trên một commit cũ hơn: Deploy log `Skipping deploy: no longer main's latest commit` và không ship gì.

Khi đã thiết lập Tester: sau lần deploy đó, **Post-merge Verify** mở một issue đã khóa có tiêu đề
`test(post-merge): verify #<pr> …`, với label `openhands-test`. Trong vòng một lần poll, Tester khởi
động, và báo cáo của nó xuất hiện dưới dạng một comment trên issue.

<Aside type="note">
Không agent nào deploy, và không agent nào thấy các role này. Developer và Reviewer chỉ cần GitHub
token. Quyền truy cập của Tester vào tài khoản development tách biệt với deploy role, vốn chỉ được
assume bởi một workflow chạy từ `main`, trong environment của stage.
</Aside>

Tiếp theo: repository của bạn giờ đã có mọi thứ mà một bản fork của repository này có. Tiếp tục từ
[2. Cấu hình repository](../../setup/github-repository/), với repository của chính bạn thay cho
bản fork.
