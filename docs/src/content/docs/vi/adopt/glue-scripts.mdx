import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**Kết quả:** một project `tooling-agent` với mười Nx target và 223 unit test pass. Các workflow ở bước
6, 7 và 9 chỉ gọi những target này.

<Steps>

1. **Chép `packages/tooling/agent/`** từ repository này, nguyên vẹn. `project.json` của nó đã khai
   báo mọi target mà các workflow gọi, và `AGENTS.md` của nó cho agent biết mỗi thư mục chứa gì:

   <FileTree>
   - packages/tooling/agent/src/
     - agent-issues/ spec → issue, bộ validate `tasks.md`, và lưu trữ các spec đã xong
     - agent-ci/ CI đỏ → agent
     - agent-review/ "changes requested" → agent
     - helpers/ khóa các issue mà agent đọc, và phân biệt tác giả tin cậy với người lạ
     - ui-screenshots/ quy tắc ảnh chụp màn hình, và comment `E2E screenshots`
     - invariant-coverage/ code nào ghi entity nào, và quy tắc rằng writer mới cần invariant
     - post-merge-test/ PR đã deploy → issue test cho Tester
   </FileTree>

   Chúng chỉ phụ thuộc vào built-in của Node, TypeScript (cho việc quét invariant) và CLI `gh`.
   `tsx` chạy chúng. Thêm thư mục này vào `pnpm-workspace.yaml` và các reference trong
   `tsconfig.json` ở gốc của workspace nếu các glob của bạn chưa bao gồm `packages/tooling/*`.

2. **Đổi tên scope.** Thay `@agentic-sdlc/` bằng scope của workspace của bạn trong `package.json`,
   `project.json` và `vitest.config.mts` của project, và trong comment của các file `main.ts` của nó.
   Mọi workflow bạn chép sau này cũng nêu tên `@agentic-sdlc/tooling-agent`.

3. **Đổi các hằng số cho thiết lập của bạn.** Các hằng số in đậm trỏ vào ứng dụng ghi chú của
   repository này, nên bạn gần như chắc chắn sẽ đổi chúng. Phần còn lại chỉ đổi nếu bạn đã thay đổi
   một quyết định trong [phần tổng quan](../overview/):

   | Hằng số | File | Mặc định |
   | --- | --- | --- |
   | **`UI_SOURCE`** | `ui-screenshots/check.ts` | `.tsx`/`.css` dưới `packages/notes-website/src/` và `packages/common/shadcn/src/` |
   | **`WRITER_PACKAGES`**, **`ENTITIES_PACKAGE`** | `invariant-coverage/scan.ts` | Các package có code ghi vào bảng, và package chứa các entity của nó (`notes-table`) |
   | **`WRITER_MAP_PATH`**, **`INVARIANTS_PATH`**, **`HELPERS`** | `invariant-coverage/check.ts` | `packages/notes-table/entity-writers.json`, `packages/notes-table/src/helpers/invariants`, `notes-table` |
   | **`UI_PATHS`**, **`NOT_DEPLOYED`** | `post-merge-test/plan.ts` | Những gì được tính là thay đổi UI đáng để bấm thử, và các đường dẫn không bao giờ đến một stack đã deploy |
   | `SPEC_READY_LABEL`, `AGENT_BRANCH_PREFIX` | `agent-issues/gate.ts` | `spec-ready`, `openhands/` |
   | `AGENT_LABEL` | `agent-issues/issue.ts` | `openhands` |
   | `AGENT_BRANCH`, `REVIEW_STATUS_CONTEXT`, `MAX_CI_FIX_ATTEMPTS` | `agent-ci/plan.ts` | `^openhands\/issue-\d+$`, `software-factory/review`, `5` |
   | `MAX_REVIEW_FIX_ATTEMPTS`, `CHANGES_REQUESTED` | `agent-review/plan.ts` | `5`, `🔄 CHANGES REQUESTED` |
   | `WAIVER_LABEL` | `ui-screenshots/check.ts`, `invariant-coverage/check.ts` | `no-ui-screenshots`, `no-new-invariant` |

   Nếu bạn chưa kiểm tra invariant, cứ để thư mục `invariant-coverage` ở đó và đừng chép job PR
   Checks của nó ở bước 6. Một số unit test đọc các file invariant thật, nên hãy cập nhật các test
   đó (trong `invariant-coverage/check.test.ts`) hoặc các đường dẫn ở trên.

   <Aside type="caution">
   Đừng đổi `REVIEW_STATUS_CONTEXT`. `software-factory/review` là status mà worker issue-to-PR của
   OpenHands tìm. Bất kỳ tên nào khác thì agent sẽ không bao giờ được gửi quay lại.
   </Aside>

4. **Chạy test.**

   ```bash
   pnpm nx run @your-scope/tooling-agent:test
   ```

</Steps>

## Thử chạy dry run

Mỗi script agent đọc sự kiện GitHub từ `GITHUB_EVENT_PATH`, và với `DRY_RUN=true` in ra quyết định
của nó thay vì thực hiện. Để phát lại một trường hợp thật, lưu một payload từ một lần chạy workflow
trước đây và trỏ script vào đó:

```bash
DRY_RUN=true GITHUB_REPOSITORY=owner/repo GITHUB_EVENT_PATH=./event.json \
  pnpm nx run @your-scope/tooling-agent:agent-ci-status
```

```json
{
  "pullRequest": 470,
  "plan": {
    "action": "send-back",
    "attempt": 1,
    "label": "ci-fix-1",
    "description": "CI failed (fix attempt 1 of 5): E2E tests (4/4)"
  }
}
```
