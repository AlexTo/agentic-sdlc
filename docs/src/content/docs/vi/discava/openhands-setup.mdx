Agent của Discava chạy trên một máy trạm Linux, dưới OpenHands Agent Canvas. Không có bản deploy
OpenHands trên cloud và không có webhook. Mọi thứ là poll ra ngoài tới GitHub.

## Agent Canvas

Agent Canvas 1.41.0, cài từ npm (`@openhands/agent-canvas`) và chạy như một user service. Trạng
thái của nó nằm trong `~/.openhands/`: cài đặt, agent profile, secret và database SQLite của các
automation.

## Cài đặt cuộc hội thoại

Các cài đặt định hình cách agent làm việc:

| Cài đặt | Giá trị | Vì sao |
| --- | --- | --- |
| Agent | ACP, server `claude-code` | Một coding agent bên ngoài, qua Agent Client Protocol |
| ACP prompt timeout | 30 phút | Một lượt triển khai thì dài |
| Max iterations | 500 | Đủ chỗ cho cả một giai đoạn trong một cuộc hội thoại |
| Confirmation mode | tắt | Không người giám sát. Không có ai ở đó để xác nhận |
| Security analyzer | LLM | Các lệnh vẫn được sàng lọc rủi ro |
| Runtime | local | Chạy trên host, nơi Node, pnpm và git đã có sẵn |
| Worktree branch prefix | `openhands/` | Mọi nhánh agent tạo đều bắt đầu bằng tiền tố này. Glue dựa vào nó |

## Agent profile

Mỗi vai trò agent một profile:

| Profile | Vai trò | Agent | Model | Dùng bởi |
| --- | --- | --- | --- | --- |
| `developer` | Developer | Claude Code (ACP) | Sonnet | GitHub issue to PR |
| `reviewer` | Reviewer | Claude Code (ACP) | Opus | GitHub code review |
| `tester` | Tester | Claude Code (ACP) | Opus | GitHub issue tester |

Mỗi profile có prompt timeout 30 phút.

## Secret

Lưu trong Agent Canvas (**Settings → Secrets**), theo tên:

| Tên | Dùng cho |
| --- | --- |
| `GITHUB_PERSONAL_ACCESS_TOKEN` | Các automation đọc GitHub bằng nó. Các cuộc hội thoại nhận nó để clone, push, mở PR, review và comment |
| `OPENHANDS_AUTOMATION_API_KEY` | Key riêng của backend automation |
| `DISCAVA_STUDENT_USERNAME`, `DISCAVA_STUDENT_PASSWORD` | Student của Tester trên `discava-development` |
| `DISCAVA_INSTRUCTOR_USERNAME`, `DISCAVA_INSTRUCTOR_PASSWORD` | Instructor của Tester |
| `DISCAVA_ADMIN_USERNAME`, `DISCAVA_ADMIN_PASSWORD` | Admin của Tester |

GitHub token là một classic personal access token trên `discava-bot`, một tài khoản máy chỉ các
automation dùng. Tài khoản này là collaborator có quyền ghi, và token có các scope `repo` và
`workflow`.

Sáu secret `DISCAVA_*` là các người dùng test Cognito trên stage development, mỗi vai trò trong ứng
dụng một người. Tester đăng nhập vào các cổng bằng chúng và lấy API token bằng chúng.

## Tester có gì trên máy

Developer và Reviewer chỉ cần Node, pnpm, git và `gh`. Tester còn dùng:

| Công cụ | Để làm gì |
| --- | --- |
| AWS CLI, đã đăng nhập vào tài khoản chứa các stack `discava-development-*` | Tìm stage (output của stack), lấy Cognito token, đọc DynamoDB, S3 và CloudWatch log. Prompt của nó bảo nó chỉ dùng để đọc |
| Playwright với Chromium | Điều khiển các cổng đã deploy |
| `tmp/screenshots/` của bản checkout Discava | Nơi lưu ảnh chụp màn hình của nó, mỗi pull request một thư mục |

<Aside type="caution">
Đây là nơi duy nhất một agent ở Discava làm việc với quyền truy cập cloud. Đó là lý do stage là
`discava-development`, với dữ liệu bỏ đi được, và là lý do
[chỉ các collaborator mới comment được](../post-merge-verify/#ai-có-thể-comment) trên những gì các agent đọc. Với một team, hãy cho Tester một role chỉ đọc riêng và một
máy hoặc VM riêng.
</Aside>

## Ba automation

Hai cái đầu được cài từ catalog automation của Agent Canvas, không phải viết tay. Cái thứ ba là của
riêng Discava. Mỗi automation làm gì trong một lần poll được mô tả ở
[Runtime của agent](../../concepts/the-agent-runtime/#ba-automation), và prompt mà mỗi cái giao cho
agent của nó nằm ở [Prompt của các agent](../agent-prompts/).

### Developer: GitHub issue to PR

| Trường | Giá trị |
| --- | --- |
| Template | `github-issue-to-pr` 1.2.4 |
| Repository | `AlexTo/discava` |
| Label kích hoạt | `openhands` |
| Tiền tố nhánh | `openhands/issue` → nhánh `openhands/issue-<n>` |
| Chế độ pull request | Ready for review |
| Secret GitHub token | `GITHUB_PERSONAL_ACCESS_TOKEN` |
| Lịch | `*/5 * * * *`, Australia/Sydney |
| Agent profile | `developer` |

Một lượt revise bảo agent gắn lại label
`openhands-review` sau đó, để head mới được review.

### Reviewer: GitHub code review

| Trường | Giá trị |
| --- | --- |
| Template | `github-pr-reviewer` 1.11.2 |
| Repository | `alexto/discava` |
| Label kích hoạt | `openhands-review` |
| Requested reviewer | `all-hands-bot` (không dùng trên thực tế: label làm việc này) |
| Review mới mỗi lần quét | 2 |
| Giọng review | Concise |
| Maintainer | không có |
| Lịch | `*/5 * * * *`, Australia/Sydney |
| Agent profile | `reviewer` |

Trong khi các check vẫn đang chạy, Reviewer đăng một comment "⏳ Review waiting on checks" và thử lại
ở một lần quét sau. Các review của nó bắt đầu bằng "_This review was posted by an AI agent
(OpenHands)._" và mang một marker ẩn `<!-- openhands-review-run: <id> -->`.

### Tester: GitHub issue tester

Không có template catalog nào cho cái này. Nó là một worker khoảng một trăm dòng, xây trên cùng các
helper GitHub và hội thoại mà các template catalog dùng, với prompt của nó trong một file nằm bên
cạnh.

| Trường | Giá trị |
| --- | --- |
| Template | không có: `worker.py`, `prompt.md` và `config.json`, viết tay |
| Repository | `AlexTo/discava` |
| Label kích hoạt | `openhands-test` |
| Tác giả issue | `github-actions[bot]` |
| Tiền tố nhánh | `openhands/test-fix` → nhánh sửa `openhands/test-fix-<n>` |
| Test mới mỗi lần quét | 2 |
| File prompt | `prompt.md` |
| Secret GitHub token | `GITHUB_PERSONAL_ACCESS_TOKEN` |
| Lịch | `*/5 * * * *`, Australia/Sydney |
| Agent profile | `tester` |

Ở mỗi lần poll, worker:

1. Liệt kê các issue đang mở mang `openhands-test`, số nhỏ nhất trước.
2. Bỏ qua mọi issue không do một trong các **tác giả issue** mở. Nội dung của một issue trở thành
   một phần những gì agent đọc, nên chỉ các issue của chính workflow mới được test.
3. Tìm sự kiện mới nhất đã gắn label. Số issue và ID của sự kiện đó tạo thành một lần giao, nên một
   lần poll sau của cùng lần gắn label bị bỏ qua, và comment của chính Tester không bao giờ khởi
   động lần test thứ hai. Gỡ và gắn lại label là một sự kiện mới, và do đó là một lần test mới.
4. Bắt đầu hoặc tiếp tục cuộc hội thoại của issue với prompt, tối đa hai lần test mới mỗi lần poll.

Các issue nó poll được mở bởi [Post-merge Verify](../post-merge-verify/). Các comment của Tester kết
thúc bằng "_This comment was posted by an AI agent (OpenHands)._".

<Aside title="Một tài khoản cho các agent">
Ở Discava, Developer, Reviewer và Tester đều đăng dưới tên `discava-bot`, còn maintainer dùng tài
khoản của mình. Nhờ vậy maintainer có thể duyệt PR của agent bình thường, và dễ thấy comment nào do
agent viết. Reviewer và Developer vẫn dùng chung một tài khoản, và GitHub không cho một tài khoản
duyệt PR của chính nó, nên verdict của Reviewer được đăng dưới dạng review `COMMENTED`. Glue đọc dòng
verdict chứ không đọc trạng thái review, nên điều này không ảnh hưởng gì.
</Aside>
