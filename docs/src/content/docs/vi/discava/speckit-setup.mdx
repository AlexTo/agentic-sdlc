Discava dùng Speckit 1.3.2 gần như nguyên bản. Các thay đổi quan trọng nằm ở hai template, để những
gì Speckit viết ra có thể được automation đọc.

## Cấu hình

`.specify/init-options.json`, được `specify init` viết ra:

```json
{
  "ai": "claude",
  "ai_skills": true,
  "feature_numbering": "timestamp",
  "here": true,
  "integration": "claude",
  "script": "sh",
  "speckit_version": "1.3.2"
}
```

- **Tích hợp dưới dạng skill.** Các lệnh được cài dưới dạng skill (`/speckit-specify`,
  `/speckit-plan`, …) cho coding agent của team.
- **Đánh số theo timestamp.** Thư mục spec được đặt tên `YYYYMMDD-HHMMSS-<name>`, không phải
  `001-<name>`. Hai người viết spec trên hai nhánh trong cùng một ngày không bao giờ trùng số.

## Extension git

Extension `git` đi kèm Speckit được cài (`.specify/extensions.yml`). Các hook của nó tạo một nhánh
tính năng trước `/speckit-specify` và commit sau mỗi bước, nên mỗi bước viết spec là một
Conventional Commit riêng trong spec PR.

## Thay đổi template

### `spec-template.md`: một dòng parent issue

```markdown
**Parent issue**: [#<number>, or "none" if there is no tracking issue]
```

Script Agent Issues đọc dòng này và ghi `Refs #<parent>` vào mọi issue triển khai, để tracking issue
của tính năng liên kết đến mọi PR.

### `tasks-template.md`: khối định dạng và task test

Ba bổ sung vào template gốc:

1. **Test không phải tùy chọn.** Template gốc nói test là tùy chọn. Template của Discava nói
   constitution yêu cầu chúng, và mỗi giai đoạn user story mang ba task mẫu: unit test, một invariant
   cùng một test phá vỡ nó (nếu một quy tắc trải trên nhiều bản ghi), và một kịch bản e2e (nếu nó
   thay đổi một luồng chính).
2. **Ai chạy gì.** Một đoạn nói rằng agent triển khai các task này mà không có Docker, rằng e2e test
   và test đồng thời chạy trên PR CI, và **(human)** có nghĩa là gì. Bao gồm cả "không dùng cho ảnh
   chụp màn hình": một thay đổi UI chụp ảnh trong e2e.
3. **Read by automation.** Các [quy tắc định dạng](../../reference/tasks-format/) mà bộ validate
   thực thi, được nêu trong template để agent viết `tasks.md` tuân theo.

Và một dòng được thêm vào phần ghi chú ở cuối: "Do not edit existing tests to make them pass. If one
looks wrong, stop and raise it."

Nguyên văn của từng thay đổi nằm trong
[Áp dụng: constitution và template](../../adopt/constitution-and-templates/).

## Một spec được viết thế nào

1. Một người mở một tracking issue cho tính năng, như #279 "course ratings and written reviews".
2. Một coding agent chạy `/speckit-specify` với nội dung issue, rồi `/speckit-clarify`. Khi không có
   ai để trả lời, agent chọn câu trả lời được khuyến nghị và ghi lại dưới mục "Clarifications" trong
   spec.
3. `/speckit-plan`, `/speckit-tasks`, `/speckit-analyze`. Các phát hiện từ analyze được sửa trong
   cùng PR. Bạn có thể thấy điều này trong lịch sử của Discava qua các commit như "resolve analysis
   findings in the public pages spec".
4. Spec PR được gắn label `spec-ready` và merge.
