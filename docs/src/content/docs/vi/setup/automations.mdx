**Kết quả:** OpenHands poll bản fork của bạn mỗi năm phút. Nó triển khai các issue có label
`openhands`, sửa lại các PR bị đánh dấu thất bại, và review các PR có label `openhands-review`.

Cả hai automation đến từ **automation catalog** của Agent Canvas. Bạn điền một form, và catalog đóng
gói một worker đã được test với các cài đặt của bạn. Bạn không phải viết hay upload code nào.

<Steps>

1. **Thêm "GitHub issue to PR"** từ catalog, với các cài đặt sau:

   | Trường | Giá trị |
   | --- | --- |
   | Repositories | `<you>/agentic-sdlc` |
   | Trigger label | `openhands` |
   | Branch prefix | `openhands/issue` |
   | Pull request mode | Draft |
   | GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
   | Agent profile | `default` |
   | Check frequency | `*/5 * * * *` |
   | Timezone | múi giờ của bạn |

   Discava chạy template phiên bản 1.2.4. Prompt của worker bảo agent thêm label `openhands-review`
   sau khi mở PR, để PR mới đến được reviewer kể cả khi là draft.

2. **Thêm "GitHub code review"** từ catalog:

   | Trường | Giá trị |
   | --- | --- |
   | Repositories | `<you>/agentic-sdlc` |
   | Trigger label | `openhands-review` |
   | Requested reviewer | login GitHub của agent |
   | New reviews per scan | `2` |
   | Review tone | Concise |
   | Maintainers | để trống, hoặc hai login trở lên (xem bên dưới) |
   | GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
   | Agent profile | `reviewer` |
   | Check frequency | `*/5 * * * *` |

   Discava chạy template phiên bản 1.11.2. **New reviews per scan** giới hạn số cuộc hội thoại review
   mà một lần poll khởi động, để một đống việc tồn đọng không khởi động mười agent cùng lúc.

   **Maintainers** là tùy chọn. Khi được đặt, một PR đã duyệt được giao cho một trong số họ làm
   requested reviewer, chọn theo người đã từng thay đổi các file đó. Điều này chỉ xảy ra khi issue của
   PR mang `priority:medium` hoặc `priority:high`. Discava để trống.

3. **Chạy mỗi automation một lần thủ công** từ trang của nó trong Agent Canvas, và đọc log lần chạy.

</Steps>

## Kiểm tra kết quả

Một lần chạy đầu không có gì để làm sẽ log một lượt quét repository và kết thúc bằng `COMPLETED`.
Sau đó:

1. Tạo một issue thử: "Add a line to README.md saying hello", và thêm label `openhands`.
2. Trong vòng một lần poll, một cuộc hội thoại cho issue xuất hiện trong Agent Canvas.
3. Khi agent xong, một draft PR xuất hiện trên `openhands/issue-<n>`, với tiêu đề `[#<n>] <issue
   title>`, và đã được thêm `openhands-review`.
4. Khi các check của nó xong, reviewer đăng một review bắt đầu bằng
   "_This review was posted by an AI agent (OpenHands)._" và kết thúc bằng `✅ APPROVED` hoặc
   `🔄 CHANGES REQUESTED`.

Sau đó đóng PR và xóa nhánh.

## Những gì chạy ở mỗi lần poll

| Automation | Ở mỗi lần poll |
| --- | --- |
| Issue to PR | 1. Với mỗi PR `openhands/issue-<n>` đang mở có head mang `software-factory/review` = `failure` hoặc `error`, gửi một lượt revise đến cuộc hội thoại của issue đó. 2. Với mỗi issue đang mở có `openhands` và chưa có PR, bắt đầu một lượt implement. Issue có label `priority:high` được làm trước |
| Code review | Với mỗi PR có `openhands-review`, có yêu cầu review cho tài khoản của nó, hoặc đang mở, không phải draft và chưa được review: nếu mọi check trên head đã xong, review đúng commit đó. Nếu không, comment "⏳ Review waiting on checks" và thử lại ở lần poll sau |

<Aside type="note">
Để cho agent thử lại một issue từ đầu, gỡ rồi gắn lại label `openhands`. Việc revise chỉ xảy ra qua
status `software-factory/review`, do các workflow glue đăng. Bạn cũng có thể đăng nó thủ công, để gửi
agent quay lại với comment của riêng bạn:
`gh api repos/<you>/agentic-sdlc/statuses/<sha> -f state=failure -f context=software-factory/review -f description="See my comment"`.
</Aside>
