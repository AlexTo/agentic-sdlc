**Kết quả:** OpenHands poll bản fork của bạn mỗi năm phút. Nó triển khai các issue có label
`openhands`, sửa lại các PR bị đánh dấu thất bại, và review các PR có label `openhands-review`.
Đây là các agent Developer và Reviewer.

Cả hai automation đến từ **automation catalog** của Agent Canvas. Bạn điền một form, và catalog
đóng gói một worker đã được test với các cài đặt của bạn. Bạn không phải viết hay upload code nào.

<Steps>

1. **Thêm "GitHub issue to PR"** từ catalog, với các cài đặt sau:

   | Trường | Giá trị |
   | --- | --- |
   | Repositories | `<you>/agentic-sdlc` |
   | Trigger label | `openhands` |
   | Branch prefix | `openhands/issue` |
   | Pull request mode | Ready for review |
   | GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
   | Agent profile | `developer` |
   | Check frequency | `*/5 * * * *` |
   | Timezone | múi giờ của bạn |

   Discava chạy template phiên bản 1.2.4. Prompt của worker bảo agent thêm label
   `openhands-review` sau khi mở PR, để mọi PR mới đều đến được Reviewer.

2. **Thêm "GitHub code review"** từ catalog:

   | Trường | Giá trị |
   | --- | --- |
   | Repositories | `<you>/agentic-sdlc` |
   | Trigger label | `openhands-review` |
   | Requested reviewer | login GitHub của agent |
   | New reviews per scan | `2` |
   | Review tone | Concise |
   | Maintainers | để trống, hoặc hai login trở lên (xem bên dưới) |
   | GitHub token secret | `GITHUB_PERSONAL_ACCESS_TOKEN` |
   | Agent profile | `reviewer` |
   | Check frequency | `*/5 * * * *` |

   Discava chạy template phiên bản 1.11.2. **New reviews per scan** giới hạn số cuộc hội thoại
   review mà một lần poll khởi động, để một đống việc tồn đọng không khởi động mười agent cùng lúc.

   **Maintainers** là tùy chọn. Khi được đặt, một PR đã duyệt được giao cho một trong số họ làm
   requested reviewer, chọn theo người đã từng thay đổi các file đó. Điều này chỉ xảy ra khi issue
   của PR mang `priority:medium` hoặc `priority:high`. Discava để trống.

3. **Chạy mỗi automation một lần thủ công** từ trang của nó trong Agent Canvas, và đọc log lần chạy.

</Steps>

## Kiểm tra kết quả

Một lần chạy đầu không có gì để làm sẽ log một lượt quét repository và kết thúc bằng `COMPLETED`.
Sau đó:

1. Tạo một issue thử: "Add a line to README.md saying hello", và thêm label `openhands`.
2. Trong vòng một lần poll, một cuộc hội thoại cho issue xuất hiện trong Agent Canvas.
3. Khi agent xong, một PR xuất hiện trên `openhands/issue-<n>`, với tiêu đề `[#<n>] <issue
   title>`, và đã được thêm `openhands-review`.
4. Khi các check của nó xong, agent Reviewer đăng một review bắt đầu bằng
   "_This review was posted by an AI agent (OpenHands)._" và kết thúc bằng `✅ APPROVED` hoặc
   `🔄 CHANGES REQUESTED`.

Sau đó đóng PR và xóa nhánh.

Mỗi automation làm gì ở một lần poll được mô tả ở [Runtime của agent](../../concepts/the-agent-runtime/).

<Aside type="tip" title="Vai trò thứ ba: Tester">
Discava chạy một automation thứ ba, Tester, test mỗi thay đổi đã merge trên stage development đã
deploy của nó. Nó cần một bản deploy để test, nên nó không thuộc thiết lập này. Khi repository của
bạn tự deploy, xem [Kiểm chứng sau merge](../../discava/post-merge-verify/) và
[Prompt của các agent](../../discava/agent-prompts/).
</Aside>

<Aside type="note">
Để cho agent thử lại một issue từ đầu, gỡ rồi gắn lại label `openhands`. Để gửi agent quay lại một
PR đang mở với comment của riêng bạn, hãy đăng status mà các workflow glue đăng:
`gh api repos/<you>/agentic-sdlc/statuses/<sha> -f state=failure -f context=software-factory/review -f description="See my comment"`.
</Aside>
