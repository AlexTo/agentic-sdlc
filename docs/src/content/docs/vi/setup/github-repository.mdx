**Kết quả:** Issues và Actions được bật, mọi label mà quy trình dùng, một nhánh `main` chỉ nhận pull
request có check xanh và một lượt duyệt, comment được giới hạn cho các collaborator, và tài khoản
riêng của agent là một collaborator.

Bản fork sao chép code, không sao chép thiết lập. `scripts/setup-repository.sh` đặt tất cả chúng bằng
CLI `gh`. Mỗi bước đặt cùng một trạng thái mỗi lần, nên chạy lại cũng an toàn.

<Steps>

1. **Tạo tài khoản của agent.** Agent làm việc dưới tài khoản GitHub riêng của chúng, một tài khoản
   máy không dùng cho việc gì khác. Tài khoản của Discava là `discava-bot`. Hãy tạo một tài khoản.
   Token của nó là token bạn tạo ở [bước 3](../openhands/), và PR cùng comment của agent hiện dưới
   tài khoản đó, nên bạn duyệt chúng như của bất kỳ ai khác.

2. **Chạy script** từ bản clone của bạn, đăng nhập `gh` bằng chủ sở hữu bản fork, với tài khoản của
   agent:

   ```bash
   ./scripts/setup-repository.sh <you>/agentic-sdlc <agents-account>
   ```

   Thêm `--dry-run` trước nếu bạn muốn xem từng lệnh `gh` trước khi nó chạy. Script này đặt:

   | Đặt | Vì sao |
   | --- | --- |
   | Bật Issues và Actions | GitHub tắt cả hai trong bản fork, mà quy trình chạy trên issue |
   | 20 label | Mọi label trong [Tham khảo: label](../../reference/labels/) |
   | Branch protection trên `main` | Một pull request, một lượt duyệt, lượt duyệt cũ bị hủy, và bảy check bắt buộc: `Checks (lint)`, `Checks (test)`, `Checks (build)`, `Tasks format`, `Invariant coverage`, `E2E tests`, `UI Screenshots` |
   | Token của workflow chỉ đọc, và Actions không được mở hay duyệt pull request | Một workflow có thể mở pull request thì cũng có thể duyệt một pull request. Archive Specs push nhánh chuyển một spec đã xong vào `specs/_archive/` và cảnh báo kèm một liên kết mở pull request của nó, đã điền sẵn, để bạn gửi |
   | Tương tác giới hạn cho collaborator, trong sáu tháng | Một bản fork của một repository công khai cũng công khai, và các agent đọc mọi comment trên những gì chúng làm việc trong khi đang giữ một token có thể push |
   | GitHub Pages từ Actions | Job **Deploy Docs** của CI publish trang web này |
   | Tài khoản của agent được mời với quyền ghi | Để các agent có thể push nhánh và mở pull request |

   Branch protection vẫn cho phép bypass, để bạn, với tư cách chủ sở hữu, merge được một pull request
   do chính bạn mở, chẳng hạn spec PR, vốn là PR mà GitHub không cho bạn duyệt.

3. **Chấp nhận lời mời** trong khi đăng nhập bằng tài khoản của agent.

4. **Kiểm tra Actions đã bật.** Nếu tab **Actions** của bản fork vẫn hiện **I understand my
   workflows, go ahead and enable them**, hãy bấm nó. Đôi khi GitHub vẫn đòi cú bấm đó ngay cả sau khi
   API đã bật Actions.

</Steps>

<Aside type="caution">
Giới hạn tương tác hết hạn sáu tháng sau khi bạn đặt nó, và không có gì cảnh báo bạn. Hãy ghi lại
ngày đó, và chạy lại script trước khi đến hạn. Nếu sau này bạn thêm agent Tester, vốn giữ thông tin
đăng nhập cloud, thì giới hạn này là thứ ngăn comment của một người lạ đến được nó. Xem
[Ai có thể comment](../../discava/post-merge-verify/#ai-có-thể-comment).
</Aside>

<Aside type="caution">
Đừng thêm `software-factory/review` vào các check bắt buộc. Nó là một tín hiệu cho agent, chỉ bao giờ
được đăng dưới dạng `failure`, và yêu cầu nó sẽ chặn mọi PR.
</Aside>

## Kiểm tra kết quả

Trang **Issues → Labels** của bản fork liệt kê 20 label, **Settings → Branches** hiện rule trên
`main` với bảy check bắt buộc, và **Settings → Moderation options → Interaction limits** hiện giới
hạn chỉ collaborator cùng ngày kết thúc của nó. **Settings → Collaborators** liệt kê tài khoản của
agent với vai trò **Write**.

Tiếp theo: [3. Cài OpenHands](../openhands/).
