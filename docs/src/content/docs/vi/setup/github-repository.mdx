import { Steps, Aside } from '@astrojs/starlight/components';

**Kết quả:** mọi label mà quy trình dùng, một nhánh `main` chỉ nhận pull request có check xanh
và một lượt duyệt, và comment được giới hạn cho các collaborator.

<Steps>

1. **Tạo các label.** Có 16 label, nên bước này làm bằng script nhanh hơn trên UI. Chạy nó từ bản
   clone của bạn. `--force` cập nhật label đã tồn tại, nên chạy lại cũng an toàn.

   ```bash
   gh label create spec-ready           --force --description "Merging this spec PR starts the agent"
   gh label create openhands            --force --description "OpenHands implements this issue"
   gh label create openhands-review     --force --description "OpenHands reviews this PR's head"
   gh label create no-ui-screenshots    --force --description "Waives the UI Screenshots check: a UI change with nothing to look at"
   for n in 1 2 3 4 5; do
     gh label create ci-fix-$n          --force --description "CI fix-up attempt $n of 5"
     gh label create review-fix-$n      --force --description "Review fix-up attempt $n of 5"
   done
   gh label create ci-fix-exhausted     --force --description "CI fix-ups used up; a person takes over"
   gh label create review-fix-exhausted --force --description "Review fix-ups used up; a person takes over"
   ```

2. **Bảo vệ `main`.** Trong bản fork, mở **Settings → Branches → Add classic branch protection
   rule**, và đặt:

   | Cài đặt | Giá trị |
   | --- | --- |
   | Branch name pattern | `main` |
   | Require a pull request before merging | bật, với 1 lượt duyệt bắt buộc |
   | Dismiss stale pull request approvals when new commits are pushed | bật |
   | Require status checks to pass before merging | bật, với sáu check bên dưới |
   | Do not allow bypassing the above settings | tắt |

   Sáu check: `Checks (lint)`, `Checks (test)`, `Checks (build)`, `Tasks format`, `E2E tests` và
   `UI Screenshots`. GitHub chỉ gợi ý một check trong ô tìm kiếm sau khi nó đã chạy một lần, nên
   nếu thiếu check nào, hãy mở một PR bất kỳ trước.

   Để bypass được phép cho bạn, với tư cách chủ sở hữu, merge các PR mà agent mở bằng token của
   chính bạn (xem lưu ý bên dưới).

   <Aside type="caution">
   Đừng yêu cầu status `software-factory/review`. Nó là một tín hiệu cho agent, chỉ bao giờ được
   đăng dưới dạng `failure`, và yêu cầu nó sẽ chặn mọi PR.
   </Aside>

3. **Cho phép Actions mở pull request.** Mở **Settings → Actions → General**, và trong
   **Workflow permissions** chọn **Allow GitHub Actions to create and approve pull requests**.
   Workflow Archive Specs cần nó để mở PR chuyển một spec đã xong vào
   `specs/_archive/`.

4. **Giới hạn comment cho các collaborator.** Một bản fork của một repository công khai cũng công
   khai, và các agent đọc mọi comment trên issue và pull request mà chúng làm việc, trong khi đang giữ
   một token có thể push. Mở **Settings → Moderation options → Interaction limits** và chọn **Limit to
   repository collaborators**, trong sáu tháng. Khi đó không ai khác có thể comment, mở issue hay mở
   pull request.

   <Aside type="caution">
   Giới hạn này hết hạn, tối đa sáu tháng sau khi bạn đặt nó, và không có gì cảnh báo bạn. Hãy ghi lại
   ngày đó và đặt lại trước khi đến hạn. Nếu sau này bạn thêm agent Tester, vốn giữ thông tin đăng
   nhập cloud, thì giới hạn này là thứ ngăn comment của một người lạ đến được nó. Xem
   [Ai có thể comment](../../discava/post-merge-verify/#ai-có-thể-comment).
   </Aside>

</Steps>

<Aside type="caution" title="Một tài khoản hay hai">
Lần thử đầu, agent có thể dùng token từ tài khoản của chính bạn, như Discava đã làm lúc đầu. Tuy nhiên, GitHub
không cho một tài khoản duyệt PR của chính nó. Khi đó lượt duyệt của bạn và của agent Reviewer hiện
dưới dạng comment, và bạn merge với tư cách admin của repository. Với một team, hãy cho agent một tài
khoản GitHub riêng có quyền ghi, và dùng token của nó ở [bước 3](../openhands/). Khi đó mọi người có
thể duyệt agent PR bình thường. Từ ngày 21 tháng 11 năm 2026, agent của Discava dùng tài
khoản riêng, `discava-bot`.
</Aside>

## Kiểm tra kết quả

Trang **Issues → Labels** của bản fork liệt kê 16 label mới, **Settings → Branches** hiện rule
trên `main` với sáu check bắt buộc, và **Settings → Moderation options → Interaction limits** hiện
giới hạn chỉ collaborator cùng ngày kết thúc của nó.
