**Kết quả:** OpenHands Agent Canvas đang chạy trên máy bạn dưới danh nghĩa GitHub App của bạn, và hai
agent profile: `developer` cho agent Developer và `reviewer` cho agent Reviewer.

<Steps>

1. **Cài Agent Canvas.** Discava chạy phiên bản 1.45.0:

   ```bash
   npm install -g @openhands/agent-canvas
   ```

2. **Khởi động nó dưới danh nghĩa app của bạn**, từ bản clone của bạn:

   ```bash
   pnpm agent-canvas
   ```

   Lần đầu tiên, nó hỏi **App ID** và đường dẫn tới **file `.pem`** từ
   [bước 2](../github-repository/), và giữ cả hai trong `~/.config/agent-app/`, chỉ mình bạn đọc
   được. Sau đó, mỗi lần chạy, nó:

   - khởi động Agent Canvas với app là tác giả các commit của agent, nên GitHub hiện chúng dưới
     app;
   - tạo một token của app, loại token có hiệu lực một giờ, và lưu nó trong Agent Canvas dưới dạng
     secret `GITHUB_PERSONAL_ACCESS_TOKEN`, thứ mà các automation đọc. Dù tên như vậy, GitHub token
     loại nào đặt ở đó cũng được;
   - thay token mỗi 45 phút chừng nào nó còn chạy.

   Chờ dòng `Token stored in the GITHUB_PERSONAL_ACCESS_TOKEN secret`, rồi mở
   [http://127.0.0.1:8000](http://127.0.0.1:8000). Nếu Agent Canvas hỏi dùng agent nào, hãy chọn
   Claude Code: nó tìm thấy phiên đăng nhập bạn đã có, nên hãy để trống mọi trường API key.

   Hãy để terminal mở, và luôn khởi động Agent Canvas theo cách này: các automation chỉ poll khi nó
   đang hoạt động, và token chỉ luôn mới khi lệnh này còn chạy.

3. **Tạo hai agent profile**, mỗi vai trò agent một cái. Trong Agent Canvas, mở **Settings → Agent**
   và bấm **Add agent profile**, hai lần:

   | Name | Agent type | Agent | Model |
   | --- | --- | --- | --- |
   | `developer` | ACP (external subprocess) | `claude-code` | `sonnet` |
   | `reviewer` | ACP (external subprocess) | `claude-code` | `opus` |

   ACP là Agent Client Protocol: coding agent bạn vốn dùng sẽ làm việc, đăng nhập dưới tên bạn trên
   máy này. Agent và model nào cũng được. Hãy giữ Reviewer ít nhất mạnh bằng Developer: nó là bước
   kiểm tra cuối trước bạn.

   Để nguyên mọi thứ khác. Agent Canvas vốn đã chạy không cần người trông (không có lời nhắc xác
   nhận), với đủ chỗ cho cả một giai đoạn trong một cuộc hội thoại (500 iteration).

</Steps>

## Kiểm tra kết quả

Trong Agent Canvas, **Settings → Secrets** liệt kê `GITHUB_PERSONAL_ACCESS_TOKEN`. Bắt đầu một cuộc
hội thoại với profile `developer` và hỏi nó:

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

Nó báo `<app-name>[bot]`, và một danh sách issue trống.

<Aside type="caution" title="Giữ GitHub login của chính bạn tránh xa các agent">
Đừng thêm GitHub token ở mục **Integrations** của Agent Canvas, và xóa mọi GitHub server được liệt
kê ở mục **MCP Servers**: cả hai đều giữ một token cố định, thường là của bạn, và một agent dùng nó
sẽ hành động dưới danh nghĩa bạn thay vì app.
</Aside>

<Aside type="caution">
Agent chạy lệnh trên máy này dưới user của bạn. Đừng giữ thông tin đăng nhập cloud trong môi trường
của nó, và hãy dùng một máy riêng hoặc VM khi bạn vượt quá mức thử nghiệm.
</Aside>

<Aside type="tip" title="Chạy Agent Canvas như một service">
Khi Agent Canvas chạy như một service thay vì trong một terminal, hãy cho một timer chạy
`pnpm agent-canvas --once` mỗi 45 phút: nó tạo một token, lưu token đó rồi thoát. Discava làm việc
này trên Linux bằng systemd: xem
[Thiết lập OpenHands của Discava](../../discava/openhands-setup/#github-app).
</Aside>

Discava có một profile thứ ba, `tester`, cho agent Tester. Nó test các thay đổi đã merge trên một
stage đã deploy, thứ mà ứng dụng ghi chú không có, nên bạn không cần nó ở đây.
