**完成后你将拥有：** 一份属于你自己、已批准的 constitution，以及能生成 Agent Issues workflow 可读取文件的 Speckit 模板。

你在[第 2 步](../speckit/)中复制的 `.specify/` 已经包含一份可用的 constitution 和模板，是为笔记应用编写的。这一步让它们成为你自己的。

<Steps>

1. **为你的项目改写 constitution。** 在你的编码智能体中：

   ```text
   /speckit-constitution
   ```

   把你项目自己的原则告诉它：架构、数据模型、安全默认值、代码约定。[Discava 的 constitution](../../discava/constitution-and-guidance/)是一个完整的例子。保留复制来的 constitution 中的以下部分，并根据你的技术栈调整其中的命令和包名，因为工作流的其余部分都依赖它们：

   | 保留 | 来自复制来的 constitution | 原因 |
   | --- | --- | --- |
   | 单元测试、不变式和 e2e 测试都是必需的，并且测试就是规格说明 | III. Layered Tests | 智能体不能为了让 CI 变绿而削弱测试 |
   | 一切都在 `pnpm dev` 下运行，不需要云账号 | II. Everything Runs Locally | 这样 PR CI 才能运行 e2e 套件，给智能体真实的反馈 |
   | 智能体在自己的分支和 PR 上实现，从不运行本地环境，并把需要本地环境的任务标为 **(human)** | Development Workflow | 智能体没有 Docker。它运行不了的，由 CI 运行 |
   | PR CI 是关口。智能体从不合并、从不推送到 `main`、从不编辑 CI workflow，也从不削弱测试 | Development Workflow | 这是让智能体守在自己职责范围内的东西 |

2. **修改 `tasks-template.md` 中的包路径。** 它的测试任务写的是这个仓库的包：`packages/notes-table/src/helpers/invariants/` 和 `@agentic-sdlc/e2e`。把它们改成你的包。模板的其余部分保持原样：**Read by automation** 下的格式规则、**(human)** 标记、必需的测试，以及禁止编辑已有测试的说明，都是 Agent Issues workflow 和 `Tasks format` 检查所依赖的。

3. 在 `spec-template.md` 中**保留父 issue 行**：

   ```markdown
   **Parent issue**: [#<number>, or "none" if there is no tracking issue]
   ```

   Agent Issues 会据此在每个 issue 中写入 `Refs #<parent>`。

</Steps>

## 检查是否成功

为一个很小的功能生成一份用完即弃的 spec 和任务。然后，等粘合脚本就位后（[第 5 步](../glue-scripts/)）：

```bash
pnpm nx run @your-scope/tooling-agent:validate-tasks
```

```text
1 tasks.md file(s) are in the expected format.
```

之后删除这个临时的 spec 文件夹。

<Aside type="caution">
`/speckit-tasks` 有时会写出 `### Phase 2`，或者给任务加缩进。这正是校验器要捕获的问题，所以不要放宽校验器。修改模板措辞，直到生成的文件能够通过。
</Aside>
