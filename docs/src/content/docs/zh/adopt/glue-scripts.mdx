import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**完成后你将拥有：** 一个 `common-scripts` 项目，带有六个 Nx target 和 143 个通过的单元测试。第 6 步和第 7 步中的 workflow 只调用这些 target。

<Steps>

1. **创建项目。** 从这个仓库复制 `packages/common/scripts/`（它的 `package.json`、`project.json`、`tsconfig*.json` 和 `vitest.config.mts`），并删除属于示例应用的 `src/dynamodb/`。在 `package.json` 和 `project.json` 中，以及 `vitest.config.mts` 的 `name` 中，把它重命名为 `@your-scope/common-scripts`。如果你更愿意生成一个，用 Nx Plugin for AWS 生成的 TypeScript 项目结构相同。

2. 从这个仓库的 `packages/common/scripts/src/` **复制四个粘合文件夹**：

   <FileTree>
   - packages/common/scripts/src/
     - agent-issues/ spec → issue：gate、discover、tasks、validate、issue、plan-issue、create-next-issue、main、validate-main，以及用于归档的 archive、archive-specs、archive-main
     - agent-ci/ CI → 智能体：plan、run、main
     - agent-review/ 评审 → 智能体：plan、run、main
     - ui-screenshots/ 截图规则：check、main
   </FileTree>

   它们只依赖 Node 内置模块和 `gh` CLI，由 `tsx` 运行。

3. 在项目的 `project.json` 中，于 `targets` 之下**添加这些 target**：

   ```json
   "agent-issue":         { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-issues/main.ts",    "cwd": "{projectRoot}" } },
   "archive-specs":       { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-issues/archive-main.ts", "cwd": "{projectRoot}" } },
   "agent-ci-status":     { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-ci/main.ts",        "cwd": "{projectRoot}" } },
   "agent-review-status": { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-review/main.ts",    "cwd": "{projectRoot}" } },
   "ui-screenshots":      { "executor": "nx:run-commands", "options": { "command": "tsx src/ui-screenshots/main.ts",  "cwd": "{projectRoot}" } },
   "validate-tasks":      { "executor": "nx:run-commands", "options": { "command": "tsx src/agent-issues/validate-main.ts", "cwd": "{projectRoot}" } }
   ```

4. 如果你改动了[概览](../overview/)中的任何决定，**按你的配置修改这些常量**：

   | 常量 | 文件 | 默认值 |
   | --- | --- | --- |
   | `SPEC_READY_LABEL`、`AGENT_BRANCH_PREFIX` | `agent-issues/gate.ts` | `spec-ready`、`openhands/` |
   | `AGENT_LABEL` | `agent-issues/issue.ts` | `openhands` |
   | `AGENT_BRANCH`、`REVIEW_STATUS_CONTEXT`、`MAX_CI_FIX_ATTEMPTS` | `agent-ci/plan.ts` | `^openhands\/issue-\d+$`、`software-factory/review`、`5` |
   | `MAX_REVIEW_FIX_ATTEMPTS`、`CHANGES_REQUESTED` | `agent-review/plan.ts` | `5`、`🔄 CHANGES REQUESTED` |
   | `UI_SOURCE`、`SCENARIO`、`WAIVER_LABEL` | `ui-screenshots/check.ts` | portal 和共享 UI 的 `.tsx`/`.css`、`packages/e2e/src/scenarios/*.e2e.ts`、`no-ui-screenshots` |

   `UI_SOURCE` 几乎肯定是你要改的那一个。把它指向你的前端源码。

   <Aside type="caution">
   不要修改 `REVIEW_STATUS_CONTEXT`。`software-factory/review` 是 OpenHands issue-to-PR worker 查找的 status。换成任何其他名称，智能体都永远不会被打回去。
   </Aside>

5. **运行测试。**

   ```bash
   pnpm nx run @your-scope/common-scripts:test
   ```

</Steps>

## 试一次 dry run

三个智能体脚本都从 `GITHUB_EVENT_PATH` 读取 GitHub 事件，在 `DRY_RUN=true` 时会打印出它的决定，而不是执行它。要重放一个真实的案例，从过去的某次 workflow 运行中保存一份 payload，然后让脚本指向它：

```bash
DRY_RUN=true GITHUB_REPOSITORY=owner/repo GITHUB_EVENT_PATH=./event.json \
  pnpm nx run @your-scope/common-scripts:agent-ci-status
```

```json
{
  "pullRequest": 470,
  "plan": {
    "action": "send-back",
    "attempt": 1,
    "label": "ci-fix-1",
    "description": "CI failed (fix attempt 1 of 5): E2E tests (4/4)"
  }
}
```
