import { Steps, Aside, FileTree } from '@astrojs/starlight/components';

**完成后你将拥有：** 仓库中的 `.specify/`、你的编码智能体可以使用的 `speckit-*` 命令，以及按时间戳命名的 spec 文件夹。

<Steps>

1. **安装 CLI**，固定为 Discava 使用的版本：

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. 为你的编码智能体**在仓库中初始化**，并带上内置的 git 扩展。Discava 使用的是 `claude` 集成，它会把命令安装为 skill：

   ```bash
   specify init --here --integration claude --script sh --extension git
   ```

   运行 `specify init --help` 查看其他集成。选择你团队的智能体会读取的那一个。

3. **切换为时间戳编号。** 在 `.specify/extensions/git/git-config.yml` 中：

   ```yaml
   branch_numbering: timestamp
   commit_style: conventional
   ```

   文件夹会变成 `specs/20261116-013307-course-reviews/`，而不是 `specs/001-course-reviews/`，这样两个人同时编写 spec 时永远不会冲突。

4. 在 `.specify/extensions.yml` 中**检查 git 扩展的 hook**。Discava 保留默认设置：`/speckit-specify` 之前运行 `speckit.git.feature`（创建分支），每一步之后运行 `speckit.git.commit`（每步一个 commit）。它设置了 `auto_execute_hooks: true`，让这些 hook 不经询问直接运行。

5. **提交 `.specify/`** 以及该集成的命令或 skill 文件。

</Steps>

## 检查是否成功

<FileTree>
- .specify/
  - extensions/git/ git-config.yml、命令、脚本
  - extensions.yml
  - init-options.json
  - memory/constitution.md 仍是模板，下一步填写
  - scripts/bash/
  - templates/ spec、plan、tasks、checklist 和 constitution 模板
</FileTree>

在你的编码智能体中，可以看到 `speckit-specify`、`speckit-clarify`、`speckit-plan`、`speckit-tasks`、`speckit-analyze` 和 `speckit-constitution` 命令。

<Aside type="tip">
Spec PR 放在它们自己的分支上（`spec/<name>`），而不是 `openhands/...`。git 扩展创建的功能分支用来做这个就很合适。只有智能体的分支才使用 `openhands/` 前缀。
</Aside>
