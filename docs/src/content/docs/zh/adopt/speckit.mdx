**完成后你将拥有：** 仓库中的 `.specify/`、你的编码智能体可以使用的 `speckit-*` 命令，以及按时间戳命名的 spec 文件夹。

<Steps>

1. **安装 CLI**，固定为 Discava 使用的版本：

   ```bash
   uv tool install specify-cli --from "git+https://github.com/github/spec-kit.git@v1.3.2"
   specify --version
   ```

   ```text
   specify 1.3.2
   ```

2. 从这个仓库**复制 `.specify/`**。它已经按工作流的需要配置好了：

   | 设置 | 位置 | 值 |
   | --- | --- | --- |
   | 按时间戳命名 spec 文件夹 | `extensions/git/git-config.yml` | `branch_numbering: timestamp`，这样两个人同时编写 spec 时永远不会冲突：`specs/20261116-013307-course-reviews/`，而不是 `specs/001-course-reviews/` |
   | 每一步都用 Conventional Commits | `extensions/git/git-config.yml` | `commit_style: conventional` |
   | git 扩展的 hook 不经询问直接运行 | `extensions.yml` | `auto_execute_hooks: true`：`/speckit-specify` 之前创建分支，每一步之后提交一个 commit |
   | 模板和 constitution | `templates/`、`memory/` | 已经包含[第 3 步](../constitution-and-templates/)中的改动 |

3. **为你的编码智能体添加命令。** 如果它读取 Claude Code skill，从这个仓库复制 `.claude/skills/speckit-*`。否则，让 Speckit 在一个临时文件夹中为你的智能体生成它们，然后只复制命令文件：

   ```bash
   mkdir /tmp/speckit && cd /tmp/speckit
   specify init --here --integration <your-agent> --script sh --extension git
   ```

   运行 `specify init --help` 查看集成列表。复制它为你的智能体命令创建的文件夹，而不是它的 `.specify/`，后者会撤销第 2 步。

4. **提交 `.specify/`** 以及命令或 skill 文件。

</Steps>

## 检查是否成功

<FileTree>
- .specify/
  - extensions/git/ git-config.yml、命令、脚本
  - extensions.yml
  - init-options.json
  - memory/constitution.md 笔记应用的 constitution，下一步为你的项目改写
  - scripts/bash/
  - templates/ spec、plan、tasks、checklist 和 constitution 模板
</FileTree>

在你的编码智能体中，可以看到 `speckit-specify`、`speckit-clarify`、`speckit-plan`、`speckit-tasks`、`speckit-analyze` 和 `speckit-constitution` 命令。

<Aside type="tip">
Spec PR 放在它们自己的分支上（`spec/<name>`），而不是 `openhands/...`。git 扩展创建的功能分支用来做这个就很合适。只有智能体的分支才使用 `openhands/` 前缀。
</Aside>
