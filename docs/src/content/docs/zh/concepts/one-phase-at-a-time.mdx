**简短版本：**spec 不是一次性全部交给智能体的。`tasks.md` 被拆分成多个阶段，智能体**每个 issue
拿到一组阶段**。每个 issue 变成一个 pull request。当该 pull request 合并后，下一个 issue 会自动打开，
直到没有剩余的智能体任务。

```d2
direction: right

spec: spec PR {shape: document}
i1: "issue 1\n从准备到第一个故事" {shape: page}
p1: PR 1
i2: "issue 2\n下一阶段" {shape: page}
p2: PR 2
i3: "issue 3\n最后阶段" {shape: page}
p3: PR 3
done: 不再打开任何 issue

spec -> i1: 合并
i1 -> p1
p1 -> i2: 合并
i2 -> p2
p2 -> i3: 合并
i3 -> p3
p3 -> done: 合并
```

## 为什么不一次性交出整个 spec？

- **评审仍然可行。** 把整个功能做成一个 PR，就是成千上万行没人能好好读完的代码。一个阶段则是你可以
  一次评审完的 PR。
- **每一步都建立在已合并的代码之上。** 阶段 3 从已经包含阶段 1 和 2（经过评审和测试）的 `main`
  开始，而不是从智能体自己未经评审的工作开始。
- **错误保持在小范围内。** 如果某个阶段出了问题，你扔掉的是一个 PR，而不是一个功能。
- **智能体的上下文保持聚焦。** 一个阶段是智能体从第一个测试到最后一个 commit 都能记在脑子里的范围。

## 阶段如何分组

`tasks.md` 由 `/speckit-tasks` 按阶段编写：通常是准备、基础，然后每个用户故事一个阶段，最后是
打磨。Agent Issues workflow 这样对它们分组：

| 组 | 阶段 | 原因 |
| --- | --- | --- |
| 0 | 直到并包括**第一个** `User Story` 阶段的所有内容 | 单靠准备和基础交付不出任何人能试用的东西。与 MVP 故事一起发布，第一个 PR 就是一个可用的切片 |
| 1, 2, … | 之后的每个阶段，各自单独一组 | 一个阶段，一个 issue，一个 PR |

issue 会写明它的任务范围（"Tasks `T015` to `T019` … Do not start tasks outside these
phases"），智能体每完成一项任务就在 `tasks.md` 中勾选它。

## 什么会打开下一个 issue

Agent Issues 在 pull request 合并到 `main` 时运行，并且只对两种合并采取行动：

1. **带 `spec-ready` 标签的 spec PR。** 它打开第 0 组。
2. **来自智能体分支（`openhands/…`）的 PR。** 它读取这次合并刚刚更新的 `tasks.md`，找到第一个含有
   未勾选且不是 **(human)** 的任务的组，并打开它的 issue。

其他所有合并都会被忽略，即使是编辑了 `specs/` 的合并。智能体自己的 PR 会修改 `tasks.md`，所以像
"当 `specs/**` 变化时运行"这样的规则会触发自己。

## 什么会让链条停止

| 情况 | 会发生什么 |
| --- | --- |
| 每个智能体任务都已勾选 | 不会打开任何 issue。功能完成。所有 **(human)** 任务都留给评审者 |
| 合并的 PR 没有勾选它的全部任务 | 该组的下一个 issue 已经存在，所以不会重复打开。合并的 PR 会收到一条评论，列出未勾选的任务 ID |
| `tasks.md` 不是预期的格式 | 运行会失败，而不是把错误的任务交给智能体。Tasks format PR 检查通常会更早阻止这种情况 |
| spec PR 在没有 `spec-ready` 的情况下被合并 | 不会打开任何 issue。给这个已合并的 PR 加上该标签，它就会开始 |

要重启一条停滞的链条，修好 `tasks.md`（勾选或完成任务），然后用 spec 文件夹名手动运行
**Agent Issues**。

## 同时进行多个功能

链条在一份 spec **内部**是顺序执行的。不同的 spec 彼此独立：每份都有自己的链条，智能体会处理它们
所有打开的 issue。吞吐量正是从这里来的。

<Aside type="tip">
中途修改 spec 是很正常的。更新 `spec.md` 和 `plan.md`，用下一个未使用的 ID 把新任务加入
`tasks.md`，然后合并。下一个智能体 PR 合并时会像对待其他任务一样把它们拾起来。
</Aside>
