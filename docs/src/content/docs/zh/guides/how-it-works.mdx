红色是你，灰色是自行工作的智能体或自动化，靛蓝色是自动关卡：CI，然后是 Reviewer 智能体，合并之后是 Tester 智能体。

这三个智能体都是 OpenHands 自动化：**开发智能体**编写代码，**评审智能体**评审代码，**测试智能体**在代码
部署之后测试它。

## 步骤

| # | 谁 | 发生了什么 | 产物 |
| --- | --- | --- | --- |
| 1 | 🧑🤖&nbsp;你 + 智能体 | `/speckit-specify` 把一段话的想法变成 spec。`/speckit-clarify` 最多提五个问题，并把你的回答写回去 | `specs/<timestamp>-<name>/spec.md` |
| 2 | 🧑🤖&nbsp;你 + 智能体 | `/speckit-plan` 决定*怎么做*，并对照 constitution 检查计划 | `plan.md`、`data-model.md`、`contracts/` |
| 3 | 🧑🤖&nbsp;你 + 智能体 | `/speckit-tasks` 写出一份按阶段分组的有序任务列表。`/speckit-analyze` 交叉检查这三个文件 | `tasks.md` |
| 4 | 🧑&nbsp;**你** | 开 spec PR，像评审代码一样评审它，加上 `spec-ready` 标签，合并 | 一个已合并的 spec PR。**人工关卡 1** |
| 5 | ⚙️&nbsp;自动化 | **Agent Issues** workflow 读取 `tasks.md`，为第一组阶段开一个带 `openhands` 标签的 issue | 一个实现 issue |
| 6 | 🤖&nbsp;开发智能体 | 在下一次轮询时，智能体领取该 issue，先写测试，再实现，勾选它的任务，并在 `openhands/issue-<n>` 上开 PR | 一个 pull request |
| 7 | ⚙️&nbsp;CI | PR 检查运行 lint、单元测试、构建、`tasks.md` 格式检查、e2e 测试和截图检查 | 检查结果 |
| 8 | ⚙️🤖&nbsp;自动化 + 开发智能体 | 运行变红时，**Agent CI Status** 将该 PR 标记为失败。开发智能体在下一次轮询时看到它，并修改同一个 PR | `ci-fix-1` 到 `ci-fix-5` 标签 |
| 9 | 🤖&nbsp;评审智能体 | 所有检查都结束后，评审智能体评审 head commit，并以 `✅ APPROVED` 或 `🔄 CHANGES REQUESTED` 结尾。遇到后者时，**Agent Review Status** 会把开发智能体送回去 | 一次评审，可能还有 `review-fix-N` 标签 |
| 10 | 🧑&nbsp;**你** | 你阅读 PR 描述和 **E2E screenshots** 评论，完成所有 **(human)** 任务，然后合并 | 一个已合并的 PR。**人工关卡 2** |
| 11 | ⚙️&nbsp;自动化 | 合并会再次运行 **Agent Issues**。它为下一个还有未勾选智能体任务的阶段开 issue，第 6 到 10 步不断重复，直到没有剩余任务 | 下一个 issue，或完成 |
| 12 | ⚙️🤖&nbsp;自动化 + 测试智能体 | 在 `main` 自动部署的地方：一旦合并的内容到达开发 stage，**Post-merge Verify** 就为它开一个测试 issue。测试智能体点完这个变更，调用 API，验证它写入数据库、文件存储和搜索索引的数据，然后报告 | 一份测试报告。通过时 issue 会关闭 |

第 12 步需要一个已部署的 stage。Discava 有一个。本仓库中的示例应用没有，所以 fork 到第 11 步为止。

## 你实际要做的事

每个功能，你编写并批准一次 spec。每个 pull request，你做一次评审并点击合并。只有当某个循环
用完了尝试次数（`ci-fix-exhausted` 或 `review-fix-exhausted`），智能体评论说它被卡住，或者测试智能体
因为变更在 stage 上失败而让一个测试 issue 保持打开时，你才会被提前拉进来。在智能体工作的同时，你可以去写下一份 spec。

## 每个部分在哪里

| 部分 | 文件 |
| --- | --- |
| spec 工具 | `.specify/`、`speckit-*` skill、`specs/` |
| 每次智能体运行都遵循的项目规则 | `.specify/memory/constitution.md`、`AGENTS.md` |
| 智能体收到的 issue | `.github/ISSUE_TEMPLATE/implement-phase.md` |
| spec 到 issue | `.github/workflows/agent-issues.yml` |
| 完成的 spec 到 `specs/_archive/` | `.github/workflows/archive-specs.yml` |
| CI 到智能体 | `.github/workflows/agent-ci.yml` |
| 评审智能体到智能体 | `.github/workflows/agent-review.yml` |
| 检查 | `.github/workflows/pr-checks.yml`、`ui-screenshots.yml`、`ci.yml` |
| 部署到测试 issue（仅 Discava） | `.github/workflows/deploy.yml`、`post-merge-verify.yml` |
| 粘合代码背后的规则，经过单元测试 | `packages/common/scripts/src/agent-*`、`ui-screenshots/` |
| 智能体运行时和每个角色的 prompt | OpenHands Agent Canvas，位于仓库之外 |
