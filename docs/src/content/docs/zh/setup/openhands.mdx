**完成后你将拥有：** 以你的 GitHub App 身份在你的机器上运行的 OpenHands Agent Canvas，以及两个 agent profile：用于开发智能体的 `developer` 和用于评审智能体的 `reviewer`。

<Steps>

1. **安装 Agent Canvas。** Discava 使用的版本是 1.45.0：

   ```bash
   npm install -g @openhands/agent-canvas
   ```

2. 在你的克隆中，**以你的 app 的身份启动它**：

   ```bash
   pnpm agent-canvas
   ```

   第一次运行时，它会询问[第 2 步](../github-repository/)中的 **App ID** 和 **`.pem` 文件**的路径，并把两者保存在 `~/.config/agent-app/` 中，只有你能读取。之后每次运行，它都会：

   - 启动 Agent Canvas，并把 app 作为智能体 commit 的作者，这样 GitHub 会把这些 commit 显示在 app 名下；
   - 生成一个 app 的 token（有效期一小时），并把它作为 secret `GITHUB_PERSONAL_ACCESS_TOKEN` 存进 Agent Canvas，automation 读取的就是这个 secret。尽管名字如此，任何 GitHub token 都可以放在这里；
   - 只要它还在运行，就每 45 分钟替换一次 token。

   等到出现 `Token stored in the GITHUB_PERSONAL_ACCESS_TOKEN secret` 这一行，然后打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。如果 Agent Canvas 询问要使用哪个智能体，选择 Claude Code：它会找到你已有的登录，所以所有 API key 字段都留空。

   保持终端开着，并且始终用这种方式启动 Agent Canvas：只有它在运行时，automation 才会轮询；只有这条命令在运行时，token 才会保持有效。

3. **创建两个 agent profile**，每个智能体角色一个。在 Agent Canvas 中打开 **Settings → Agent**，点击 **Add agent profile**，共两次：

   | Name | Agent type | Agent | Model |
   | --- | --- | --- | --- |
   | `developer` | ACP (external subprocess) | `claude-code` | `sonnet` |
   | `reviewer` | ACP (external subprocess) | `claude-code` | `opus` |

   ACP 即 Agent Client Protocol：由你已经在用的编码智能体来完成工作，它在这台机器上以你的身份登录。任何智能体和模型都可以。让评审智能体至少和开发智能体一样强：它是到你手上之前的最后一道检查。

   其余设置保持不变。Agent Canvas 本来就是无人值守运行的（没有确认提示），并且一个对话足以完成整个阶段（500 次迭代）。

</Steps>

## 检查是否成功

在 Agent Canvas 中，**Settings → Secrets** 列出了 `GITHUB_PERSONAL_ACCESS_TOKEN`。用 `developer` profile 启动一个对话，问它：

```text
Using the GITHUB_PERSONAL_ACCESS_TOKEN secret, run gh api graphql -f query='{ viewer { login } }', and list the open issues in <you>/agentic-sdlc.
```

它会报告 `<app-name>[bot]`，以及一个空的 issue 列表。

<Aside type="caution" title="别让智能体用上你自己的 GitHub 登录">
不要在 Agent Canvas 的 **Integrations** 下添加 GitHub token，并删除 **MCP Servers** 下列出的任何 GitHub server：它们都持有一个固定的 token，通常是你的，使用它的智能体会以你的身份而不是 app 的身份行事。
</Aside>

<Aside type="caution">
智能体以你的用户身份在这台机器上运行命令。不要在它的环境中保留云凭证，一旦超出试用范围，请使用单独的机器或虚拟机。
</Aside>

<Aside type="tip" title="把 Agent Canvas 作为服务运行">
一旦 Agent Canvas 作为服务运行，而不是在终端中运行，就让一个 timer 每 45 分钟运行一次 `pnpm agent-canvas --once`：它会生成一个 token，把它存好，然后退出。Discava 在 Linux 上用 systemd 来做这件事：参见 [Discava 的 OpenHands 配置](../../discava/openhands-setup/#github-app)。
</Aside>

Discava 还有第三个 profile `tester`，用于测试智能体。它在已部署的 stage 上测试已合并的变更，而笔记应用没有这样的 stage，所以你在这里不需要它。
