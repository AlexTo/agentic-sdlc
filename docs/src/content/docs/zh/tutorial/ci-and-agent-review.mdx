**当前位置：** ⚙️ 自动化，无人值守。**产出：** 一个全绿、并获得智能体批准评审的 PR。

每次推送到智能体的 PR 都会运行这些关卡。失败会交还给智能体，而不会交给你。

## 关卡

| 关卡 | 在标签案例中发现的问题 |
| --- | --- |
| Lint、类型检查、构建 | 一个不再与实体匹配的 API 类型 |
| 单元测试 | 接受了第六个标签，或把 `Work` 和 `work` 存成了两个标签 |
| 不变式 | 每个 e2e 测试之后，表中存在任何一条标签超过五个的笔记 |
| E2E 测试 | 标签输入框无法保存，或筛选显示了错误的笔记 |
| 并发测试 | 两次同时添加互相覆盖，丢了一个标签 |
| 截图 | 新 UI 从来没人看过：`UI Screenshots` 检查失败 |
| Tasks 格式检查 | 一个格式错误、会让链条停滞的 `tasks.md` |

## 当一道关卡失败时

1. **Agent CI Status** workflow 把 PR 的 head commit 标记为失败。
2. 智能体在它原来的对话中，根据失败输出修订*同一个* PR。
3. CI 再次运行。

举个例子：并发测试失败，因为添加标签时会先读取笔记、在内存中追加，再写回去，于是两个请求产生了竞争。智能体把它改成带有数量条件的原子追加，测试变绿。你从头到尾都没看到这件事。

## 智能体评审

CI 变绿后，第二个 OpenHands 智能体，即评审智能体，会像人一样评审 PR：正确性、遗漏的边界情况、spec 中没有测试覆盖的规则。它要么批准，要么要求修改，后者会像 CI 变红一样把开发智能体打回去。

## 上限

每个循环在每个 PR 上最多尝试**五**次，用标签计数：CI 用 `ci-fix-1` 到 `ci-fix-5`，评审用 `review-fix-1` 到 `review-fix-5`。第五次之后，workflow 会发表评论，加上 `ci-fix-exhausted` 或 `review-fix-exhausted`，然后停止。

<Aside type="caution">
循环用尽是唯一一种会提前把你拉进来的情况。[人工关卡](../../concepts/human-gates/#你何时会被提前拉进来)说明了该怎么做。
</Aside>
