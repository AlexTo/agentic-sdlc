本教程跟随一个功能从想法走到已合并的代码：**笔记标签**。

> 用户最多可以给一条笔记添加五个标签，并按标签筛选笔记列表。

它足够小，几个 PR 就能完成，同时又涉及示例笔记应用的每一层，所以工作流的每个阶段都有真正的事情要做。

| 层 | 改动内容 | 由哪道关卡发现错误 |
| --- | --- | --- |
| `notes-table` | `note` 实体上的 `tags` 属性 | 单元测试 |
| `notes-api` | 创建和更新时的 `tags`，列表上的 `tag` 筛选 | 单元测试、类型检查 |
| `notes-website` | 笔记表单上的标签输入框、标签 chip、标签筛选 | 截图、e2e |
| 业务规则 | 最多五个标签、不能重复、不区分大小写 | 不变式、单元测试 |
| 并发 | 两个标签页同时添加标签时，哪一边都不能丢 | 并发测试 |
| `docs/` | 笔记应用页面介绍标签功能 | 智能体评审、人工评审 |

## 阶段

spec 被拆分为三个阶段，因此对应三个 issue 和三个 PR：

1. **数据与 API。** 实体、procedure、校验规则、单元测试。
2. **网站。** 标签输入框、chip、筛选、带截图的 e2e 场景、不变式和并发测试。
3. **文档。** 更新文档以介绍标签。

<Aside type="note">
这个案例中的阶段只是一个例子。你自己的 spec 会有不同的拆分方式。唯一的规则是：每个阶段都是一个可评审的 PR，并且合并后 `main` 仍然能正常工作。
</Aside>

## 开始之前

- 你有这个仓库的一个 fork，并已按[搭建：fork 并运行](../../setup/before-you-start/)完成配置。
- OpenHands 正在轮询带 `openhands` 标签的 issue。
- 你在 `main` 上工作，且工作树是干净的。
